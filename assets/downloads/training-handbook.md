## 本科科研训练

从可完成的小任务开始，学会提问、验证与表达。

参加科研训练、大学生创新项目或研究组项目的本科生，按基础与可用时间选择起点。；按能力与项目推进，约定周期与检查日期。

科研训练以能力进步和可核验证据为主，不承诺论文、获奖或升学结果；成果转入毕设前核对学校要求、个人贡献与复用范围。

**这条路径要形成的能力**

- 把一个给定的小问题解释为输入、操作与可观察的结果，并用实际样例说明自己理解了什么。
- 独立完成一次阅读、复现或模块任务，保留来源、版本、命令、成功与失败记录，让他人能按说明复查。
- 根据证据解释结果与局限，把收到的反馈变成下一次可完成的小任务，逐步减少对逐步指令的依赖。

**开始时，用小任务确认起点**

- 选一份自己完成的课程作业或项目，现场说明输入输出、关键实现和一个不足；没有相关作品时，记录尚未具备的基础，与指导者约定一个入门练习。
- 在可用设备上运行一个公开且获准使用的小例子，保存环境、命令和实际输出；不能运行时提交完整报错与已尝试步骤，而不是填写“已掌握”。
- 读一篇与候选任务直接相关的材料，用原文位置支撑问题、方法和局限的说明；同时提交包含课程与考试安排的可投入时间表。

**学生负责什么**

学生主动选出当前最不理解的一点，提出自己的解释或尝试，按约定完成最小任务并提交证据。到了约定检查点仍不能解释关键步骤，或数据权限、设备与课程安排阻塞任务时，应带着记录求助，不等待指导者逐项催问。

**指导与支持负责什么**

指导者根据实际起点选择难度，首次示范如何把问题拆成可检验步骤，并说明样例质量与检查时间。初次训练可由有经验的成员协助环境排查；方向、任务范围和质量判断由约定的指导者负责，不能由学生自行把帮助记录写成验收通过。

**怎样获得反馈并改进**

首次检查同时看实际产物和学生的解释；给出需要补充的一项关键证据及复查日期。学生据此修订后，尝试一个输入不同但原理相近的任务，比较能否自己定位问题；只有运行成功、但仍说不清原因时，继续补练而不扩大任务。

**带着什么进入下一步**

进入较独立的项目时，应已有可复查的小任务、能解释的失败案例和下一步计划。转入毕业设计或竞赛时，复用的是能力、记录与经授权的材料；重新确认任务书或当届规则、个人贡献和正式环节，训练验收不自动替代这些要求。

### 01 了解方向与双向匹配

参考时机：正式领任务前

目标：说清楚为什么参加、能投入多少时间、需要哪些支持，确认适合自己的起点。

**进入条件**

- 已阅读研究组公开介绍，了解课程学习与科研训练的时间关系。
- 通过负责人确认的渠道沟通，不向公开仓库提交个人申请资料。

**操作步骤**

- 整理已学课程、完成过的作业或项目、感兴趣的问题；如实说明尚不熟悉的工具。
- 列出每周可用时段、考试和课程冲突，与指导者商定试学范围、反馈方式及调整渠道。
- 确认任务负责人、材料存放位置、可用设备和账号；了解引用、数据许可、保密与 AI 使用边界。
- 把讨论结果整理成入门清单，区分已经确认的安排和仍待核实的事项。

**交付材料**

- 个人基础与兴趣说明、可投入时间表。
- 入门清单与试学任务约定，含负责人和检查日期。

**验收标准**

- 学生能用自己的话解释试学目标和完成条件。
- 指导者确认任务难度与资源可承受，课程冲突已有安排。
- 双方知道出现阻塞、需要请假或希望退出时如何联系。

未达要求：基础或时间不匹配时，缩小任务或先补课程；保留讨论结论，约定复查日期，不以报名或进入群聊视为完成。

下一步：负责人确认试学任务后，进入工具与规范训练。

配套模板：入组与阶段计划（onboarding.md）、科研训练任务卡（research-task.md）

### 02 工具、文献与规范入门

参考时机：试学初期，按实际基础安排

目标：能独立运行一个小例子、记录过程，并正确说明资料与代码来源。

**进入条件**

- 约定小练习、可用环境与检查日期；已有作品能现场解释并重跑的能力可作为起点证据，针对缺项补练，不按年级跳过检查或机械重复已掌握的练习。
- 知道哪些材料只能在受控空间保存。

**操作步骤**

- 配置开发环境，记录系统、依赖版本与启动命令；用最小样例检查安装是否成功。
- 练习 Git 提交、分支、差异查看和恢复；提交前检查密钥、个人信息与无关大文件。
- 检索代表性文献，区分原论文、教程与二手总结，制作一份包含问题、方法、证据和局限的阅读记录。
- 完成小练习和必要测试；使用 AI 辅助时保留用途说明，并亲自运行、核对来源和解释关键代码。

**交付材料**

- 可运行练习、环境说明和实际测试记录。
- 阅读记录与来源清单。
- 提交历史及已发现问题的修复说明。

**验收标准**

- 按说明可重新运行，失败信息没有被省略。
- 学生能解释输入、处理、输出，以及引用和复用部分。
- 不把工具安装完成、截图或 AI 输出当作任务已验证。

未达要求：运行失败则缩减到最小示例并记录报错；关键概念解释不清则补练后复查，不直接进入复杂项目。

下一步：基础练习通过复查后，领取一个边界清楚的研究小任务。

配套模板：入组与阶段计划（onboarding.md）、论文阅读与复现判断（reading.md）、实验、复现与运行证据（experiment.md）、AI 辅助使用与披露记录（ai-use.md）

### 03 阅读、复现与小任务验证

参考时机：正式立项前

目标：通过有限规模的真实操作，判断候选问题是否值得继续、自己是否理解任务。

**进入条件**

- 基础练习可运行，任务负责人已指定公开材料或合法可用的数据。
- 任务有明确输入、输出、预算和停止条件。

**操作步骤**

- 把宽泛方向改写成一个问题，例如某方法在何种输入下失败，以及如何观察这种失败。
- 阅读相关工作并完成复现、错误分析、数据整理或模块修复，记录原方法和自己的改动。
- 事先写出观察指标和比较方式；区分作者报告值、本地重跑值、离线分析和未验证推测。
- 整理成功与失败样例，说明已有证据能支持什么、不能支持什么，并提出下一步选择。

**交付材料**

- 研究任务单与阅读比较表。
- 可复查的代码、配置、日志和样例。
- 小任务总结：结论、局限、未解决问题与建议。

**验收标准**

- 任务结果可以追溯到具体输入、版本和运行记录。
- 学生能解释差异来源，不用一两个样例宣称普遍有效。
- 指导者确认继续研究的价值、范围与资源条件。

未达要求：无法复现时先核对依赖、数据和评价口径；价值不足则如实结束或换题，失败记录仍纳入总结。

下一步：形成有证据的继续或调整决定后，再确定项目范围。

配套模板：科研训练任务卡（research-task.md）、文献综述与证据矩阵（literature.md）、实验、复现与运行证据（experiment.md）

### 04 项目立项与任务拆分

参考时机：小任务验收后、持续投入前

目标：把研究想法变成有负责人、有截止日期、能逐项验收的计划。

**进入条件**

- 已有初步可行性证据，并确认项目适合当前能力。
- 如涉及正式创新项目申报，已获取当年度通知。

**操作步骤**

- 写清真实场景、目标用户或研究对象、核心问题、范围之外的内容和预期产物。
- 把工作拆成调研、数据、实现、验证、写作等任务，每项写负责人、依赖、期限和验收证据。
- 核对算力、设备、经费与数据许可；涉及人员研究或敏感资料时，先确认必要审批再收集使用。
- 约定周期汇报、协作贡献、署名讨论与任务变更方式；正式申报按指定系统提交并留存回执。

**交付材料**

- 项目说明与里程碑计划。
- 任务清单、资源预算和风险清单。
- 适用时的申报材料、审批记录与提交回执。

**验收标准**

- 每个里程碑都有可观察的产物，而非仅写“学习”“优化”。
- 范围、资源、授权和分工能支撑计划。
- 团队成员清楚个人责任，正式申报状态有凭据。

未达要求：缺资源或依赖未落实时先缩小范围；申报未通过不冒称已立项，按反馈修订并明确后续是否作为训练项目。

下一步：计划和必要审批确认后，按里程碑推进实现与研究。

配套模板：开题方案与评审准备（proposal.md）、科研训练任务卡（research-task.md）、课题、计划与资源变更（change-request.md）

### 05 实施、周报与阶段复核

参考时机：项目进行期间，频率按约定执行

目标：持续交付可检查的进展，让阻塞和风险尽早被发现。

**进入条件**

- 任务、存储位置、负责人和反馈节奏已确认。
- 本轮待办有优先级与验收条件。

**操作步骤**

- 按小步提交推进代码、实验或分析，每次记录改动、运行条件与实际结果。
- 周期总结已完成事项、证据链接、未完成原因、所需帮助和下周期计划，不以在线时长替代产出。
- 讨论前准备具体问题和已尝试方案，讨论后记录决定、负责人及期限；关键口头决定补入正式记录。
- 遇到数据变化、算力不足或连续失败时提交变更说明，调整范围与时间，不默默拖延或只展示好结果。

**交付材料**

- 版本化产物、配置与实验/测试日志。
- 周期报告、会议行动项及更新后的任务状态。
- 阶段演示或复查记录、适用时的变更单。

**验收标准**

- 报告中的进展与实际文件、提交和运行记录一致。
- 阻塞已分派处理，反馈有落实证据。
- 阶段产物可运行或复核，课程、健康等实际冲突得到合理调整。

未达要求：未达成里程碑时列出差距和原因，缩减下一轮任务并约定复查；长期无法投入则明确暂停或交接。

下一步：核心任务达到约定条件后，进入独立复查和成果表达。

配套模板：周报与下一阶段计划（weekly.md）、会议、讨论与决策记录（meeting.md）、实验、复现与运行证据（experiment.md）、课题、计划与资源变更（change-request.md）

### 06 结果复核与成果表达

参考时机：结项、投稿、参赛或公开前

目标：让结论、代码和说明互相对应，形成别人能够理解和检查的成果。

**进入条件**

- 核心产物已经形成，原始记录可追溯。
- 已明确拟交付的是报告、软件、演示、论文还是其他成果。

**操作步骤**

- 从干净环境或由另一位成员按说明复查，核对数据处理、指标计算、失败样例和限制。
- 围绕问题、方法、证据和局限写报告；图表标明来源、单位与对应版本，引用回到原始资料。
- 列出个人贡献、复用内容、合作支持和 AI 辅助用途，确认署名与许可，不把他人工作写成自己的。
- 按拟投稿或参赛渠道核对格式、知识产权、公开范围和提交条件，经确认后再提交。

**交付材料**

- 技术报告或成果稿件、复查记录与复现说明。
- 贡献与引用清单、授权和公开检查结果。
- 适用时的正式提交回执与成果状态记录。

**验收标准**

- 主要结论有直接证据，局限与负面结果被如实说明。
- 第三方能定位产物并理解复查方式。
- 投稿、录用、发表、授权和获奖分别记录，不混用状态。

未达要求：复查失败则定位差异、补证据并同步修改结论；授权不清的材料暂不公开，先取得许可或更换。

下一步：成果通过复查后，办理结项、资料归档和后续交接。

配套模板：学位论文写作与版本检查（thesis.md）、成果要求核对与成果台账（outcomes.md）、学术规范、查非与查重（integrity.md）、AI 辅助使用与披露记录（ai-use.md）、实验、复现与运行证据（experiment.md）

### 07 结项、归档与后续发展

参考时机：项目结束、转入毕设或退出前

目标：留下完整过程和可接续的成果，明确已经完成与仍需承担的责任。

**进入条件**

- 成果和遗留问题已整理；正式项目的结项要求已核实。
- 有确定的接收人或材料保管位置。

**操作步骤**

- 按清单整理任务、报告、代码、数据来源、环境、运行记录与授权信息，建立版本索引和备份。
- 让接收人检查关键文件并实际恢复或运行；记录缺项、修复结果及访问权限。
- 办理项目结项、设备归还和未结经费事项；通过平台正规流程移交组织资源所有权与访问权限，不移交个人账号密码。
- 总结能力进步与不足，商定后续学习或毕设衔接；作品集只选经授权、能说明本人贡献的内容。

**交付材料**

- 归档索引、最终版本和备份校验记录。
- 交接清单、遗留事项与责任人。
- 能力总结及适用时的结项确认。

**验收标准**

- 接收人可以定位、打开并复查核心材料。
- 设备、经费、账号与未完任务均有处理记录。
- 个人隐私和未公开成果未随公开展示泄露。

未达要求：发现缺档或无法恢复时先补齐并重新交接；不能补回的内容注明原因和影响，不把不完整包标成验收完成。

下一步：完成结项后再进入新项目；转为毕设须重新核对任务和学位环节要求。

配套模板：数据、代码与毕业材料归档（archive.md）、阶段移交与离组交接（handover.md）、成果要求核对与成果台账（outcomes.md）、学习复盘与成长计划（learning-review.md）

## 本科毕业设计

连起题目、实现、论文与答辩，明确每阶段的交付物。

开展毕业设计或论文的本科生，按工程、实验或理论题目选择证据。；从学院发布当年度安排开始倒排，正式日期、格式和资格以适用专业通知为准。

毕业设计须体现本人综合训练。复用科研、竞赛或实习材料前，核对题目、个人贡献、授权及学校要求，仍须完成毕业设计环节。

**这条路径要形成的能力**

- 把任务书目标转换为可验证的需求或研究问题，使需求、设计、实现与测试证据逐项对应。
- 在实际期限和资源约束下完成个人负责的工作，解释核心设计取舍，处理异常、缺陷和范围变更。
- 用一致的论文、演示与归档材料说明本人贡献、结果和局限，并能依据证据回答质疑。

**开始时，用小任务确认起点**

- 带上本人适用的毕业设计通知、正式模板和计划日期，逐项标出已核实与待核实的资格、阶段及提交要求。
- 选取候选题目的一项核心目标，写出可检查的完成条件，并提交相关课程作品、原型或小规模验证结果以说明现有基础。
- 绘制现有方案的简图，实际检查数据、依赖、设备和许可是否可用；把关键缺口、解决人和确认日期写入风险表。

**学生负责什么**

学生维护任务书目标与实际证据的对应表，主动安排实现、验证和写作，并提交包含疑问的可审阅版本。关键设计不能满足验收条件、核心测试失败或正式节点可能延误时，先提出有依据的调整方案，再与导师及相关管理人员确认。

**指导与支持负责什么**

导师帮助判断工作量、专业深度与设计可行性，在开题、中期及定稿前检查关键证据并指出优先修改项。协作者可以复查或提供技术建议，但个人工作须可辨认；正式资格、答辩和归档结果由学校规定的环节确认。

**怎样获得反馈并改进**

每个阶段用同一组核心目标检查已有证据与缺口；修改后重测受影响的功能或重新分析受影响的结果，再更新论文和演示。反馈关闭时记录问题位置、新版本、复核结果与确认人，不仅填写“已修改”。

**带着什么进入下一步**

进入研究生学习或更复杂项目时，保留一套能说明完整解决过程的材料，再评估自己能否提出尚未解决的问题、比较已有方法并设计验证。完成本科工程系统不自动证明具有研究创新，应从新的问题证据与研究设计开始。

### 01 核对要求、选题与任务书

参考时机：学院选题与任务下达窗口内

目标：拿到正式认可、范围适当且资源可获得的题目。

**进入条件**

- 已获取本专业当年毕业设计通知、模板和系统入口。
- 已了解学分、选题资格和指导安排的适用要求。

**操作步骤**

- 建立日期清单，登记选题、开题、中期、论文检查、答辩和归档窗口及通知来源。
- 比较候选题目的问题、已有基础、个人贡献、技术风险和工作量，先验证关键资源是否可用。
- 与导师确认必须完成、可选扩展和明确不做的内容，为每项核心目标写验收证据。
- 按学校流程确定题目与任务书，核对题名、导师、学生信息和成果要求，留存提交确认。

**交付材料**

- 校本要求核对表与时间计划。
- 选题比较、确定的题目及任务书。
- 核心范围、验收条件与资源风险清单。

**验收标准**

- 题目与专业培养要求相符，学生能说明本人承担的工作。
- 任务书与正式系统信息一致。
- 范围可在实际期限内完成，关键依赖有解决方案。

未达要求：题目过大则删去非核心功能；资源不落实则换方案；题目需变更时先办理规定手续，避免论文和系统登记不一致。

下一步：选题与任务书确认后，开展针对性调研并准备开题。

### 02 文献调研与开题

参考时机：正式开题前，留出修改时间

目标：讲清楚为什么做、已有工作做到哪里、自己准备怎样完成和验证。

**进入条件**

- 题目、任务书与范围已确认。
- 已取得适用开题模板和评审安排。

**操作步骤**

- 围绕题目检索文献与现有系统，记录检索词、来源和筛选依据，比较方法与不足。
- 把背景动机转换为需求或研究问题，区分已有技术、计划复用内容和本人拟完成部分。
- 说明技术路线、数据来源、评价或测试方法、计划安排与风险预案，先做关键技术小验证。
- 准备开题报告与汇报，按意见逐条修改；正式提交后保存版本、意见和通过或整改记录。

**交付材料**

- 文献比较表、引用清单和关键技术验证记录。
- 开题报告、汇报材料及阶段计划。
- 开题意见与修改对应表、正式处理结果。

**验收标准**

- 文献结论来自实际阅读，不是仅堆引用数量。
- 问题、方案与验证方法能够对应。
- 正式开题结果可核实，整改事项已安排负责人和期限。

未达要求：开题未通过则按意见重定问题或路线，并遵循学校重审安排；不可仅更换表述而保留不可行方案。

下一步：正式开题及必要整改完成后，细化需求和设计。

配套模板：文献综述与证据矩阵（literature.md）、论文阅读与复现判断（reading.md）、开题方案与评审准备（proposal.md）、送审准备与意见逐条回复（review-response.md）

### 03 需求分析与详细设计

参考时机：大规模实现之前

目标：把方案细化到可实现、可测试、可说明的结构。

**进入条件**

- 开题方案已确认，遗留问题有处理结论。
- 实现环境、数据和主要约束已明确。

**操作步骤**

- 工程题列出用户场景、功能、异常与质量要求；研究题明确假设、变量、基线、指标与实验条件。
- 绘制模块、数据流或研究流程，定义接口、输入输出、数据字典和关键算法。
- 为核心需求建立测试或验证对应表，覆盖正常、边界、错误和资源受限情况。
- 评估隐私、数据许可、安全和可维护性；用小原型验证高风险部分，再确认设计版本。

**交付材料**

- 需求或研究问题说明、范围与验收表。
- 总体及详细设计、接口或实验设计文档。
- 高风险原型结果和测试/验证计划。

**验收标准**

- 学生选取一项核心需求或研究问题，现场说明对应的设计接口或实验变量、测试方法和预期观察，证明需求可以被检验。
- 数据来源、异常处理与关键依赖明确。
- 导师能据设计判断工作量及主要风险。

未达要求：设计无法支撑验收条件时回到需求澄清；关键技术验证失败则更换方案并记录影响，必要时办理变更。

下一步：设计基线确认后，分模块实现并准备中期证据。

配套模板：需求、详细设计与测试报告（engineering-report.md）、实验、复现与运行证据（experiment.md）、课题、计划与资源变更（change-request.md）

### 04 实现推进与中期检查

参考时机：设计确认后至学院中期窗口

目标：形成可演示的核心进展，并据真实差距调整后半程计划。

**进入条件**

- 设计与本轮任务清单明确，版本管理可用。
- 中期检查的材料、时间和提交方式已核实。

**操作步骤**

- 按模块实现并及时测试，保留提交、环境和运行记录；定期演示核心路径，减少末期集成风险。
- 持续写需求、设计和方法章节草稿，记录与原设计不同的决定及理由。
- 对照任务书列出已完成、进行中、尚未开始的事项，用代码、测试或分析结果支撑进度。
- 准备中期报告和演示，说明主要问题、剩余工作和调整计划；把检查意见转成行动项。

**交付材料**

- 阶段版本、运行说明和核心演示。
- 中期报告、进度证据与论文提纲/草稿。
- 检查意见、整改表和后续里程碑。

**验收标准**

- 关键流程确实运行，截图与展示对应当前版本。
- 中期材料如实区分完成和计划，未完成项有可行安排。
- 正式检查结果及后续要求已记录。

未达要求：核心路径未完成时优先补齐最小闭环，暂停非必要扩展；中期需整改或重查的，按正式要求提交复查证据。

下一步：中期问题处理后，完成系统或研究成果并进行全面验证。

配套模板：周报与下一阶段计划（weekly.md）、会议、讨论与决策记录（meeting.md）、中期检查与差距整改（midterm.md）、课题、计划与资源变更（change-request.md）

### 05 测试、实验与结果分析

参考时机：核心实现完成后、结论定稿前

目标：用充分且可复核的证据回答任务书中的目标是否达到。

**进入条件**

- 待验证版本已标记，环境和数据可定位。
- 测试用例或实验方案已有明确预期。

**操作步骤**

- 按需求对应表执行功能、边界、异常及适用的性能和安全检查，记录实际结果与缺陷。
- 研究题核对数据划分、对照设置、指标实现和重复运行条件，避免测试信息进入方法调试。
- 修复影响核心目标的问题并回归验证；无法解决的限制须说明触发条件与影响范围。
- 从原始记录生成图表，解释结果、失败案例和适用边界，区分自测、他人复核与尚未验证。

**交付材料**

- 测试/实验方案、原始记录与结果汇总。
- 缺陷与修复清单、回归结果。
- 需求—证据对应表及结果分析。

**验收标准**

- 每个核心目标有相应证据，没有只展示成功界面的空白。
- 结果与版本、输入和运行条件能对应。
- 结论没有超出测试范围，复核人可按说明检查。

未达要求：关键测试失败则修复并复测；证据不足时补实验或收窄结论，不能通过删去失败记录宣称完成。

下一步：核心验收条件达成后，完成论文与正式检查准备。

配套模板：需求、详细设计与测试报告（engineering-report.md）、实验、复现与运行证据（experiment.md）、学术规范、查非与查重（integrity.md）

### 06 论文撰写与规范检查

参考时机：写作贯穿全过程，检查前形成完整稿

目标：让论文准确呈现本人工作，满足适用的格式与学术规范要求。

**进入条件**

- 主要实现或研究结果已完成，论证所需证据齐备。
- 已取得学院最新论文模板与检查通知。

**操作步骤**

- 按问题、相关工作、设计方法、实现验证和结论组织全文，明确个人工作与复用部分。

- 逐项处理意见并复核修改，确认论文题名、系统登记、提交文件和演示版本一致。

**交付材料**

- 完整论文稿、引用资料与图表来源记录。
- 规范自查表、适用的检测报告与 AI 使用说明。
- 修改对应表、拟提交版本与确认记录。

**验收标准**

- 学生能够解释全文方法和结果，论文对应本人实际工作。
- 格式和学术规范检查按学校口径完成，不自设通过阈值。
- 查重结果、AI 检测与学术诚信判断不混为同一结论。

未达要求：发现无来源表述或错误引用则回到原始材料修正；未达到正式检查要求时按规定整改、复检或调整答辩安排。

下一步：规定的审阅与检查完成、答辩资格获确认后，准备正式答辩。

## 学科竞赛与创新实践

先核实规则，再组队实施，保留提交、成绩和复盘记录。

参加学科、创新创业或技术竞赛的本科生与研究生，资格按当届规则核对。；按当届赛程倒排，预留校内遴选、报名审批、作品冻结、上传和补正时间。

资格、赛制、费用与奖励认定可能逐届变化。获奖不自动替代课程或学位要求；复用作品前须核实规则、授权和贡献。

**这条路径要形成的能力**

- 从当届规则提取资格、评分、限制与提交条件，把作品目标转换为可逐项检查的团队任务。
- 在有限时间和资源内完成分工、集成、测试与替补安排，使每位成员的贡献和共同接口均有记录。
- 在规定环境中真实展示作品、解释失败与取舍，并从评审和过程记录提炼可迁移的经验。

**开始时，用小任务确认起点**

- 提供主办方当届规则和报名窗口，填写资格与评分核对表；含糊条款附向官方渠道咨询的记录与当前状态。
- 每位成员用已有作品或小练习说明可承担的职责，提供与课程、研究冲突后的可投入时间；缺少的岗位写明补位办法。
- 对作品最容易失败的一项依赖做小验证，记录实际结果、许可及资源预算；不能在比赛环境使用的组件须有可验证的替代方案。

**学生负责什么**

队长主动维护依赖、集成日期与提交状态，成员对自己的交付负责，并理解共同演示链路。接口变更、关键缺陷、人员退出或规则疑义出现时，及时提出影响和备选方案；报名与提交顺序按赛规安排，不因等待完整原型错过窗口。

**指导与支持负责什么**

指导者协助核对方向、规则边界和高风险决策；队内指定未负责该模块的成员检查运行说明和接口。经费、授权及成员变更由有权限的人按对应程序确认，指导建议与官方资格、成绩认定分别记录。

**怎样获得反馈并改进**

在集成检查点按评分项实际运行候选版本，记录失败、负责人和复查日期，再由另一名成员重跑关键路径。赛后将评审意见与已有测试对照，确定下一项具体改进；获奖与否分别记录，不用名次替代对个人能力和作品质量的分析。

**带着什么进入下一步**

后续转入科研、毕业设计或持续维护时，先把竞赛功能、研究假设与工程责任分开，重新论证问题、评价方案和个人任务。经授权复用已有作品，同时补足新场景需要的证据；比赛获奖不自动代替论文贡献、课程考核或学位环节。

### 01 选赛、资格与规则核验

参考时机：报名和购买设备之前

目标：确认这项赛事值得参加、能够报名，且投入与培养目标相符。

**进入条件**

- 已取得主办方当届正式通知与规则。
- 已了解学校报名、认定或推荐流程的适用要求。

**操作步骤**

- 核实主办方、赛道、年级/学籍资格、队伍人数、跨校限制、指导教师要求和赛程。
- 逐项提取作品形态、评分依据、原创性、重复参赛、公开数据与 AI 工具限制。
- 评估比赛收益、课程冲突、费用、设备和算力投入，比较是否有更适合的任务或赛事。
- 把含糊条款向官方渠道核实并保存答复；涉及校内推荐、盖章或报名审批的，先办理对应手续。

**交付材料**

- 赛事规则摘要、原文链接与核验日期。
- 资格自查、赛程计划和初步预算。
- 参赛决定及适用的校内审批记录。

**验收标准**

- 资格逐项符合，未把往届规则当作当届依据。
- 核心评分要求与限制已转换为任务条件。
- 费用和时间可承受，正式报名渠道明确。

未达要求：资格不符则换赛道或停止报名；规则尚不明确的高风险事项在官方答复前不作不可逆投入。

下一步：规则与参赛决定确认后，组队并明确责任。

配套模板：竞赛立项、备赛与复盘（competition.md）、入组与阶段计划（onboarding.md）

### 02 组队、选题与权属约定

参考时机：队伍登记与作品开发前

目标：让团队对问题、分工、投入、署名和作品使用权有共同理解。

**进入条件**

- 赛事资格与规则已核实。
- 候选成员了解课程冲突及可投入时间。

**操作步骤**

- 确定队长、开发、研究、设计、汇报等职责及备份人，任务落实到个人而非只分到小组。
- 依据赛道选择真实问题，写清用户需求、核心创新、最小作品和评分项对应关系。
- 列出既有代码、数据、模型、图片和合作资源，确认许可、使用范围及是否需要伦理或保密审批。
- 讨论贡献记录、署名顺序、奖励分配的适用规则与退出交接方式；涉及学校或合作单位权属按正式制度处理。

**交付材料**

- 队伍信息、分工与沟通约定。
- 作品任务书、评分对应表和里程碑。
- 资源来源、权属与授权清单。

**验收标准**

- 所有成员确认任务和投入，队伍登记符合规则。
- 作品范围可执行，个人贡献能被追溯。
- 素材与成果的使用权限清楚，未私下承诺无权处分的知识产权。

未达要求：分工或权属未达成一致时先暂停相关开发或公开；人员变化须按赛事流程办理并重新确认任务。

下一步：队伍和作品方案确认后，落实预算并制作原型。

配套模板：竞赛立项、备赛与复盘（competition.md）、选题论证与范围界定（topic.md）、科研训练任务卡（research-task.md）、阶段移交与离组交接（handover.md）

### 03 方案原型、预算与报名

参考时机：报名按官方窗口独立倒排；关键投入前验证高风险假设

目标：用最小原型证明路线可行，同时完成必要报名和资源准备。

**进入条件**

- 任务分工、作品范围与权属边界已确认。
- 报名字段、附件、支付和校内审批要求已明确；把官方截止日单列为节点，报名与原型可按规则并行或调整先后。

**操作步骤**

- 先验证最容易失败的技术或数据环节，形成能演示核心价值的原型，记录成功和失败条件。
- 细化设备、算力、差旅、报名等预算，核对报销口径和审批权限；没有确认的经费不按已落实使用。
- 准备报名表、承诺书及适用附件，逐项核对成员姓名、学校、指导教师和赛道信息。
- 在官方窗口内通过正式渠道报名并保存回执和审核状态；若规则不要求完整原型，不等待内部原型验收才报名；若有要求则倒排完成。设置补正和后续赛程提醒。

**交付材料**

- 原型、可行性验证记录与修订计划。
- 预算明细和适用的审批凭据。
- 报名材料、回执及审核状态记录。

**验收标准**

- 原型能回答关键可行性问题，未把概念图当作已实现。
- 费用有来源与责任人，采购符合授权。
- 报名确已提交或审核通过，状态依据可查。

未达要求：原型失败则在截止前调整方案；报名被退回按反馈补正；无法解决的资格或经费问题及时止损并记录决定。

下一步：在资格与资源允许的范围推进实现，并跟踪待确认的正式报名状态；受资格限制的活动应先完成所需审核，依当届赛程推进，不把本图当作固定的报名顺序。

配套模板：竞赛立项、备赛与复盘（competition.md）、实验、复现与运行证据（experiment.md）、课题、计划与资源变更（change-request.md）

### 04 作品实现、复现与内部验收

参考时机：正式提交前，预留修复窗口

目标：让作品在规定环境中稳定运行，并能说明每项成绩或性能的来源。

**进入条件**

- 作品需求与评分对应表已冻结为本轮基线。
- 团队有可用的版本管理和测试环境。

**操作步骤**

- 按评分项实现并维护任务状态，记录成员贡献、版本和变更，定期集成而非临近截止才合并。
- 在规定设备或运行条件下测试正常、边界和故障场景，核对禁止联网、外部服务或数据使用等限制。
- 由未负责该模块的成员按说明复现，检查依赖、许可证、数据路径、运行时间和演示可靠性。
- 完成说明书、海报、视频或答辩稿，标明原型功能与计划功能，逐项验收后冻结提交候选版。

**交付材料**

- 可运行作品、依赖与操作说明。
- 测试/复现记录、缺陷清单与贡献记录。
- 提交候选材料及内部验收表。

**验收标准**

- 评分项与证据可对应，没有未实现却宣称完成的功能。
- 作品可在约定环境复现，失败和限制已说明。
- 代码、数据、视频与说明书版本一致，AI 使用符合当届要求。

未达要求：关键缺陷未修复则删减不可靠功能并同步修改说明；不能满足赛规的组件替换后重测，禁止隐瞒依赖。

下一步：内部验收通过并取得提交确认后，正式上传和参赛。

配套模板：实验、复现与运行证据（experiment.md）、学术规范、查非与查重（integrity.md）、AI 辅助使用与披露记录（ai-use.md）、竞赛立项、备赛与复盘（competition.md）、需求、详细设计与测试报告（engineering-report.md）

### 05 正式提交、现场比赛与结果确认

参考时机：按官方截止时间、时区与场次执行

目标：提交正确版本、保留有效凭证，并按规则完成展示和申诉。

**进入条件**

- 提交候选版已验收，所有必要成员或指导者已确认。
- 已核实文件大小、命名、格式、上传次数和最终截止时间。

**操作步骤**

- 检查包内文件、敏感信息、授权声明和成员信息，记录最终版本与校验值，预留上传失败的处理时间。
- 完成上传后重新下载或预览核对内容，保存提交编号、时间、回执及平台显示状态。
- 现场按要求完成展示，记录版本和评审问题；突发故障如实说明，不以剪辑材料冒充实时运行。
- 以官方通知确认晋级、奖项和证书信息；结果疑义按规定期限、渠道和证据要求提出复核。

**交付材料**

- 最终提交包、版本记录与提交回执。
- 现场材料、问题记录及适用的补正记录。
- 官方成绩或证书、适用的复核结论。

**验收标准**

- 提交状态可核实，材料未误传旧版或空文件。
- 展示符合规则，团队知道后续通知和补正窗口。
- 获奖名称、级别、成员与官方记录一致，不根据预测或截图猜测认定。

未达要求：上传失败立即按官方应急渠道处理并保留证据；争议按正式流程申请，不擅改成绩、证书或对外宣传。

下一步：官方结果或本轮赛程结束后，进行复盘、结算与归档。

配套模板：竞赛立项、备赛与复盘（competition.md）、答辩准备与修改验收（defense.md）、成果要求核对与成果台账（outcomes.md）、送审准备与意见逐条回复（review-response.md）

### 06 复盘、经费结算与成果归档

参考时机：赛事结束或决定退出后

目标：将参赛经验转化为可继续学习和使用的资产，完成团队责任。

**进入条件**

- 本轮提交、成绩和费用记录已收集。
- 学校成果认定与报销的适用程序已核实。

**操作步骤**

- 对照目标、评分和实际结果分析做得好与失误之处，区分技术、组织、展示和规则理解问题。
- 核对票据、费用分担、设备与借用资源，按要求报销结算，不能用估算替代真实凭证。
- 归档作品、报告、规则版本、提交回执、成绩证据与个人贡献，安排维护或停止运行。
- 确认后续开源、专利、论文或毕设复用的规则与授权；对外展示使用官方状态和获准材料。

**交付材料**

- 复盘报告、后续行动与个人贡献说明。
- 归档索引、最终作品与正式成绩证据。
- 费用结算、设备归还和项目交接记录。

**验收标准**

- 团队能复用经验，关键问题已有具体改进措施。
- 经费、设备、账号和未完事项均有去向。
- 成果认定按学校正式结果登记，公开范围与知识产权已确认。

未达要求：缺票据、缺授权或成绩待确认时标记待办并落实负责人；不为结项补造证明，不把参赛自动写成获奖。

下一步：完成交接后再确定延续方向；转论文或毕设需要重新立项和核对要求。

配套模板：竞赛立项、备赛与复盘（competition.md）、数据、代码与毕业材料归档（archive.md）、阶段移交与离组交接（handover.md）、成果要求核对与成果台账（outcomes.md）、学习复盘与成长计划（learning-review.md）

## 硕士培养与学位全流程

从选题到学位手续，逐项落实研究、审查与交接。

学硕、专硕及不同学制、学习方式的研究生，均应使用本人适用的培养方案。；按个人培养方案和年度通知倒排；研究与写作可并行，正式环节遵守学校先后条件。

学硕着重学术研究能力，专硕还须对应专业实践与应用要求，具体成果形式和标准以所属学科或专业学位类别规定为准。本页不替学校设定成果数量、级别、检测比例或截止日期。

**这条路径要形成的能力**

- 基于实际问题与相关研究，提出边界明确、可检验且资源可支持的研究问题，说明与最接近工作的关系。
- 独立设计并实施与问题匹配的研究或实践验证，检查对照、数据质量和反面证据，解释结果的适用范围。
- 把研究证据组织成连贯的学位论文，持续管理培养环节、反馈、成果状态和资料交接，并逐渐形成有依据的自主判断。

**开始时，用小任务确认起点**

- 提供本人适用的培养方案与课程、实践、学术活动和学位条件核对表，标注正式依据、缺项与咨询对象；成果条件在入学或选题时即核对，不等到论文定稿。
- 选取与方向最接近的一组文献，提交比较矩阵和原文定位，区分作者报告、本人复现与尚未验证的判断。
- 提交一个基线复现、工程问题分析或可行性试验，保留实际版本、数据来源、结果及失败记录；据此提出能力补足计划与下一次检查日期。

**学生负责什么**

学生主导选题证据、研究方案与进度安排，讨论前提交自己的判断、备选方案和需要决策的问题。证据与假设持续矛盾、研究边界改变、资源或正式条件影响计划时，应主动请求复核并提出缩题、补证或调整方案。

**指导与支持负责什么**

导师提供研究定位、方法和质量判断上的反馈，帮助识别关键假设与风险，并约定可实现的审阅安排。专业学位学生还需确认实践指导人与学校认可的考核要求；同伴复现和组内讨论提供证据，正式培养与学位审核仍按学校程序进行。

**怎样获得反馈并改进**

在选题、开题和中期等检查点同时复核“问题—方法—证据”是否仍一致，以及学生能否解释方案取舍。将意见转为修改和验证任务；新证据改变结论时回到研究定位或实验设计，不为保持原计划而隐藏反例。研究与写作同步迭代，重要结果在定稿前再次复核。

**带着什么进入下一步**

进入博士训练时，应从已完成的研究中辨认尚未解决且有价值的问题，进一步论证原创贡献、长期可行性和系统证据。进入专业岗位时，将研究方法迁移到真实约束下的需求、验证与沟通；既有论文或实践成果是起点，不自动满足下一层级的入学或培养条件。

### 01 入学、培养计划与日常管理约定

参考时机：入学后按培养方案要求完成；每学期复核

目标：明确培养类型、必修环节、沟通责任与资料管理方式，建立可持续的研究节奏。

**进入条件**

- 已确认学位类别、专业方向、学制及导师安排。
- 已取得本人适用的培养方案和学院通知入口。

**操作步骤**

- 列出课程学分、实践、学术活动、年度考核、开题与学位环节；入学即核对成果类型、署名、时间口径和认定程序，登记适用文件、版本、范围和待核实条款。
- 制定个人培养计划；专硕核对实践基地、实践周期、校内外指导及考核要求，学硕核对学科训练要求。
- 约定周报、组会、邮件与任务系统的用途、反馈频率和求助方式；请假、出差、考勤按已生效制度处理。
- 建立个人研究目录、版本管理、备份和权限，完成诚信、伦理与安全学习；遇到健康或重大困难及时说明并商定调整。

**交付材料**

- 个人培养计划与校本要求核对表。
- 学期计划、能力补足清单与沟通约定。
- 资料目录、备份方案和适用的培训记录。

**验收标准**

- 正式计划已按要求确认，必修环节和负责人清楚。
- 学生主导任务推进，导师的指导与反馈责任明确。
- 缺少打卡或报告先核实，可补充更正；自动汇总不能直接作为违纪结论。

未达要求：发现学分、实践或时间冲突时及时咨询教务并修订计划；未确认的条款标为待核，不自行套用他人的培养条件。

下一步：培养计划和工作方式明确后，围绕方向提出候选问题。

### 02 方向探索与研究选题

参考时机：开题前，完成必要试验后确定

目标：选择有真实依据、个人贡献清楚、能在资源和期限内完成的问题。

**进入条件**

- 已了解方向基础、现有项目和可用资源。
- 能获取代表性文献及合法的初步验证材料。

**操作步骤**

- 从实际问题、已有研究限制或专业实践需求提出候选选题，说明问题出现的场景和证据。
- 比较研究价值、新颖性、相关方法、可验证性、资源和风险；区分真实观察与为说明问题构造的示例。
- 完成小规模基线复现或可行性试验，明确成功、失败和停止条件，避免只凭设想认定可行。
- 与导师讨论主问题、子问题和贡献边界；专硕同时核对实践对象、应用产物及合作单位使用授权。

**交付材料**

- 候选选题比较与选题说明。
- 初步复现/试验记录和资源风险表。
- 问题边界、预期贡献与继续或调整决定。

**验收标准**

- 问题确实存在或具有可检验假设，价值有来源支持。
- 个人工作与团队已有成果可区分。
- 数据、设备、经费和周期可支持最低可行研究。

未达要求：没有真实证据或关键资源不可得时缩题、换方法或换题；保留否定结果，重新讨论后再投入大规模实验。

下一步：候选问题具备可行依据后，通过系统综述完善定位。

配套模板：选题论证与范围界定（topic.md）、科研训练任务卡（research-task.md）、实验、复现与运行证据（experiment.md）

### 03 文献综述与研究定位

参考时机：开题前形成初稿，研究期间持续更新

目标：从可追溯的检索与比较中识别已有结论、争议和本研究切入点。

**进入条件**

- 已有候选问题和检索范围。
- 可访问相关数据库、论文及必要的原始资料。

**操作步骤**

- 设定关键词、同义词、时间范围、数据库和纳入排除标准，保存检索日期与筛选记录。
- 精读核心工作，按问题、假设、方法、数据、评价、结果和局限建立比较矩阵，回溯关键原始文献。
- 核对论文与代码、数据或后续修订的关系；未运行过的工作明确写为文献报告，不混写成本地复现。
- 按问题和方法脉络撰写综述，说明证据冲突、未覆盖条件及本研究如何补充，而非逐篇摘要拼接。

**交付材料**

- 检索记录、文献库与筛选说明。
- 核心阅读记录、比较矩阵和问题地图。
- 综述稿、研究定位及待补证据清单。

**验收标准**

- 代表性方法与相反证据均被考虑，引用能找到原文。
- “尚未研究”等判断有检索边界，不作无依据的绝对表述。
- 研究定位能解释与最接近工作的区别及验证方式。

未达要求：核心相关工作遗漏时补检索并重写定位；发现已有工作已解决主问题时调整问题，不能仅换术语制造创新。

下一步：若最接近工作已解决主问题，或必要数据不可获得，带着比较矩阵和可行性证据返回选题；问题、相关工作与可行性一致后准备开题，研究期间继续更新综述。

配套模板：文献综述与证据矩阵（literature.md）、论文阅读与复现判断（reading.md）、选题论证与范围界定（topic.md）

### 04 研究方案与正式开题

参考时机：学校规定的开题窗口内

目标：形成可执行研究方案，并获得正式开题环节的处理结论。

**进入条件**

- 选题、综述和初步可行性材料已形成。
- 已核对开题资格、时间、评审形式及提交模板。

**操作步骤**

- 把主问题拆成可检验子问题，为每项安排方法、基线、数据、指标和预期证据。
- 编制计划、算力与经费预算、伦理与数据许可安排，以及失败、延期和改题的备选方案。
- 按学位类型说明研究或实践产物与能力目标，准备报告、汇报及必要的前期成果证明。
- 按指定流程提交并参加开题，记录评审意见、结论和修改期限，完成逐项回应及必要复审。

**交付材料**

- 开题报告、研究方案与汇报材料。
- 阶段计划、预算、风险及适用审批记录。
- 开题结论、修改对应表和通过或待整改状态。

**验收标准**

- 研究问题、方法和评价相互对应，计划可在剩余培养时间内完成。
- 正式流程、意见处理与版本均可追溯。
- 需要审批的研究活动在实施前已取得相应许可。

未达要求：开题未通过时按意见修改并遵循重审规定；重大改题或方法变化需核对是否重新开题，不能用导师口头认可替代正式手续。

下一步：开题及必要整改、审批完成后，按确认方案实施研究。

配套模板：开题方案与评审准备（proposal.md）、实验、复现与运行证据（experiment.md）、送审准备与意见逐条回复（review-response.md）、课题、计划与资源变更（change-request.md）

### 05 研究实施、专业实践与持续记录

参考时机：开题后持续推进，按约定周期复盘

目标：积累足以支撑论文的可靠证据，同时完成适用的实践与过程要求。

**进入条件**

- 研究方案、授权与资源已落实。
- 实验、实践或分析任务有明确的版本和责任人。

**操作步骤**

- 按问题组织实验或实践，保存数据来源、处理步骤、参数、环境、随机设置和原始日志；失败运行也记录。
- 建立基线、对照、消融或案例验证，防止数据泄漏、评价口径变化和只选择有利结果。
- 周报列证据和阻塞，组会落实行动项；每学期复核课程与年度要求，专硕同步保存实践计划、过程和考核证据。
- 定期备份并试恢复；涉及新数据、新用途、合作变动或预算超支时，先核对授权与变更手续再继续。

**交付材料**

- 版本化代码/分析产物、数据说明、环境与原始记录。
- 实验结果、失败分析、周报和会议行动项。
- 适用的实践报告、年度材料及变更记录。

**验收标准**

- 结论能追溯到真实运行或实践记录，不能把预检、离线重算当作完整实验。
- 关键结果可重复检查，风险和负面证据未被隐藏。
- 课程、实践及年度事项与研究进度一并跟进。

未达要求：结果不稳定先排查数据、配置与统计口径；连续无法支持假设则缩小结论或调整研究方案，并记录导师反馈和必要审批。

下一步：按学校时间准备中期材料，不等全部研究完成才检查进度。

配套模板：专业实践计划与总结（professional-practice.md）、实验、复现与运行证据（experiment.md）、周报与下一阶段计划（weekly.md）、校本要求核对与年度培养记录（annual-check.md）、课题、计划与资源变更（change-request.md）、会议、讨论与决策记录（meeting.md）

### 06 中期检查与年度考核

参考时机：按适用制度分别执行，不默认二者互相替代

目标：审视培养条件、研究进度和完成可能性，及时形成可落实的调整方案。

**进入条件**

- 已获得本年度中期及年度考核通知。
- 研究、课程、实践和成果状态有真实记录。

**操作步骤**

- 对照开题计划整理已完成、延期和变更项，提供核心结果、原型演示或实践产物。
- 核对课程学分、学术活动、专业实践、伦理与研究计划等适用事项，提前处理缺项。
- 评估剩余问题、论文结构、资源和毕业窗口，提交现实的后续安排，避免把未做工作全部排到最后。
- 参加正式检查，区分导师建议与考核结论；把每条整改意见转成任务、责任人、期限和复查证据。

**交付材料**

- 中期报告、汇报材料及证据索引。
- 适用的年度考核和实践材料。
- 正式结论、整改计划及更新后的时间表。

**验收标准**

- 进度由已有材料支撑，关键差距和风险已明确。
- 课程与实践等培养环节没有遗漏。
- 整改条件、复查时间和可能影响已得到正式确认。

未达要求：未通过或需整改时按学校规定补材料、调整方案或申请延期，完成复查后再声明通过；不隐瞒影响后续资格的问题。

下一步：落实中期整改；核心证据不足时返回研究执行并更新验证计划，可同步写提纲与方法。支撑结论的证据经复核后再写核心结论；中期通过不等于研究完成，不能用占位结果表示已经取得发现。

配套模板：中期检查与差距整改（midterm.md）、校本要求核对与年度培养记录（annual-check.md）、专业实践计划与总结（professional-practice.md）、送审准备与意见逐条回复（review-response.md）、课题、计划与资源变更（change-request.md）

### 07 学位论文结构、初稿与反复修订

参考时机：写作贯穿研究，送审前完成实质性审阅

目标：以完整论证呈现本人研究，做到论文、数据、代码和结论一致。

**进入条件**

- 论文主问题与主要证据已明确。
- 已取得学位类型对应的论文规范、模板和保密要求。

**操作步骤**

- 建立章节与研究问题对应表，说明每章的目的、主张和证据；专硕按适用规范呈现专业实践与应用贡献。
- 先完成方法和结果等核心章节，再统一绪论、相关工作与结论；明确已发表合作成果和本人贡献的关系。
- 逐图逐表核对原始数据、单位、统计方法和运行版本，检查论证跳跃、反例与局限。
- 给导师提交可审阅的完整版本与问题清单，保留反馈和逐项修改说明；最终检查摘要、引用、附录及格式一致性。

**交付材料**

- 论文提纲、章节证据表和完整初稿。
- 图表来源、参考文献与贡献说明。
- 审阅意见、修改对应表和候选定稿。

**验收标准**

- 正文形成完整论证，未用计划或占位文字替代结果。
- 学生能解释所有核心内容，引用和复用清楚。
- 导师审阅、格式要求和后续送审时间有可落实安排。

未达要求：核心证据不足则补验证或收窄论点；结构性问题优先修订，不靠润色掩盖缺陷。时间不足按正式程序评估延期。

下一步：写作同时核验培养成果要求；两项均达适用条件后准备正式送审检查。

配套模板：学位论文写作与版本检查（thesis.md）、论文阅读与复现判断（reading.md）、送审准备与意见逐条回复（review-response.md）、AI 辅助使用与披露记录（ai-use.md）

### 08 培养成果与学位申请条件核验

参考时机：入学即了解，学位申请前逐项确认

目标：对入学与选题时已核对的条件进行最终复核，用正式依据和证明材料确认适用条件；规则或计划变化时及时重核，不等论文定稿才首次了解成果要求。

**进入条件**

- 已明确本人年级、学位类型、学科或专业类别。
- 已取得相应成果和学位申请规定的有效版本。

**操作步骤**

- 逐条核对课程、实践、考核、成果及其他申请条件，记录文件来源、生效范围和咨询结果。
- 如有论文或其他成果要求，核对类型、作者及单位、时间口径和认定程序；不得自行把专硕或他人标准套用。
- 分别登记投稿、录用、在线发表、正式出版、专利申请/授权、软件登记、获奖或实践验收等实际状态。
- 收集正式证明并请指定部门核验，记录缺项、补救方案和预计完成时间；成果不足时按规定办理后续安排。

**交付材料**

- 适用条件核对表与政策来源。
- 成果台账、贡献说明及正式证据。
- 认定或资格核验结果、缺项处理计划。

**验收标准**

- 每项条件都有适用依据和状态，未核实处明确标注。
- 成果证据可查，状态没有夸大，合作署名与单位符合要求。
- 是否满足申请条件由学校规定的审核环节确认。

未达要求：证据不足则补正式材料或咨询认定部门；未满足条件时如实报告并按规定调整申请时间，不承诺录用、授权或特殊豁免。

下一步：确认适用条件与证明材料后，完成送审前的规范及资格检查。

配套模板：成果要求核对与成果台账（outcomes.md）、校本要求核对与年度培养记录（annual-check.md）、课题、计划与资源变更（change-request.md）

### 09 格式、查重、查非与 AI 使用说明

参考时机：按学校规定的送检和送审窗口执行

目标：完成相互独立的规范检查，确保报告对应实际拟提交论文版本。

**进入条件**

- 论文候选定稿、引用、贡献和成果证明已齐备。
- 已核实学校对各类检查的名称、对象、平台、阈值及复检规则。
- 已核对预答辩是否必需及办理顺序；如为送审前置，提交前必须完成预答辩和规定修改。

**操作步骤**

- 先核对学术诚信、引用、数据真实性、署名与保密，再检查格式、附件和论文信息。
- 按正式通知进行相似性检测，逐项核对重复来源和引用，不以改写、拆字等方式规避检查。
- 部分高校把错别字、格式、图表、编号、参考文献著录和排版等非学术性问题检查称为“查非”。逐项检查并记录位置、修正和复核；本校是否设置正式环节、具体范围与标准以适用文件为准。
- 按学校和成果渠道要求说明 AI 工具、用途、范围及人工核验；如有 AI 检测结果，应与使用说明、相似性报告分开保存。

**交付材料**

- 规范自查表、正式送检版本与文件校验记录。
- 相似性报告及适用的查非/其他核查材料。
- AI 使用说明、整改记录与复检结果。

**验收标准**

- 每份报告对应明确文件版本、检测时间与正式平台。
- 各类检查分别满足本校要求，不能以一项通过代替全部通过。
- 检测分数只是线索或流程依据，不能单独证明不存在学术不端，也不直接代替人工审查。

未达要求：未达要求时核实原因并按规定修改、复检或申请复核；检查后实质修改须核对是否重新送检，不能沿用不对应的报告。

下一步：资格及规定检查完成、送审版本确认后，按学校流程送审。

配套模板：学术规范、查非与查重（integrity.md）、AI 辅助使用与披露记录（ai-use.md）、成果要求核对与成果台账（outcomes.md）

### 10 匿名送审、评阅意见与异议处理

参考时机：学校指定送审窗口内

目标：提交符合匿名要求的正确版本，并按正式评阅结果完成回应和后续手续。

**进入条件**

- 送审资格和前置检查已获确认。
- 已取得匿名规则、提交清单、评阅及异议处理规定。

**操作步骤**

- 从同一论文基线生成完整保存版与匿名送审版，按规则处理姓名、单位、致谢、成果信息、文件属性和可识别链接。
- 检查匿名后的引用、附件和必要研究信息仍完整；未经规则允许，不擅自删改影响评阅的实质内容。
- 通过学校指定系统提交，核对文件预览、版本、信息和回执；保持评审独立，不私自寻找或联系评阅人。
- 收到意见后逐条回应、修订并保留证据；存在事实错误或异议时，在规定期限内通过正式渠道申请复核或申诉。

**交付材料**

- 同源的完整保存版与匿名送审版、匿名检查表。
- 正式送审回执、评阅意见与处理结论。
- 逐条回复、修改论文及适用的复审/异议材料。

**验收标准**

- 匿名要求与论文信息准确性同时满足，提交版本可追溯。
- 所有意见有明确处理，未采纳意见有依据和说明。
- 是否重审、复审或取得答辩资格以学校正式处理结果为准。

未达要求：评阅未达到答辩条件时按规定整改、复审或延期；异议未获结论前不自行认定通过，也不通过非正式接触影响评审。

下一步：正式评阅和修改要求满足、答辩资格确认后，进入答辩。

配套模板：学术规范、查非与查重（integrity.md）、送审准备与意见逐条回复（review-response.md）、学位论文写作与版本检查（thesis.md）

### 11 答辩申请与正式答辩

参考时机：满足正式答辩资格后，按学院通知办理

目标：在规范程序中说明研究贡献、证据和限制，并接受正式学术评价。

**进入条件**

- 已获得明确的评阅处理结果与答辩资格。
- 答辩申请、委员会安排、公开或保密要求由规定程序确认。

**操作步骤**

- 按学院清单完成答辩申请与材料提交，核对论文、评阅回复和资格材料版本；如校规将预答辩安排在评阅后，按通知先完成并落实修改。
- 制作问题—方法—证据—贡献的汇报，明确本人工作和局限，计时演练并准备可复查演示。
- 对照评阅意见准备回答，核对场地、设备、线上安排和保密要求；不自行对外发布受限论文或会议链接。
- 正式答辩如实回应并完整记录问题、修改意见和决议，确认后续期限和负责人员。

**交付材料**

- 答辩申请与资格材料、汇报及演练记录。
- 适用的预答辩意见和修改结果。
- 正式答辩记录、决议与后续修改清单。

**验收标准**

- 所有前置条件和答辩程序按学校要求完成。
- 汇报、论文、成果证明和实际研究一致。
- 答辩结论使用正式表述；答辩通过不等于学位已经授予。

未达要求：答辩未通过或需重大修改时，遵循学校对修改、再次申请及时间间隔的规定；不得自行承诺再次答辩结果。

下一步：按照答辩决议完成修改、审核和学位申请后续手续。

配套模板：答辩准备与修改验收（defense.md）、送审准备与意见逐条回复（review-response.md）、成果要求核对与成果台账（outcomes.md）

### 12 答辩后修改、定稿与学位手续

参考时机：答辩后至当批次材料截止日期

目标：把答辩意见落实到终稿，完成学校规定的审核和提交。

**进入条件**

- 正式答辩决议、修改意见及提交期限已获得。
- 已明确修改审核人和学位材料接收渠道。

**操作步骤**

- 逐条处理答辩意见并说明修改位置，未采纳处写出依据，按要求由导师或指定人员审核。
- 核对终稿的题名、作者、摘要、图表、附录和引用；实质修改是否需要补检或补审按规定确认。
- 完成学位申请、图书馆提交、纸质归档及必要签字，核对各渠道版本一致并保存回执。
- 查询毕业和学位的正式审核状态，分别记录答辩通过、材料接收、毕业审核和学位授予结果。

**交付材料**

- 论文终稿、逐条修改说明和审核确认。
- 学位申请及适用的归档提交材料、回执。
- 正式办理状态表和待补事项。

**验收标准**

- 修改要求全部有处理结论，终稿与审核文件一致。
- 签字、上传和接收记录齐全，待办有负责人和期限。
- 学位状态以学校正式决定为准，不根据答辩或系统草稿自行宣布。

未达要求：终稿或手续被退回时按具体意见补正并重新确认接收；错过窗口应及时联系负责部门按正式程序处理。

下一步：完成终稿与正式材料提交后，继续完成研究资产归档和离组交接。

配套模板：学位论文写作与版本检查（thesis.md）、送审准备与意见逐条回复（review-response.md）、数据、代码与毕业材料归档（archive.md）、成果要求核对与成果台账（outcomes.md）

### 13 研究资料归档、交接与离组

参考时机：贯穿研究，离组前集中验收

目标：让研究在人员离开后仍可核查、恢复和接续，并明确保管与访问责任。

**进入条件**

- 终稿、研究产物和官方材料已整理。
- 导师、项目负责人或指定接收人已明确归档范围与权限。

**操作步骤**

- 建立索引，覆盖论文版本、原始数据、处理脚本、代码、环境、配置、日志、图表来源、许可和正式记录，区分原件与派生文件。
- 冻结最终版本并生成校验记录，按已确认规则备份和试恢复；数据不能随包转移时登记存放位置、访问申请和保管责任。
- 由接收人抽查关键结果和运行说明，记录未完成实验、已知缺陷、合作事项、成果修订及后续负责人。
- 完成设备、经费、账号和权限交接；核对保存期限、保密与公开条件，个人作品集和离组后使用材料均遵循授权。

**交付材料**

- 归档目录、最终快照、校验与恢复记录。
- 数据/代码说明、结果索引和授权台账。
- 交接签收、遗留事项及权限处理记录。

**验收标准**

- 接收人可以找到并打开核心材料，关键证据能够复查。
- 密码不写入普通文档，敏感资料保存在授权位置，公开版本已脱敏。
- 责任、保存期限与离组后的联系和使用边界明确。

未达要求：缺失材料或复查失败时先补齐并重验；无法恢复的内容写明原因和影响，不用空目录或目录截图代替实际交接。

下一步：归档与交接获接收后结束本轮培养任务，后续成果修订按既定责任继续跟进。

配套模板：数据、代码与毕业材料归档（archive.md）、阶段移交与离组交接（handover.md）、成果要求核对与成果台账（outcomes.md）、学习复盘与成长计划（learning-review.md）

## 博士研究与学位全流程

独立定义问题，以可核验的研究形成贡献，并将多项工作组织为连贯的学位论文。

不同学制、学习方式和学位类别的博士生，含国际学生；按本人适用的培养方案确定正式要求。；按正式培养节点安排；基础学习、研究、写作和年度回顾交叉推进，依据证据定期调整研究主线。

本页是研究与成长的工作框架，不替代校本培养程序。资格考核是否设置及其与开题的先后、年度与中期安排、预答辩位置、成果认定和学位申请条件均须逐项核实；年度回顾贯穿培养全过程。学术学位与专业学位的贡献形式按适用规定确认，不统一设定学制、论文数量、发表级别或检测阈值。

**这条路径要形成的能力**

- 围绕有价值的未解问题建立持续研究主线，论证原创贡献及其与已有知识的区别，并主动检验可能推翻主张的证据。
- 在不确定条件下选择、修正和整合研究方法，使多个研究环节共同支撑主线，解释理论、实证或实践贡献的适用边界。
- 以独立判断组织研究、学术交流和合作，接受实质性质疑并据证据回应，留下可复查、可接续的研究材料。

**开始时，用小任务确认起点**

- 根据本人培养方案列出课程、资格考核、开题、年度或中期、成果与学位条件，保存适用文件；与导师确认指导结构、决策责任和检查安排。
- 提交一个已完成研究的论证地图，关联问题、主要主张、关键证据和局限；说明本人完成与合作部分，并指出一个仍未解决的问题。
- 对拟研究主线给出最接近工作的比较、初步证据或明确标为待检验的假设、关键资源与失败条件，再用一项小规模验证识别最薄弱的前提。

**学生负责什么**

学生主动维护研究主线、贡献边界与证据缺口，提出研究优先级和方法取舍，并组织必要的复核与学术讨论。关键主张被反证、合作或数据条件改变、主线失去可行性时，应尽早提交诊断与备选方向，与指导团队讨论调整。

**指导与支持负责什么**

导师或按培养安排组成的指导团队对原创性、方法质量、研究范围和发展提供持续质询与支持，明确各成员的反馈职责。帮助学生接触不同观点并获得必要资源；正式考核与学位评价按学校规定组织，不用组内共识替代独立评审。

**怎样获得反馈并改进**

阶段交流重点检查新证据是否改变主张、各项工作如何共同支撑主线，以及关键异议是否得到实质回应。学生写出拟采纳与暂不采纳意见的理由，完成补证或修订后邀请适当人员复核；重复出现的缺口应触发主线或方法调整，而非只增加实验数量。

**带着什么进入下一步**

研究结束时，把核心论证、可复查材料、未解问题与后续责任交接清楚；开展独立研究或专业工作时，能够在新问题上重新组织证据、合作与质量控制。论文数量、发表状态、答辩结论和正式学位授予分别记录，不用单一数量替代研究独立性或原创贡献的评价。

### 01 培养依据、指导关系与成长计划

参考时机：入学及指导关系确定时建立；每学期和要求变化时复核

目标：明确自己需要达到的研究能力、正式培养条件和支持渠道，能够主动组织长期研究并及时寻求帮助。

**进入条件**

- 已确认学籍、学位类别、研究方向及导师或指导团队安排。
- 能够取得本人年级适用的培养方案、学位要求和学院通知入口。

**操作步骤**

- 登记课程、资格考核、开题、年度与中期、教学或实践、论文与学位环节；逐项记录正式依据、先后条件、办理窗口和负责部门，未知事项列入咨询清单。
- 自评理论、方法、工程、学术表达和研究规范能力，以已有作品或试做任务为依据，形成需要补足的能力及对应学习产出。
- 与导师或指导团队约定研究讨论、材料反馈、分歧处理和阶段审查方式；明确日常建议、导师认可与正式考核结论的区别。
- 建立研究目录、文献库、版本记录、备份及授权台账，完成适用的伦理、安全与诚信培训；涉及国际学生时分别核对授课、论文、摘要和答辩语言以及资源访问条件。
- 制定本学期研究与学习计划，注明各任务的证据、反馈对象和复核日期；将健康、资源或指导关系困难交由适当支持渠道协调，不在公开材料记录敏感细节。

**交付材料**

- 个人培养要求登记表，含已确认事项、待核实事项和正式来源。
- 能力基线与学期成长计划，含具体作品、检查方式和优先次序。
- 指导沟通约定、资料目录及备份恢复入口。

**验收标准**

- 学生能够解释各正式节点的条件与责任人；教务或学院负责人员确认存在疑问的制度适用问题。
- 导师或指导团队已审阅研究方向、能力差距和工作安排；必要的正式培养计划已按学校流程确认。
- 学生能够找到资料和求助渠道，并实际完成一次非敏感样本的备份恢复检查。

未达要求：规则不明时先向负责部门核实，保留待确认状态；指导资源、语言或能力存在明显缺口时与导师和相应支持部门调整计划，避免在前置条件不清时承诺毕业时间。

下一步：根据能力差距安排基础学习，同时开始建立问题地图；年度记录从此阶段持续维护。

配套模板：入组与阶段计划（onboarding.md）、校本要求核对与年度培养记录（annual-check.md）、会议、讨论与决策记录（meeting.md）、数据、代码与毕业材料归档（archive.md）

### 02 学科基础、研究方法与问题地图

参考时机：入学初期集中建立，随研究问题变化持续补充

目标：能够说明领域的关键概念、方法假设和证据边界，独立判断一个问题是否值得研究，而非只复述论文结论。

**进入条件**

- 已形成能力基线和学习计划，并具有必要的课程、文献与计算资源。
- 已初步确定研究方向，但允许经阅读和试验调整。

**操作步骤**

- 围绕候选研究方向列出理论与方法先修知识，以推导、代码实现、例题解释或案例分析检验掌握情况，不以阅读数量代替理解。
- 保存检索范围与筛选依据，比较代表性工作、相反结果和领域争议，建立问题、假设、方法、数据与评价的关系图。
- 选择能够澄清关键疑问的基线复现、理论推演或实地观察，记录实际条件与失败；区分原文报告、自己真实运行和构造示例。
- 提出候选问题，分别写出真实需求或理论依据、尚未解决的条件、可能的替代解释，以及能够推翻当前判断的观察。
- 向导师或合适的领域同伴解释核心论证并回应质疑，标记仍依赖帮助的部分，将其转为下一轮学习任务。

**交付材料**

- 知识与方法能力清单，附推导、实现或分析作品及待补项。
- 可追溯文献矩阵、争议记录和问题地图。
- 初步验证记录与候选问题比较，含否定证据和资源限制。

**验收标准**

- 学生能脱离原文解释关键假设、方法选择及失败条件，并正确区分观察、推断与未知。
- 导师或受邀领域人员检查代表性文献覆盖、基础理解和问题比较；同伴意见记录为反馈，不冒充正式考核结论。
- 候选问题有可追溯依据，能说明为什么现有方法尚不能在所述条件下充分解决。

未达要求：基础解释或最小验证无法完成时缩小任务，补学关键概念后重新演示；若已有研究已解决候选问题或实际需求无依据，调整问题地图并重选方向。

下一步：基础能力和问题依据形成后，按正式安排准备资格考核（如适用）与研究方案；二者先后以校本规定为准。

配套模板：论文阅读与复现判断（reading.md）、文献综述与证据矩阵（literature.md）、实验、复现与运行证据（experiment.md）、选题论证与范围界定（topic.md）

### 03 资格考核与研究准备核验（如适用）

参考时机：正式资格考核窗口；未设置该环节时仅开展研究准备讨论

目标：能够独立解释学科基础、分析开放问题并回应追问，确认进入下一研究阶段所需的能力和正式资格。

**进入条件**

- 已核实本人是否需要资格考核、申请条件、形式、范围及其与开题的先后关系。
- 已有基础学习作品、研究问题草案和自评差距；适用时已满足报名条件。

**操作步骤**

- 依据正式考核说明整理申请材料和准备清单，核对语言、时间、提交方式及允许使用的辅助资源；不把他人的考试经验视为规则。
- 通过推导、口头解释、方法比较或开放问题分析检验理解，说明关键假设、反例、局限和不确定处。
- 进行模拟问答，先由学生独立回应，再根据导师或同伴反馈补足知识；记录真实薄弱点，不将模拟成绩写成正式通过。
- 按要求参加正式考核，取得学院或考核组织出具的结果与整改要求；未设置资格考核时保存研究准备讨论记录，不建立虚构的资格结论。

**交付材料**

- 资格考核适用性及申请条件核对记录。
- 准备作品、问答记录和能力差距整改表。
- 正式结果及后续要求；不适用时为研究准备讨论记录。

**验收标准**

- 学生能解释关键概念及其适用条件，遇到未知问题能够给出合理分析路线并明确不确定性。
- 导师检查准备材料与能力差距；资格是否通过以学校指定考核组织的正式结论为准。
- 补考、整改或不适用状态准确记录，下一环节所需条件已核对。

未达要求：未达到能力要求时按具体薄弱点安排补学和复核；正式未通过时遵循规定的整改、复核或其他处理程序，不自行跳过前置资格。

下一步：在已满足正式前置条件的情况下推进开题；若校本安排开题在前，则按实际程序回填结果并继续研究。

配套模板：校本要求核对与年度培养记录（annual-check.md）、论文阅读与复现判断（reading.md）、会议、讨论与决策记录（meeting.md）、课题、计划与资源变更（change-request.md）

### 04 研究主线、子问题设计与正式开题

参考时机：在学校规定的开题窗口内，具备必要的前期证据后

目标：独立提出具有贡献潜力且能够检验的主问题，说明多项研究之间的逻辑关系与逐步收敛的实施方案。

**进入条件**

- 已满足正式开题条件，掌握核心相关工作并完成必要的前期验证。
- 关键数据、设备、方法能力和合作条件已有可核验的可行性依据。

**操作步骤**

- 以一句可讨论的主问题统领研究，明确对象、适用条件与研究价值，列出子问题如何共同支持主问题而非仅按技术模块并列。
- 将预期理论、方法、系统或实践贡献与最接近工作逐项比较，为每项主张设计支持证据、竞争解释和可能否定它的结果。
- 安排各子研究的依赖、方法、比较对象、评价标准和数据来源；说明伦理与授权要求、成本上限、停止条件及替代方案。
- 按正式开题格式准备报告和陈述，区分已完成结果与拟开展工作，并用前期记录证明最低可行性。
- 参加开题评审，逐条记录意见、实际修改、尚存分歧与需重新评审的事项；导师建议与正式评审结论分别保存。

**交付材料**

- 开题报告与研究主线图，含子问题依赖及预期贡献。
- 主张—证据—替代解释表、前期验证材料和研究风险计划。
- 正式开题结果、意见回复及后续阶段任务。

**验收标准**

- 学生能解释为何这些子研究构成一项博士研究，以及哪些结果将迫使自己调整主张或方向。
- 导师或指导团队审查可行性和资源承诺；开题是否通过由学校指定评审组织决定。
- 评审要求已转为具体修改或待复核任务，各研究的证据、检查人和下一检查点清楚。

未达要求：主线松散、贡献重叠或关键证据不可得时缩减并重构子问题；未通过或需重开题时按正式意见完成整改，在确认所需程序后再推进相关研究。

下一步：按确认后的方案启动首个子研究，同时安排贯穿全程的年度、中期与研究主线回顾。

### 05 独立研究、证据检验与迭代

参考时机：开题后的研究周期内反复进行；必要的探索可在开题前开展

目标：独立完成问题到证据的研究循环，能够识别结论何时成立、何时失效，并据此调整研究主线。

**进入条件**

- 已有清晰的子问题、适当的前置批准和可获得的研究资源。
- 能够说明当前主张、比较对象、判定依据及所需原始证据。

**操作步骤**

- 为当前子问题建立任务卡，固定本轮假设、方法、比较条件、分析计划和判定依据；探索后新增的分析单独标记。
- 完成理论推导、方法实现、实验或实地研究，保存实际环境、原始记录、版本和失败；证明中的前提与推导、实验中的观测与解释分别记录。
- 主动检验替代解释与边界条件，按问题需要采用反例、消融、稳健性分析、误差检查或独立复核，避免只选择有利案例。
- 在指导讨论前提出自己的结论、理由与下一步选择；记录异议和待验证事项，由学生据证据修订方案，重大范围或资源变化按要求办理。
- 把每轮结果写回研究主线和论文草稿，维护协作者任务与贡献记录；保留无效方法和否定结果，以便后续判断而非重复试错。

**交付材料**

- 按版本保存的研究记录、原始证据、代码或推导及运行或阅读入口。
- 主张检验表，含支持结果、相反结果、替代解释和尚未检验的条件。
- 阶段研究小结、个人与协作贡献记录及下一轮任务卡。

**验收标准**

- 学生能独立解释方法选择、关键结果和失败，结论强度与实际证据相符。
- 导师或指导团队检查论证与研究价值；适合复核的部分由具备条件的同伴或指定复核人员检查，记录其真实复核范围。
- 关键结果可追溯至材料和版本；无法重现或受访问限制的部分明确标注，不把保存回放当作新的真实运行。

未达要求：关键结果不稳定、替代解释未排除或资源无法支持时，先定位证据缺口并缩小主张；连续缺少支持时按停止条件暂停该路线，保留否定结果并提交主线调整方案。

下一步：按约定周期进入年度或中期回顾；证据充分的研究同步进入贡献整合和写作，其余研究继续迭代。

配套模板：科研训练任务卡（research-task.md）、实验、复现与运行证据（experiment.md）、周报与下一阶段计划（weekly.md）、会议、讨论与决策记录（meeting.md）、课题、计划与资源变更（change-request.md）、AI 辅助使用与披露记录（ai-use.md）

### 06 持续年度回顾、中期考核与方向调整

参考时机：从入学开始持续维护；按学校年度、中期等正式节点提交，不以研究完成为前提

目标：用实际证据检查能力增长、研究主线和培养进度，及时发现不可完成的承诺并作出可执行调整。

**进入条件**

- 已有上期确认的培养计划、研究任务和后续正式节点。
- 已汇集本期课程、研究、学术交流及其他适用培养事项的实际记录。

**操作步骤**

- 对照上期计划和正式要求登记已完成、未完成、变更和未知状态，链接作品、原始记录或正式结果，不以工作时长或论文数量代替能力判断。
- 比较本期与上期的独立定义问题、方法选择、证据分析和学术表达能力，用具体工作说明进步与仍需支持的部分。
- 复核子研究之间的联系、相反证据和剩余关键风险，提出继续、收缩、合并或停止某条路线的理由与代价。
- 向导师或指导团队提交自评并参加适用的年度或中期考核；将评审意见转为整改任务，记录负责人、证据、期限及复核人。
- 更新下一阶段计划和预计完成路径；涉及延期、休学、指导关系或重大课题变更时向负责部门核实并办理正式手续。

**交付材料**

- 年度或阶段自评报告，含培养事项状态和能力成长证据。
- 研究主线与风险更新、正式考核材料及实际结果。
- 整改跟踪表、下一阶段计划及需要办理的正式事项。

**验收标准**

- 学生解释计划差异的原因，并能给出有依据的优先次序和可完成的下一步。
- 导师或指导团队审阅研究与成长计划；年度、中期是否通过以学校指定考核组织的结论为准。
- 整改是否关闭有实际复核记录；资源和个人困难已落实到适当协调渠道，未公开不必要的敏感信息。

未达要求：正式考核未通过时按规定整改与复核；研究停滞或工作量超出资源时缩减范围并更新主线，必要时办理延期等手续，不能通过修改历史计划掩盖偏差。

下一步：将确认的调整带回当前研究与学习任务；证据足够时推进贡献整合，同时继续下一周期回顾。

配套模板：校本要求核对与年度培养记录（annual-check.md）、中期检查与差距整改（midterm.md）、课题、计划与资源变更（change-request.md）、会议、讨论与决策记录（meeting.md）、学习复盘与成长计划（learning-review.md）

### 07 原创贡献整合、成果认定与学术交流

参考时机：各子研究取得可核验结果后持续进行；学位申请前再次核对

目标：清楚说明个人博士研究增加了什么知识或能力，将多项研究整合为有边界的贡献，并准确判断适用成果条件。

**进入条件**

- 已有能够支持核心主张的研究证据及相反结果记录。
- 已取得本人适用的成果认定依据，协作分工与授权状态可核实。

**操作步骤**

- 为每项贡献关联主问题、最接近工作、个人完成部分、关键证据和适用范围，检查各贡献是否相互支持及是否存在重叠。
- 区分理论、方法、系统或专业实践贡献与单纯工作量，说明研究改变了何种认识或解决能力，以及仍未解决的问题。
- 按实际学位类别核对允许的成果形式和认定条件，分别记录在做、投稿、接收、发表或其他正式认定状态，保留证明材料。
- 与合作者确认贡献记录、署名、知识产权和材料使用许可；学位论文使用合作成果时明确个人部分及必要说明。
- 通过论文投稿、报告或适当的学术交流接受外部质疑，逐条回应实质意见并在需要时补证或收缩结论，不把接收结果当作免于进一步检查的依据。

**交付材料**

- 主问题—子研究—原创贡献—证据对应表。
- 成果台账与适用条件核对记录，附实际状态证明。
- 协作贡献和授权记录、学术交流材料及意见回复。

**验收标准**

- 学生能够用完整论证说明原创贡献，而非仅列出论文题目或实验增幅。
- 导师或指导团队审查贡献逻辑和个人工作边界；成果是否满足申请条件由负责部门按适用规定认定。
- 外部意见已对应到实际修改、补充证据或有理据的说明，未解决分歧及成果真实状态清楚。

未达要求：贡献不足或彼此割裂时返回研究补足关键联系或缩小主张；成果认定不确定时咨询负责部门；投稿被拒后按实质意见修订，不把重复投稿或夸大状态当作问题解决。

下一步：以已验证的主线组织完整学位论文，同时补齐仍影响主要论证的研究和正式申请条件。

### 08 学位论文统整与学术规范检查

参考时机：研究过程中持续写作；送审前形成可完整审阅的版本

目标：形成逻辑连贯、证据充分、个人贡献明确的博士论文，使读者能够追溯主要论断并理解其适用边界。

**进入条件**

- 研究主线和核心贡献已有证据支持，缺口及待完成工作明确。
- 已核实论文语言、格式、合作成果使用和适用规范检查要求。

**操作步骤**

- 建立章节论证图，说明总问题如何引出各子研究、结果如何回到总问题，撰写跨研究综合讨论，避免把多篇论文直接拼接。
- 为核心论断链接原始证据、推导或材料位置，核对符号、数据、图表与不同版本的一致性；相反结果和局限放入论证而非隐藏。
- 明确本人及合作者贡献、已发表材料来源、引用和必要许可，核验参考文献原文；记录 AI 实际用途、人工核验及适用的披露。
- 按导师或指导团队约定分轮审阅结构、论证和表达，逐条记录修改与未决问题；需要语言支持时保持研究判断与内容责任由学生承担。
- 分别核对学术规范、学校所称查非或其他专项检查、查重及匿名要求，记录各自的正式依据、版本、结果和整改，不能以一个检测数值替代学术判断。

**交付材料**

- 完整论文稿、章节论证图和核心主张证据索引。
- 审阅意见与修改记录、合作贡献和材料来源说明。
- 适用的规范检查记录、AI 使用记录及送审前待办清单。

**验收标准**

- 学生能够解释整篇论文的统一主张、章节关系与局限，主要结论均有可追溯依据。
- 导师或指导团队完成约定的内容审阅；规范检查和正式提交资格由学校指定人员或部门依规定确认。
- 论文语言、引用、图表、贡献说明与实际材料一致；每项检查对应确切版本，未解决事项未伪装为已通过。

未达要求：核心论断缺证时返回研究补证或缩小结论；主线不连贯时重构章节；规范问题逐项整改并按要求复核，不能用措辞改写掩盖来源或材料问题。

下一步：满足正式条件并完成所需审阅后进入评阅；预答辩如为前置环节，按学校安排先完成并整改。

配套模板：学位论文写作与版本检查（thesis.md）、学术规范、查非与查重（integrity.md）、AI 辅助使用与披露记录（ai-use.md）、成果要求核对与成果台账（outcomes.md）

### 09 预答辩、送审与评阅意见处理

参考时机：按学校规定的顺序和窗口办理；预答辩是否设置及位置单独核实

目标：向评审者提交准确完整的研究，并通过逐条回应和实质修改提升论证质量，明确正式评阅状态。

**进入条件**

- 已核实送审资格、所需前置环节、匿名范围、材料和提交渠道。
- 论文已完成必要审阅与规范检查，待提交版本能够准确识别。

**操作步骤**

- 核对预答辩是否适用及其位置、评阅申请条件和提交窗口；需要预答辩时按安排陈述主线与贡献，完成要求的修改和确认。
- 冻结送审版本并登记日期和校验值；按要求检查正文、补充材料、文件元数据及链接中的匿名信息，同时保留适当引用与完整材料。
- 通过正式渠道提交并保存回执，记录版本、材料清单和实际评阅状态；不得通过非正式方式联系评阅人干预评审。
- 收到意见后逐条分析事实问题、论证缺口、方法质疑和表达问题，给出修改位置、补充证据或有依据的说明，明确仍未解决之处。
- 将重大修改、复审或申诉交由规定渠道处理；导师检查回复与正文的一致性，等待所需正式结论后再确认下一环节资格。

**交付材料**

- 适用的预答辩记录、送审资格核对表及冻结版本记录。
- 提交材料清单、回执和正式评阅结论。
- 逐条回复、修订论文及复审或整改确认记录。

**验收标准**

- 实际提交材料与所登记版本一致，匿名处理符合要求且不损害论证完整性。
- 学生能够解释每条实质意见如何改变研究或论证；导师核对修改与回复，而正式评阅结果以指定评阅流程为准。
- 需要的复审、整改或申诉已按程序记录，是否具有正式答辩资格由负责部门确认。

未达要求：意见揭示核心缺陷时返回研究或写作补足证据；评阅未通过时遵循整改、复审或申诉程序，不更换版本后绕过正式判定，也不将导师同意代替评阅通过。

下一步：取得所需评阅及整改确认，并满足学校规定的全部前置条件后，申请正式答辩。

### 10 正式答辩、修改验收与学位申请

参考时机：获得正式答辩资格后；后续修改和学位手续按通知完成

目标：清楚捍卫研究主线与原创贡献，诚实回应证据边界，并完成答辩后修改和各项正式学位程序。

**进入条件**

- 答辩资格、评阅及所需整改已按学校程序确认。
- 已取得答辩组织、材料、语言、时间及后续学位申请要求。

**操作步骤**

- 围绕主问题、贡献、关键证据、个人工作和局限准备陈述，确保使用的数字、图表和结论对应当前论文版本。
- 练习回应替代解释、研究选择和跨子研究联系；如使用演示，准备可离线展示的适当材料，并准确说明演示覆盖范围。
- 参加正式答辩，依据实际证据回答问题；不确定时明确说明并记录后续核实事项，由答辩组织形成正式记录和结论。
- 将答辩意见逐条对应修改和证据，经指定审核人确认后形成终稿；需要进一步研究或再次答辩时遵循正式安排。
- 按要求提交终稿与学位申请材料，分别追踪答辩结果、修改接收、毕业审核和学位审议状态，不把答辩通过写成已授予学位。

**交付材料**

- 答辩陈述、必要演示材料与当前版本对应表。
- 正式答辩记录、意见回复和修改验收记录。
- 终稿、学位申请材料及各环节实际状态台账。

**验收标准**

- 学生能够独立解释原创性、方法选择、证据与局限，回答与论文材料一致。
- 答辩结论由正式答辩组织作出，修改由指定审核人验收；导师指导不替代这些正式决定。
- 学位及毕业状态有相应部门记录支持，尚待审议或补交的事项明确。

未达要求：答辩或修改未获通过时按正式结论安排补充研究、整改或再次答辩；材料不全时补齐并确认接收，不把上传成功当作审核完成。

下一步：按确认后的终稿和要求完成学校归档与研究交接，并继续跟踪尚未完成的毕业和学位手续。

### 11 研究资产归档、交接与后续发展

参考时机：研究期间持续归档；阶段结束、毕业或离组时完成正式交接

目标：使研究证据能够在权限范围内被理解和复核，交清协作责任，并把博士阶段形成的能力转化为下一阶段发展计划。

**进入条件**

- 已确认需要保存、提交和移交的材料及其版本、权限和接收对象。
- 已核实学校归档要求、合作约定和仍未完成的研究或学位事项。

**操作步骤**

- 整理终稿、原始与处理数据、代码、环境、推导、实验日志、审阅及授权材料，建立可追溯清单并保留必要版本关系。
- 为受限数据、知识产权和个人信息设置合适的存储与访问安排；公开材料单独审查，完成归档不等于取得公开发布许可。
- 编写从入口到关键结果的恢复或复核说明，由接管者或指定人员实际抽检，记录所用环境、通过范围、失败和无法验证的部分。
- 移交项目、设备、服务、资料和未完成事项，按管理流程调整访问权限，不传递个人账号密码；确认投稿回复和后续合作责任。
- 总结独立定义问题、方法选择、证据判断、表达与协作的成长，形成可分享的研究介绍及下一阶段学习计划，并确认学校归档和后续手续的实际接收状态。

**交付材料**

- 归档清单、版本与校验记录、权限和保存期限说明。
- 恢复或复核指南及接管者实际抽检记录。
- 交接签收、未完成事项责任表及学校归档回执。
- 研究能力回顾和下一阶段发展计划。

**验收标准**

- 接管者能够找到材料、理解关键依赖并完成约定抽检；未实际验证的内容明确标注。
- 导师或项目负责人确认研究交接，学校指定接收部门确认正式归档；权限、设备和未完成责任已由相关负责人核对。
- 学生准确区分可公开材料与受限材料，学位、毕业及归档状态均有实际依据。

未达要求：关键文件缺失、恢复失败或权限不清时先修复并再次抽检；接管者未确认前保留必要访问和责任安排，不能仅压缩文件或发送链接就标记交接完成。

下一步：确认归档、交接和应办手续完成后结束本轮培养记录；后续研究按授权与协作约定继续维护证据和责任。

## 学习与成长

把培养路径变成自己的学习计划，需要知道当前会什么、下一步要学会什么，以及凭什么判断已经学会。本页将本科科研训练、毕业设计、硕士与博士的阶段要求连接为一个可反复使用的学习循环，帮助你逐步承担更多判断与组织责任。

### 先用小任务找到学习起点

选一个与你当前阶段有关、资料和资源允许使用的小任务，在同一份记录中尝试下面四项。保留实际产物和得到的帮助，再决定补什么。即使已有相关课程成绩，也需要检查能否将知识用于当前任务。

#### 能解释：说清对象与理由

用自己的话说明问题、输入、输出、关键概念和一个具体例子，指出依据来自哪篇原始论文或官方文档。请同伴追问一个“为什么”；记录你能解释到哪里、哪些词仍只能照读。

**留下证据：**简短说明、概念图或带来源的阅读笔记，以及尚未理解的问题。

#### 能运行：完成最小实践

按资料完成一个最小程序、实验、推导或分析，记下环境、输入、步骤与实际结果。换一个输入后再试；若不能完成，保留最小失败案例和错误信息。

**留下证据：**可重做的命令、材料与输出，或标明具体阻塞点的失败记录。

#### 能比较：说明变化意味着什么

选择两种方法或两种设置，说明相同条件、变化因素和评价方法；检查差异是否来自数据、资源或操作条件。样例太少时，只描述这次观察，并列出尚不能支持的判断。

**留下证据：**比较表、原始记录链接、差异解释与仍需核查的因素。

#### 能提问：把困惑转成下一步

写清预期、实际、已经尝试的方法及具体不确定之处。说明需要谁提供哪类帮助，或设计一个能排除某种解释的小检查。

**留下证据：**一个可回答的问题、拟检查的证据，以及求助或验证安排。

每项记录“独立完成 / 借助提示完成 / 尚未完成 / 本轮不适用”，并附证据与理由。这些状态用于选择下一步练习；不同任务上的状态可能不同。得到帮助后，再做一个变化过的小任务，观察是否能解释和完成。

#### 贯穿示例：研究一个项目的测试失败

**以下仅为任务设计示例，不代表已完成的研究或实验结果。**本科入门可以从运行一个公开项目的测试开始，解释一条失败记录并保留重做步骤；毕业设计可以实现一个范围明确的失败定位工具，为正常、异常和边界情况设计验证；硕士可以围绕有依据的定位困难提出问题，与适当方法进行公平比较并分析失效条件；博士可以进一步组织一组相互关联的研究，解释哪些因素限制定位能力、提出可检验的贡献，并在证据允许的范围内讨论适用性。

向下一层推进的依据是能够提出和回答更充分的问题。项目规模、代码行数或材料数量可以帮助安排工作，但需要结合解释、验证与判断的证据评价成长。

### 让每轮学习接上上一轮，也通向下一轮

从当前培养阶段选一个可检查的能力目标，用同一条记录串起六步。阅读和实践可以反复交替；检查发现缺口时，回到相应步骤修改，保留版本与原因。

1. **诊断当前起点**用解释、运行、比较和提问留下证据，注明独立完成程度、所获帮助及当前缺口。
2. **选阶段与能力目标**进入相应培养路径，写清本轮要能做什么、交付什么、怎样检查，以及需要的资源与支持。
3. **学习并开展实践**阅读直接相关的原始资料，完成最小练习，再用于实际任务；记录关键选择、错误和尝试。
4. **记录证据并自检**按约定判据检查结果，核对来源和版本，区分观察、解释与尚未验证的判断，列出缺项。
5. **获得反馈并纠正**提出具体问题，将意见转成可执行修改；重做有关检查，记录解决情况与仍有分歧的事项。
6. **迁移并安排下一步**在变化的输入、方法或情境中尝试使用所学，比较所需帮助；据此选择下一阶段、补练或缩小任务。

**本轮结束时只作有证据的结论：**“达到本轮目标”“部分达到，继续补练”“调整目标后再检查”均可使用。将决定、依据、下一任务和检查安排写清楚；正式培养节点是否通过，另以有权部门的结论为准。

### 卡住时，选择能够解除阻塞的行动

先判断主要困难属于哪一类，再准备最小而充分的材料。等待他人反馈期间，推进不依赖该决定的阅读、整理或检查；涉及未获准的数据、权限或正式要求时，先取得相应确认。

#### 概念不清：缩到一个例子

**表现：**能重复术语，却解释不了适用条件或方法为何这样做。

**行动：**回到原始定义，写一个正例和反例，标明推理中断的句子或步骤。请导师、助教或熟悉该主题的同伴检查这处理解。

**复核：**用一个新例子重新解释；仍需逐句提示时，继续补基础并缩小本轮范围。

#### 实现受阻：保留最小失败案例

**表现：**程序、实验或数据处理无法产生预期输出，错误原因不清。

**行动：**固定版本、输入和步骤，缩小到可重现的失败；记录尝试及结果。方法问题联系指导者，环境或权限问题联系相应资源负责人。

**复核：**修改后重做原失败案例，并补一个相邻情形；写明修复解释与尚未覆盖范围。

#### 证据不足：检查主张与方案

**表现：**结果与预期冲突、比较条件不一致，或已有结果支撑不了想写的结论。

**行动：**列出主张、现有证据、候选解释和最有区分力的下一检查，与导师或方法顾问讨论；必要时收缩主张、调整设计或停止无效路线。

**复核：**用新增证据检查原判断，保留负面与不确定结果，说明结论变化及其原因。

#### 一条可以直接使用的求助消息

“我在完成【阶段与任务】，预期【具体结果】，实际得到【现象与证据链接】。我已尝试【方法及结果】，目前不确定【一个具体问题】。希望【联系人】帮助确认【解释、选择或资源】；得到反馈后，我会用【检查方法】复核，并在【双方约定的时间】更新记录。”

计划开始时约定检查点和阻塞处理方式。若连续尝试没有产生新信息，或阻塞已经影响约定节点，应及时汇报并调整；不必等到所有尝试都做完才求助。涉及研究诚信、人员安全或数据授权的疑问，先暂停相关操作并联系负责人员。

### 复盘同时检查成果质量与能力成长

建议结合已有周报、组会或阶段检查复盘，避免重复填写。短任务可在完成后复盘，持续研究可约定周期与关键事件触发的检查；周期应由任务依赖、反馈需要和个人情况决定，本页不设统一时长或学校门槛。

- **先写本轮能力：**使用“能够解释某方法的前提”“能够重现实验并检查差异”等可观察表述，写明起点证据和本轮检查条件。
- **再连起学习与产物：**记录原始资料的标题、位置和用途，将阅读转成推导、实现、比较或提问；提供对应的版本、数据、日志与材料链接。
- **单独看成果质量：**检查正确性、完整性、可重复性、主张与证据一致性及正式提交缺项；失败或未完成的结果如实保留。
- **单独看能力成长：**对照起点说明现在能独立解释、执行、比较或判断什么，仍需哪些提示。团队产物应标明个人工作和获得的帮助。
- **让反馈闭合：**逐项写出反馈、采纳或暂缓的理由、修改证据与复查结果。遇到分歧，列出还需要的证据和下一次讨论安排。
- **安排迁移与下一步：**改变一个有意义的条件再次尝试；据结果选择进入下一阶段、继续练习或调整目标，并明确资源、求助对象与检查安排。

**简短填法示例（待执行计划）：**本轮能力：“能够解释测试失败与代码缺陷之间的区别”；起点：“目前只会转述错误消息，尚未检查环境因素”；学习任务：“阅读项目测试说明，设计两个可能原因的区分检查”；拟交证据：“命令、环境信息、输出与解释表”；迁移任务：“换一条失败记录再次判断”。执行后再填真实结果和反馈，不预先标记完成。

语言表达、软件熟练度与研究判断可以分别改进。需要双语术语表、书面反馈、辅助技术或其他学习支持时，在复盘中说明具体需要，并使用[沟通与支持指南](https://csma-graduation-projects.github.io/international.html#support) 确认可用安排。

### 先约定责任与沟通方式

学生负责理解要求、提出计划、完成工作、保留真实记录并主动报告困难；导师负责方向、方法、资源和质量上的指导，说明反馈安排，帮助判断范围与优先级。正式培养审核、成果认定、学位申请等由学校指定人员和组织办理。组内检查通过，只说明具备进入下一步的准备，不能代替正式审批。

入组时共同完成一份指导约定：本学期目标、固定交流时间、会前材料、常用渠道、预期反馈时间、紧急事项联系人和请假方式。周期可根据任务调整，不在网页上统一规定每日工作时长，也不把论文数量、在线时长或消息回复速度当作未经确认的考核标准。

不同沟通渠道承担什么工作

| 渠道 | 适合办理 | 留下的记录 |
| --- | --- | --- |
| 学校系统与正式邮件 | 培养审批、请假或外出申请、重要计划变更、需要明确答复的事项；学校要求系统办理时优先使用系统。 | 申请内容、时间范围、明确答复和系统回执。邮件不能替代必须办理的系统手续。 |
| 受控 GitHub 仓库或学校任务平台 | 任务拆分、代码与文档版本、实验记录、问题跟踪、阶段交付。 | 任务负责人、完成条件、提交版本和处理结果。先确认访问权限，再放入材料。 |
| 微信等即时沟通 | 临时协调、紧急提醒、会议变动和简短确认。 | 涉及正式决定时，再补到邮件、任务记录或指定系统，避免决定只留在聊天中。 |

### 让每天的工作连接到学期目标

每天开始前选出当前最重要的一项可交付任务，确认需要的输入与资源；结束前记录完成内容、文件版本、实验状态和下一步。一次失败的运行也有价值：写清预期、实际现象、已排查原因和下一次验证，不以重复尝试次数代替进展。

每周对照计划形成简短周报，附上能打开的证据；根据反馈更新任务状态。每月回看研究问题是否仍成立、工作是否偏离主线、资源预算是否足够，并对完成的里程碑做一次可运行或可核查的展示。每学期依据培养方案核对课程、学术活动、专业实践和正式考核，提前登记下一阶段的官方截止时间。

这些频率是建议起点。课程密集、实习、集中实验或答辩准备期间，可以与导师重新约定；调整后要有明确的下一次检查日期。不要同时承诺多个互相争抢时间的任务，先确定关键任务，再安排辅助阅读和工具学习。

### 用完成条件管理任务

一条任务应写清「要解决什么、交付什么、怎样验收、谁负责、何时检查」。例如，将“继续做实验”改为“运行已确认的数据划分与基线，提交命令、配置、完整日志和结果差异说明”。交付时间是计划；完成状态要由材料和检查结果支持。

建议使用的任务状态与转换条件

| 状态 | 进入条件与下一步 |
| --- | --- |
| 待开始 | 目标与输入已明确，确定优先级和检查日期后开始。 |
| 进行中 | 记录当前版本与最近一次结果；工作过大时拆成可验收的小项。 |
| 受阻 | 说明阻塞原因、已尝试方法、所需帮助、影响和备选方案；及时发出求助。 |
| 待检查 | 交付材料齐全并完成自查，注明希望对方检查的问题。 |
| 已完成 / 待修改 | 记录检查结论；待修改项补充问题位置、责任人和复查日期。正式考核另记官方状态。 |

题目、数据、方法或截止时间发生重要变化时，保留原计划，说明原因、已完成工作如何使用、影响和新计划，再由对应负责人确认。无法按期完成时，尽早报告并缩小范围，不能等截止后补造进度。

### 周报和组会要形成下一步

跨语言协作时，先约定组会与反馈语言，提前提供术语和议题，会后用简短行动记录确认理解。不要用口语流利程度代替对研究质量的判断；需要语言、学习或资源支持时，参阅[国际学生支持与沟通说明](https://csma-graduation-projects.github.io/international.html#support) 。

周报围绕五件事：本周原计划、实际完成及证据、得到的认识、尚未解决的问题、下周可交付任务。把事实与解释分开，例如“本次三次运行中两次失败”是事实，“可能由资源不足引起”是待验证解释。阅读进展说明理解了什么、与当前问题有什么关系；实现进展说明哪些功能已经验证、哪些仍未完成。

会前按约定时间发送材料，并列出需要讨论的具体问题。会上优先讨论结论依据、关键困难和方案取舍；会后整理决策、行动项、负责人、检查日期与需要补充的证据。未达成一致的事项写成待确认，不将猜测记录为导师决定。下一次交流先回看行动项，再讨论新问题。

向导师提交稿件时说明版本、本次主要改动、期望反馈范围和计划提交日期，预留合理审阅时间。反馈超出约定时间，可简短提醒并指出受影响的节点；涉及正式截止日期时同步联系学院负责人员，寻求可执行安排。

### 区分请假、实习与专业实践

请假是特定时间内调整学习或出勤安排；实习是校内外的岗位或项目经历；专业实践是培养方案规定的教学环节。参加实习不自动等于完成专业实践，获得单位证明也不自动替代学校考核。出发前核对申请对象、审批顺序、保险或安全要求、保密与成果归属，以及是否影响课程和研究节点。

申请写明起止日期、安排、任务影响、衔接办法和必要的联系渠道，通过指定受控渠道提交。敏感健康信息只提供给有权限的人员。实践开始前确定学习目标、指导人员、任务与考核材料；过程中保留真实记录，结束后提交总结与所需评价，完成学校认定后才记为相应培养环节完成。

### 先估算资源，再安排实验

申请服务器、模型接口、数据或会议经费前，说明用途、预计时长或调用量、费用上限、数据许可和完成后释放资源的方式。先做小规模验证，再扩大运行；实验记录资源占用与费用，发现预算偏离时及时停止扩张并沟通。共享设备按约定预约，长任务留下用途与结束条件，避免占用后无人知道如何处理。

经费使用和报销按单位流程办理，保留合规凭证。合作项目开始前确认数据可用范围、署名与知识产权；不能因为是实习或竞赛，就默认可以带出单位数据、代码或未公开成果。

### 反馈、健康与记录纠正

持续受阻、负担过重或身心状态影响学习时，尽早与导师、辅导员或学校支持部门沟通，商定任务调整与复查时间。对指导安排、考核或权益有疑问，可通过学院和学校公布的渠道咨询、反馈或申诉；具体程序以适用制度为准。评价应针对工作和证据，保护个人隐私。

AI 可以辅助汇总会议和周报，使用前确认材料允许进入所选工具。汇总后由本人核对事实、姓名、日期和决定，删除错误推断；涉及他人的决定应请相关人员确认。AI 生成的出勤或进度结论不能直接作为考核依据。发现记录错误时保留更正说明、时间和确认人，让后续使用者知道哪个版本有效。

## 学术规范与提交检查

学术规范要落实在选题、阅读、实现、实验和写作的每一步。提交前集中检查很必要，但不能替代平时的真实记录。本页将引用与查重、规范检查（查非）、AI 工具披露分开说明，帮助你逐项自查并形成可复核的修改记录。

[真实证据](https://csma-graduation-projects.github.io/integrity.html#integrity-evidence) [引用与查重](https://csma-graduation-projects.github.io/integrity.html#citation-check) [查非](https://csma-graduation-projects.github.io/integrity.html#format-check) [AI 使用](https://csma-graduation-projects.github.io/integrity.html#ai-disclosure) [匿名送审](https://csma-graduation-projects.github.io/integrity.html#anonymous-review) [整改与复核](https://csma-graduation-projects.github.io/integrity.html#integrity-remediation)

### 先确认材料真实、来源可查

论文中的每个关键结论，应能回到所依据的文献、数据、运行记录或分析过程。区分原作者报告的结果、自己实际复现的结果和仍待验证的推测；借用公开结果作比较时明确来源与条件。演示成功、一次运行完成和充分支持研究结论，是不同层次的证据。

实验记录至少包含代码版本、环境、数据版本与划分、配置、执行命令、时间、退出状态、日志和原始输出。保留失败、超时与异常结果，按事先说明的规则纳入或排除；不能为提高指标临时挑选有利样本而不报告。图表从保存的数据生成，记录处理脚本，核对单位、样本量、误差和图注是否准确。

使用第三方代码、模型、图片和数据时，核对来源、许可证、使用限制和引用要求；“可下载”不等于“可任意公开”。涉及人的调查、访谈、实验或个人信息数据，在招募或采集前判断是否需要伦理审查、知情同意与授权，按学校流程办理。不得在研究完成后用一份自查表冒充事前批准。

### 引用与查重：逐条理解，逐项处理

写作时就建立引用记录：结论来自哪里、原文位置、如何支持当前论述。直接引用标明引用关系；转述用自己的理解组织，并准确给出来源。参考文献要实际查阅和核实，避免引用不存在的题名、作者、年份或 DOI。不能把别人的观点、图表或代码只改几个词后当作自己的成果。

1. **确认规则与版本。**从当年正式通知确认检测平台、检测对象、提交内容、判定口径、修改与重检流程；没有确认的阈值不自行填写。
2. **完成内容与引用自查。**核对正文引文与文后条目是否对应，图表是否说明来源，合作工作和本人已有成果是否说明贡献与复用关系。
3. **使用指定渠道。**提交导师审阅后的完整稿，记录文件名、版本、日期及校验值。不要把未公开论文上传到来源不明的检测网站。
4. **逐项阅读报告。**定位相似片段，判断引用是否准确、表达是否不当、公共定义是否需要说明；修正问题本身，保留修改理由和位置。
5. **按规定复核。**需要重检或审核时走正式流程，保存报告与回执。相似性检测通过，不代表研究质量、署名或数据使用已经合格。

**不要以规避检测代替修改。**不得通过内容图像化、加入无关文字、故意替换字符或伪造引用来降低检测结果。本页不提供统一重复率，也不将检测数值直接等同于学术不端结论。

### 查非：检查非学术性错误

部分高校将错别字、格式、图表、编号、参考文献著录和排版等非学术性错误检查称为“查非”。它与查重是不同环节。本校是否设立正式查非、检查顺序、抽查办法和判定标准，须在[校本要求表](https://csma-graduation-projects.github.io/policies.html#local-check) 中确认；下面的自查方法适用于写作质量检查。

规范检查应对照最终导出的论文逐项完成

| 检查对象 | 具体操作 |
| --- | --- |
| 基本信息与结构 | 核对题目中英文、学位类型、摘要、关键词、目录、章节、声明和附录；采用学校当前模板。 |
| 文字与术语 | 检查错别字、残留占位符、重复段落、术语前后不一致和缩写首次解释。 |
| 图表与公式 | 检查清晰度、图题表题、单位、符号解释、编号、正文引用和跨页显示；核对图表数值与原始结果。 |
| 引用与编号 | 检查参考文献著录字段、引用顺序、页码、交叉引用和自动编号，清除“引用源未找到”等错误。 |
| 页面与导出 | 核对页眉页脚、页码、分页、空白页、字体、可搜索文字与书签；从头到尾查看导出 PDF。 |

检查记录写明页码或段落、问题类型、修改内容、复核结果与日期。修改后重新导出，检查受影响的目录、编号和分页，避免只修源文件而提交旧 PDF。正式提交前再次打开实际待上传文件，不能仅凭文件名判断版本。

### AI 工具使用：可说明、可核验、本人负责

先核对学校、课程、竞赛和投稿单位的适用规定。记录工具名称与版本、使用日期、用途、涉及的章节或代码范围，以及本人如何核验。语言润色、代码建议、资料整理与内容生成应如实区分；需要披露时使用规定位置和格式。任何辅助工具都不能替代本人完成应由本人完成的研究与论证。

逐条核验 AI 提供的文献、事实、公式、代码与数据解释；代码应阅读、测试并确认许可，不能因为能够运行就视为正确。生成示例不得伪装成真实实验记录或真实用户反馈。未公开论文、个人信息、评阅意见及受限数据，只有在工具与数据使用范围均获许可时才能输入。

如学校安排 AIGC 检测，登记政策版本、结果解释与复核渠道，按要求处理。本页不设置“AI 率”阈值，不提供规避检测方法，也不以单个检测分数自动判断违规。发生疑问时，保留写作版本、笔记、实验和修改过程供有权限的人员复核。

### 匿名送审：正文之外也要检查

先读取具体匿名要求，再从确认的论文版本生成送审稿。通常需要核对封面、致谢、作者与导师信息、在学成果、自引表述、项目说明、页眉页脚、附录、图片内文字、附件和文件名。匿名规则不等于删除必要的科学引用，按学校规定处理身份关联信息并保持学术准确。

检查 PDF 或文档属性中的作者、单位、批注、修订痕迹和隐藏内容；同时核对补充材料、演示视频、代码仓库链接、README、提交记录和访问页面是否暴露身份。若评阅要求提供代码，采用获准的匿名方式；不能为了匿名擅自破坏已有仓库历史或删除原始材料。无法兼顾复核需要和匿名要求时，请学院确认提供方式。

保留完整稿、送审稿及其对应关系，记录文件校验值和系统提交回执。冻结后如发现重要问题，先联系指定人员，依规则退回或更正；不能私自替换文件后仍声称是已审核的同一版本。

### 发现问题后，形成可复核的整改

先定位问题涉及的版本与范围，再区分排版错误、证据不足、引用失当或可能的规范问题。暂停有问题材料的进一步提交，保留原始记录，与导师和相应负责人员沟通。逐条写明原意见、处理方式、修改位置、证据和仍未解决的部分；没有采纳的意见说明理由，不能只回复“已修改”。

组内复核、正式查重查非、评阅和答辩分别记录结果。涉嫌学术不端的认定与处理，依学校制度和正式程序进行；对学术评价有异议，查询学校公布的复核渠道。个人意见、检测报告和评阅材料留在受控范围，不在公开主页展示。

沿用已有项目约定，不为统一外观强制搬动或重命名正在使用的仓库。若材料分布在多个获准系统中，用归档索引说明每部分的存放位置、访问条件、负责人和版本。公开索引不包含受控地址、账号或个人评价；需要权限的索引放在对应受控空间。

新项目可以参考下面的结构，按实际工作合并或删去不适用项。学校要求的正式文件仍保存在指定系统；目录清楚比目录数量多更重要。

阶段提交使用明确的日期和版本，避免“最终版2”“最后一次修改”等名称。论文的送审、答辩、修改后终稿分别保留，并标记正式提交状态；代码使用对应提交或发布版本。文件名一致不代表内容一致，重要交付同时保留校验值。

### 原始材料、工作材料与公开成果分开

材料的可见性与使用边界

| 材料层次 | 典型内容 | 处理方法 |
| --- | --- | --- |
| 受控原始材料 | 原始采集数据、授权记录、参与者信息、原始实验输出。 | 保留来源和原貌，限定访问；分析使用副本或派生数据，不覆盖原始记录。 |
| 受控工作材料 | 个人计划、周报、未公开论文、评阅意见、研究过程与内部交接记录。 | 按职责授权访问；明确当前有效版本和负责人，不放入公共网站。 |
| 经确认的公开成果 | 获准公开的论文、代码、示例数据、演示、空白模板和说明。 | 单独生成发布包，检查许可、隐私、署名和保密限制，确认后发布。 |

清洗或匿名化后的数据也要检查重新识别风险、授权条件和许可证，不能因为删掉姓名就默认可以公开。无法共享的数据可提供数据字典、申请流程、处理脚本及合成示例，明确示例只用于演示，不代表真实实验结果。

**页面不可见不等于资料私有。**公开 GitHub 仓库中的文件，即使不链接、被折叠或不进入网页构建，仍可能从仓库和历史访问。填写后的个人材料应保存在获准的受控空间。

### 每份关键材料至少说明这些信息

在交付清单中为材料分配稳定编号，记录名称、用途、格式、版本或日期、负责人、来源、对应任务或论文位置、存放位置、访问级别、许可条件和校验值。对不适用的字段说明原因，不使用空白掩盖未确认状态。

数据另记采集或下载时间、数据版本、字段含义、单位、样本量、清洗和排除规则、划分方法及生成脚本。运行记录另记代码版本、依赖、配置、数据版本、命令、资源、起止时间、退出状态和输出位置。图表注明输入数据与生成脚本，形成“论文结论—图表—结果—运行—代码与数据”的对应关系。

受许可限制不能随包交付的材料，登记限制、获准获取方式和负责联系的岗位，不交付个人账号凭据。资料来自合作单位时，确认研究组保留、后续使用和公开的范围；共同完成的代码和论文记录贡献与署名约定。

### README 要让接收者真正运行起来

1. **说明范围。**列出交付内容、论文或项目版本、已经验证的结果与已知限制，说明哪些功能需要外部账号或受限数据。
2. **说明环境。**给出操作系统、语言和关键依赖版本、硬件要求、安装命令及环境文件。模型或服务依赖注明版本和访问条件。
3. **说明数据。**给出合法获取方式、放置位置、预处理命令和数据校验，不要求接收者猜目录结构。
4. **给出最小运行。**提供一条可验证的起步命令、预期输出、预计时间和资源需求，再给完整实验入口。
5. **说明结果。**指出输出文件、指标计算与制图方法，列出可接受差异和随机性来源；不能重复的结果写明原因与复核方式。

交付前从干净目录按 README 操作。确实不能完整重跑时，保留运行日志、原始输出、分析脚本及限制说明，将“完整重跑”“保存记录复算”“只核查文件”分别标记，不把结构检查写成复现成功。

校验值用于发现文件是否改变。以下示例在归档目录内执行，实际文件列表应与交付清单一致：

```text
# macOS：生成与复核 SHA-256 清单
shasum -a 256 README.md thesis/final.pdf > SHA256SUMS
shasum -a 256 -c SHA256SUMS

# Linux 可使用同类命令
sha256sum README.md thesis/final.pdf > SHA256SUMS
sha256sum -c SHA256SUMS
```

文件修改后重新生成清单；校验通过仅表明与清单对应，不证明内容正确或来源真实。备份完成后抽取关键文件做恢复检查，确认能打开、能读取、权限有效；不要把同步成功当作已经完成恢复验证。

### 交接完成，以接收者验收为准

归档与交接的最少验收项目

| 验收项 | 应留下的凭证 |
| --- | --- |
| 正式材料 | 学校要求的终稿、声明、修改记录等已按规定提交，保留对应回执或状态。 |
| 完整与一致 | 交付清单逐项核对；论文版本、代码版本、数据与结果的对应关系清楚，关键文件校验一致。 |
| 可运行与可复查 | 接收者按说明运行样例或约定流程，记录命令、环境、结果和未完成项，注明验证范围。 |
| 权限与许可 | 接收者已取得所需访问权限，公开与保留范围明确，受限材料未误入公开包。 |
| 剩余事项 | 风险、后续维护责任、费用、到期事项和支持安排已记录，并有接收确认。 |

某项未通过时，登记问题、负责人、修复日期和复查方式；不能以“已压缩上传”直接关闭交接。校方归档与研究组交接的完成情况分别记录，最终由相应接收人员确认。

### 明确保留期限与离组后的访问

保留期限依据学校制度、资助项目、数据许可、伦理要求和合作协议确定，记录依据与到期处理责任人，不自行给所有材料统一设年限。到期不自动删除：先核对是否仍有保留义务、复查需求或其他限制，再按批准流程处理并留下记录。

离组交接通过组织所有权转移、成员权限调整、服务账号管理和密钥轮换完成，不交个人密码。检查代码仓库、存储、服务器、模型服务、域名或其他资源的负责人、账单和恢复方式；确认新负责人能访问后，依约撤销不再需要的权限。保留协作需要时，约定访问范围和期限。

### 每学年与每个毕业批次，先核对适用要求

国际学生还需核对本人项目的授课、论文、摘要和答辩语言，以及课程、语言能力、项目资格与行政手续。参阅[国际学生核对清单](https://csma-graduation-projects.github.io/international.html#checklist) 和[官方依据](https://csma-graduation-projects.github.io/international.html#sources) ，不能仅凭网页选择了英文就推定适用规则。

填写核对表的第一步，是明确学校与学院、专业、入学年级、学位类型、学习形式、计划毕业批次和培养方案版本。每条规则记录名称、发布单位、原文链接或正式系统位置、发布日期、生效日期、适用范围、具体要求、核验日期与核验人。无法确认时标为“待核验”，不能自行用相近专业或上一届标准填补。

校本要求确认表应覆盖的事项

| 事项 | 需要确认的问题 | 完成凭证 |
| --- | --- | --- |
| 课程与学分 | 必修、选修、成绩、补修、学术活动与其他培养环节的要求是什么？ | 适用培养方案与正式系统记录。 |
| 实践与安全 | 专业实践的时长、单位、指导、审批、考核及伦理或安全要求是什么？ | 获准计划、记录、评价与认定。 |
| 选题、开题与中期 | 资格、时间、材料、组织方式、变更和未通过处理如何办理？ | 正式表格、意见与完成状态。 |
| 成果要求 | 是否有适用成果要求？成果类型、作者贡献、署名、时间和录用/发表/授权状态如何认定？ | 有效规则与正式认定结果。 |
| 论文与预答辩 | 采用哪版写作规范？是否要求预答辩或其他前置审查？ | 模板版本、审核意见与确认。 |
| 查重、查非与 AI 使用 | 是否设相应环节？渠道、顺序、口径、披露、修改、复核要求是什么？ | 适用通知、提交版本与报告。 |
| 送审与答辩 | 匿名要求、截止时间、评阅周期、资格、修改与异议程序是什么？ | 送审回执、评阅意见和答辩记录。 |
| 学位申请与终稿 | 答辩后如何修改、复核、申请学位和提交终稿？ | 修改确认、申请与归档回执。 |
| 科研资料与离组 | 哪些材料交给谁？保留期限、访问、公开和后续维护如何安排？ | 交付清单、许可与接收确认。 |

将每项状态记为“待核验、已确认、已完成、不适用”，不适用也写明依据。规则不明不妨碍继续阅读、研究和准备工作，但涉及该规则的正式提交应先完成核验；主动联系学院教务或研究生管理人员，记录答复并获取正式依据，避免错过处理时间。

### 如何把制度转成可执行计划

从学校最终截止时间向前安排导师审阅、修改、检测、评阅和材料确认，预留返工时间。本站建议周期只是工作安排，不替代学校规定的最短间隔、固定批次或期限。学硕与专硕、不同年级、不同学习形式可能采用不同规则，不可只看文件标题相似就沿用。

新通知出现时，核对是否替代旧文件、是否仅适用于某一批次，并更新受影响的任务。来源之间有冲突时交由发布部门确认；保留旧版本与替代关系。以下高校案例用于理解真实流程，不代表本门户所属学校，也不向本站学生移植他校阈值。

## 国际学生指南

### 先确认适用要求，再进入培养流程

入组后，与导师和学院负责人员共同完成一次核对。以下流程可直接在页面阅读；每一步都留下对应记录，不能仅凭口头印象标记完成。

1. **确认培养方案**记录项目身份、入学年级、学位类型、适用文件版本及负责部门。
2. **确认语言与手续**分别核对课程、交流、材料和考核语言，并登记需要办理事项的官方联系人与日期。
3. **进入本硕博路径**选择对应学位阶段，标出已经完成、正在进行和下一项正式环节。
4. **约定任务与交付**写清本次任务、提交材料、完成条件、反馈方式及检查日期。
5. **参加正式考核并纠正**保留正式结论，未通过或待修改事项列出行动、责任人与复查安排。
6. **完成学位与离校归档**分别核对学位状态、最终材料、数据权限、资源交还与离校记录。

**遇到不清楚的要求，回到核对：**标记“待确认”，写明谁去咨询、向谁确认以及预计确认日期。缺少文件、语言许可或正式结论时，不能默认通过；不适用的事项写明理由和确认依据。

### 本科：先分清科研训练、毕业设计与竞赛

三类活动的目标与认定方式不同。科研训练可以帮助你学习研究方法，竞赛可以练习团队交付；能否计入课程、实践学分或毕业设计，由适用培养文件和负责部门确认。

- **科研训练：**核对参与条件、先修知识、指导安排与可使用的数据；从可完成的小问题开始，提交阅读记录、实验或实现记录及简短汇报。记录任务范围、个人贡献、反馈和下一次检查日期。
- **课程与学分：**确认课程选择、教学与考核语言、应修课程及学分认定方式；项目经历需要申请认定时，保存课程对应关系、申请材料与正式结果，不自行折算学分。
- **毕业设计：**提前核对选题、任务书、开题、检查、论文格式、摘要、评阅与答辩语言；保存批准题目、阶段材料、修改记录和正式考核结果。组内展示完成后，仍需完成学校规定的毕业设计环节。
- **竞赛：**报名前向组织方确认国际学生和所在年级的参赛资格、组队规则、提交语言、公开展示与成果使用范围；记录公告版本、资格确认、分工及提交回执。竞赛获奖不自动替代毕业要求。
- **结项与衔接：**整理可复现的代码或实验材料、说明文档和个人总结，区分公开作品与受限资料；记录课程认定、毕业设计或后续研究分别还缺什么。

### 硕士：把研究推进与正式培养环节对齐

先确认学术学位或专业学位、适用培养方案和实践安排，再建立个人时间表。相同的研究任务可能对应不同的正式材料；导师的指导意见与学院的审核结果应分别记录。

- **选题与综述：**围绕问题、已有工作、可获得数据和可完成范围形成选题说明；确认文献阅读、组会与书面反馈语言，保留文献表、问题依据及导师意见。
- **开题与中期：**从适用文件确认先决条件、材料格式、报告语言、时间安排和审核部门；提交报告、证据与计划，保存正式意见、修改回应和复查结论，不能把组内预演当作正式通过。
- **成果与实践：**逐项核对培养方案要求的研究成果、实践或学术活动，记录适用条款、认定口径、本人贡献、当前证据和缺项；不套用其他年级或学位类型的数量要求。
- **论文与学术规范检查：**确认正文、摘要、表格、附件的语言和格式；向负责部门核实“查非”的正式名称、对象与办理方式，并分别记录查重或其他学术规范检查的要求、报告和整改结果。不要把不同检查视作同一件事。
- **送审与答辩：**提前确认评审材料语言、匿名要求、送审资格、答辩语言及所需批准；保存提交版本、评审意见、逐项回应、答辩结论与最终修改记录。外文写作许可不等于外文答辩许可。
- **学位与归档：**核对学位申请状态、最终论文与附件、数据和代码使用权限；保存正式回执并完成交接，区分“答辩完成”“学位获授”和“离校办结”的状态。

### 把语言、资源与学业困难及时说清楚

#### 让反馈可理解、可执行

会前提交简短材料和具体问题；会后用双方理解的语言整理“决定、行动、负责人、日期”，请相关人员核对。听懂程度和口语流利程度不等于研究能力；需要书面反馈、额外解释或演示时，直接说明。

#### 统一术语，核对翻译

把开题、送审、学位授予等术语对应到学校正式名称、英文解释和实际材料。翻译或 AI 辅助文本由本人核对，正式文件含义不清时向发布部门确认；未公开研究和个人资料只能进入获准使用的工具。

#### 提前测试资源访问

用本人账号实际打开所需资源；无法使用时记录服务名称、错误现象和对任务的影响，向学校支持人员查询可用渠道或获准的替代方案。工具装在电脑上，不代表已有账号权限、许可或稳定服务。

#### 获得支持并提出复核

学习、健康、沟通或资源困难影响进度时，联系导师及学校公布的学业或学生支持部门，约定调整和复查日期。对记录、指导安排或考核有异议时，保存事实与材料，通过学校公布的反馈、复核或申诉渠道提出，并记录回执。只向必要人员提供个人信息。

支持安排应根据个人需要确认，不根据国籍推测语言能力、学习习惯或研究水平。把语言表达需要改进的部分与研究证据需要补充的部分分别说明，让下一步工作清楚可行。

## 科研工具指南

## 科研工具与任务方法

先按任务选一套能产出证据的最小组合，再按确实遇到的问题补工具。下列步骤是通用研究工作建议；软件功能、学校模板与服务条件请以适用版本和官方说明核对。

推荐组合是该任务的起步选择；可选替代用于已有习惯或特定需要；需另行准备表示应先核对环境、权限和预算。无需把目录中的软件全部安装。

### 文献调研与综述

从“读过若干论文”走到能比较问题、方法、证据和局限。

**初学者最小组合：**Zotero + Excel + VS Code

**操作步骤**

1. 先写研究问题、检索词、数据库、检索日期和纳入排除条件；用 Zotero 按主题收集条目，逐篇核对元数据与原文。
2. 给每篇核心文献写结构化阅读记录：问题、对象、方法、数据、评价、发现、局限；关键判断标明原文页码或章节。
3. 在 Excel 或 CSV 中建立综述矩阵，一行一篇文献；列出任务、数据规模、基线、指标、可复现材料、证据强弱和与本课题的关系。
4. 按“已知什么—证据有什么限制—还需验证什么”组织综述；写入 Word 时使用 Zotero 引文插件，LaTeX 路线导出 BibTeX / BibLaTeX 并检查引用键。

**交付格式**

- literature-matrix.xlsx 或 .csv：至少含来源标识、问题、方法、证据、局限。
- reading-notes.md、search-log.md；按需导出的 references.bib / .ris 和综述正文。

**完成核验**

- 抽查每项重要结论，能回到原论文具体位置；区分作者报告与自己的判断。
- 矩阵能解释不同研究为何可比或不可比；不是摘要粘贴集合。
- 新增一条引用后，正文与参考文献能一致更新；附件权限符合来源要求。

**替代与增加工具的条件**

- 只需简单矩阵时用 CSV + VS Code；阅读笔记已有固定习惯时可继续用 Obsidian 或 OneNote。
- 优先掌握 Zotero 原生导出与 Word 插件；需要自动维护 LaTeX 引用键时再评估第三方扩展，不将其视为必需。

**常见误用**

- 导入 PDF 不等于已核对文献；AI 生成的作者、DOI 或结论必须回原文验证。
- Markdown 适合记录与交换文字，不能把 .md 改后缀当作符合学校格式的 Word 文件。

配套模板：[论文阅读与复现判断](https://csma-graduation-projects.github.io/templates.html#reading)；[文献综述与证据矩阵](https://csma-graduation-projects.github.io/templates.html#literature)；[选题论证与范围界定](https://csma-graduation-projects.github.io/templates.html#topic)

功能依据：[Zotero：入门、条目与笔记](https://www.zotero.org/support/quick_start_guide)；[Zotero：Word 插件与引用更新](https://www.zotero.org/support/word_processor_plugin_usage)；[Zotero：书目与 BibTeX / RIS 导出](https://www.zotero.org/support/creating_bibliographies)

### 实证复现、算法实验与数据分析

让每张表、每条结论都有对应的输入、版本、运行记录和计算过程。

**初学者最小组合：**VS Code + Git + Python + venv

**操作步骤**

1. 先确定复现对象、数据许可、指标、基线与可接受差异；记录作者报告值，保留数据原件和获取说明。
2. 选择独立 Python 环境并在 VS Code 确认解释器；记录系统、Python、依赖、硬件、随机种子和完整命令。先跑小样例，再扩大规模。
3. 把清洗、划分、运行、评价与绘图写成明确步骤；为每次运行分配编号，保存配置、输入标识、退出状态、完整日志和原始输出。
4. 用脚本从保存的原始输出重算指标，报告重复运行差异、失败案例与限制；算法对比同时固定输入规模、资源条件与计时范围。
5. 在新的输出目录按 README 重跑一个最小实验；核对结论能否由该记录支持，不能把离线重算写成新一轮真实运行。

**交付格式**

- README.md、requirements.txt 或项目锁定文件、脚本、Git 提交号和环境记录。
- run-manifest.json、config.json、完整日志、原始结果 .jsonl / .csv、分析脚本与图表 .svg / .pdf。

**完成核验**

- 另一位同学能按命令定位输入并复跑最小样例；失败也有退出码与记录。
- 论文表格能从保存的原始结果计算得到，手工修改有明确追踪。
- 检查数据泄漏、划分重叠、评价口径、异常处理与统计方法是否适合研究问题。

**替代与增加工具的条件**

- 小规模初查可用 Excel；用于论文的重复计算应保留公式和参数，复杂或批量统计转为脚本。
- 只有论文明确依赖容器、特殊硬件或操作系统时再准备对应环境；Notebook 用于探索时，交付前清空输出并按顺序重跑。

**常见误用**

- pip freeze 只反映部分 Python 依赖信息，不等于系统、GPU、驱动、数据和模型环境已完整记录。
- 截图、进度条、安装成功和一个示例通过，都不能代替完整实验结果。

### LLM、Agent 与 RAG 研究

先验证任务与评价是否成立，再控制模型、数据、工具和费用开展实验。

**初学者最小组合：**VS Code + Git + Python + venv

**操作步骤**

1. 写清任务、数据范围、基线、成功与失败定义，区分模型回答质量、检索质量与端到端完成率；先建立可人工核对的小样本。
2. 使用已获授权的模型或服务，记录模型标识、版本或访问日期、提示词、参数、数据快照、工具配置和预算；先做少量真实调用验证。
3. RAG 先保存文档来源、切分规则、检索候选与引用位置，再评估回答；Agent 记录每步输入、工具调用、返回值、终止原因和实际环境状态。
4. 分别保存真实模型运行、离线回放、手工构造样例和失败记录；评测脚本检查原始轨迹，不能只看模型自评“已完成”。
5. 检查数据隔离、基线公平性、重复运行差异、成本与错误类型；无真实模型权限时仅交付明确标注的离线演示和待验证项。

**交付格式**

- 任务与评价规范、许可说明、数据划分标识、提示词和模型配置。
- 逐次请求 / 响应或脱敏轨迹 .jsonl、工具执行记录、费用与耗时表、评测代码和失败样例。

**完成核验**

- 能回答“这条结果是哪次真实执行产生的”，并定位到数据、代码与模型配置。
- RAG 引用能回到来源片段；Agent 的完成判断由实际任务状态或独立检查支持。
- 基线与新方法的资源和评价口径已说明，人工样例与真实数据结果明确分开。

**替代与增加工具的条件**

- 小型 RAG 起步可先用简单检索与文件索引验证评价，再决定是否需要向量数据库。
- AI 辅助工具可帮助解释和起草，但模型服务、GPU、Docker、框架与账号需要按任务另行准备和验证。

**常见误用**

- 有聊天软件或编辑器扩展，不等于有实验 API、GPU、模型权限或可公开的数据。
- 不得把缓存回放、手工填写轨迹或模拟响应描述成实时模型实验；也不要将未授权材料发给外部服务。

### 论文撰写、规范检查与送审

让主稿、引文、图表、修改说明和最终送审版本保持一致。

**初学者最小组合：**Word + Zotero 引文插件 + Zotero + draw.io

**操作步骤**

1. 先下载本人适用的学校模板并选定主稿格式：Word 路线使用样式与引文插件；学校允许且已有基础时，选 LaTeX + VS Code 作为主稿。
2. 按研究问题、方法、证据和局限组织章节；图表从真实结果生成，保存可编辑源文件，题注、单位、引用与正文一致。
3. 每轮修改保留版本和问题回复表；Word 使用修订与批注协作，LaTeX 使用 Git 差异与编译日志，统一维护同一份主稿。
4. 按学校要求检查格式、查重、非学术性差错与 AI 使用说明。匿名送审另存副本，检查封面、致谢、正文自引、文件名、属性、批注、修订、附件和链接。
5. 从最终副本导出 PDF 并逐页检查字体、公式、分页、交叉引用和匿名性；登记送审文件版本、日期与提交回执。

**交付格式**

- 主稿 .docx，或 .tex + .bib + 图表源文件；对应最终 .pdf。
- 修改回复表、格式与匿名核对表、适用制度依据、允许保留的检测报告和提交回执。

**完成核验**

- PDF 与所登记主稿一一对应，图表与原始结果一致，所有引文都能定位。
- Word 隐藏标记不代表删除修订；在送审副本中按要求处理修订与批注后重新检查。
- Word for Mac 没有 Windows 的 Document Inspector；应核对属性并人工检查正文、批注、修订和导出 PDF，不能仅凭某个按钮宣称已完全匿名。

**替代与增加工具的条件**

- Word 和 LaTeX 二选一作为主稿；需要格式转换时以转换后的全文重新验收，避免同时维护两套正文。
- Markdown 适合提纲和阅读笔记；转入学校 Word / LaTeX 模板后仍需完成排版核验。

**常见误用**

- 学校认可的检测系统与阈值以适用规定为准，不用通用 AI 或商业网站的分数替代。
- 不要在唯一主稿上删除引文域、批注或身份信息；保留受控原稿与送审副本。
