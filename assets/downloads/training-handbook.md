# CSMA 学生培养工作手册

更新：2026-10-18。通用工作指南；正式要求以本人适用的校院文件为准。

在线入口：https://csma-graduation-projects.github.io/

填写后的材料存入获准的受控空间；本手册不是校院审批记录。

## 本科科研训练

从可完成的小任务开始，学会提问、验证与表达。

参加科研训练、大学生创新项目或研究组项目的本科生，按基础与可用时间选择起点。；按能力与项目推进，约定周期与检查日期。

科研训练以能力进步和可核验证据为主，不承诺论文、获奖或升学结果；成果转入毕设前核对学校要求、个人贡献与复用范围。

### 01 了解方向与双向匹配

参考时机：正式领任务前

目标：说清楚为什么参加、能投入多少时间、需要哪些支持，确认适合自己的起点。

**进入条件**

- 已阅读研究组公开介绍，了解课程学习与科研训练的时间关系。
- 通过负责人确认的渠道沟通，不向公开仓库提交个人申请资料。

**操作步骤**

- 整理已学课程、完成过的作业或项目、感兴趣的问题；如实说明尚不熟悉的工具。
- 列出每周可用时段、考试和课程冲突，与指导者商定试学范围、反馈方式及调整渠道。
- 确认任务负责人、材料存放位置、可用设备和账号；了解引用、数据许可、保密与 AI 使用边界。
- 把讨论结果整理成入门清单，区分已经确认的安排和仍待核实的事项。

**交付材料**

- 个人基础与兴趣说明、可投入时间表。
- 入门清单与试学任务约定，含负责人和检查日期。

**验收标准**

- 学生能用自己的话解释试学目标和完成条件。
- 指导者确认任务难度与资源可承受，课程冲突已有安排。
- 双方知道出现阻塞、需要请假或希望退出时如何联系。

未达要求：基础或时间不匹配时，缩小任务或先补课程；保留讨论结论，约定复查日期，不以报名或进入群聊视为完成。

下一步：负责人确认试学任务后，进入工具与规范训练。

配套模板：入组与阶段计划（onboarding.md）、科研训练任务卡（research-task.md）

### 02 工具、文献与规范入门

参考时机：试学初期，按实际基础安排

目标：能独立运行一个小例子、记录过程，并正确说明资料与代码来源。

**进入条件**

- 已有明确的小练习、可用环境与检查日期。
- 知道哪些材料只能在受控空间保存。

**操作步骤**

- 配置开发环境，记录系统、依赖版本与启动命令；用最小样例检查安装是否成功。
- 练习 Git 提交、分支、差异查看和恢复；提交前检查密钥、个人信息与无关大文件。
- 检索代表性文献，区分原论文、教程与二手总结，制作一份包含问题、方法、证据和局限的阅读记录。
- 完成小练习和必要测试；使用 AI 辅助时保留用途说明，并亲自运行、核对来源和解释关键代码。

**交付材料**

- 可运行练习、环境说明和实际测试记录。
- 阅读记录与来源清单。
- 提交历史及已发现问题的修复说明。

**验收标准**

- 按说明可重新运行，失败信息没有被省略。
- 学生能解释输入、处理、输出，以及引用和复用部分。
- 不把工具安装完成、截图或 AI 输出当作任务已验证。

未达要求：运行失败则缩减到最小示例并记录报错；关键概念解释不清则补练后复查，不直接进入复杂项目。

下一步：基础练习通过复查后，领取一个边界清楚的研究小任务。

配套模板：入组与阶段计划（onboarding.md）、论文阅读与复现判断（reading.md）、实验、复现与运行证据（experiment.md）、AI 辅助使用与披露记录（ai-use.md）

### 03 阅读、复现与小任务验证

参考时机：正式立项前

目标：通过有限规模的真实操作，判断候选问题是否值得继续、自己是否理解任务。

**进入条件**

- 基础练习可运行，任务负责人已指定公开材料或合法可用的数据。
- 任务有明确输入、输出、预算和停止条件。

**操作步骤**

- 把宽泛方向改写成一个问题，例如某方法在何种输入下失败，以及如何观察这种失败。
- 阅读相关工作并完成复现、错误分析、数据整理或模块修复，记录原方法和自己的改动。
- 事先写出观察指标和比较方式；区分作者报告值、本地重跑值、离线分析和未验证推测。
- 整理成功与失败样例，说明已有证据能支持什么、不能支持什么，并提出下一步选择。

**交付材料**

- 研究任务单与阅读比较表。
- 可复查的代码、配置、日志和样例。
- 小任务总结：结论、局限、未解决问题与建议。

**验收标准**

- 任务结果可以追溯到具体输入、版本和运行记录。
- 学生能解释差异来源，不用一两个样例宣称普遍有效。
- 指导者确认继续研究的价值、范围与资源条件。

未达要求：无法复现时先核对依赖、数据和评价口径；价值不足则如实结束或换题，失败记录仍纳入总结。

下一步：形成有证据的继续或调整决定后，再确定项目范围。

配套模板：科研训练任务卡（research-task.md）、文献综述与证据矩阵（literature.md）、实验、复现与运行证据（experiment.md）

### 04 项目立项与任务拆分

参考时机：小任务验收后、持续投入前

目标：把研究想法变成有负责人、有截止日期、能逐项验收的计划。

**进入条件**

- 已有初步可行性证据，并确认项目适合当前能力。
- 如涉及正式创新项目申报，已获取当年度通知。

**操作步骤**

- 写清真实场景、目标用户或研究对象、核心问题、范围之外的内容和预期产物。
- 把工作拆成调研、数据、实现、验证、写作等任务，每项写负责人、依赖、期限和验收证据。
- 核对算力、设备、经费与数据许可；涉及人员研究或敏感资料时，先确认必要审批再收集使用。
- 约定周期汇报、协作贡献、署名讨论与任务变更方式；正式申报按指定系统提交并留存回执。

**交付材料**

- 项目说明与里程碑计划。
- 任务清单、资源预算和风险清单。
- 适用时的申报材料、审批记录与提交回执。

**验收标准**

- 每个里程碑都有可观察的产物，而非仅写“学习”“优化”。
- 范围、资源、授权和分工能支撑计划。
- 团队成员清楚个人责任，正式申报状态有凭据。

未达要求：缺资源或依赖未落实时先缩小范围；申报未通过不冒称已立项，按反馈修订并明确后续是否作为训练项目。

下一步：计划和必要审批确认后，按里程碑推进实现与研究。

配套模板：开题方案与评审准备（proposal.md）、科研训练任务卡（research-task.md）、课题、计划与资源变更（change-request.md）

### 05 实施、周报与阶段复核

参考时机：项目进行期间，频率按约定执行

目标：持续交付可检查的进展，让阻塞和风险尽早被发现。

**进入条件**

- 任务、存储位置、负责人和反馈节奏已确认。
- 本轮待办有优先级与验收条件。

**操作步骤**

- 按小步提交推进代码、实验或分析，每次记录改动、运行条件与实际结果。
- 周期总结已完成事项、证据链接、未完成原因、所需帮助和下周期计划，不以在线时长替代产出。
- 讨论前准备具体问题和已尝试方案，讨论后记录决定、负责人及期限；关键口头决定补入正式记录。
- 遇到数据变化、算力不足或连续失败时提交变更说明，调整范围与时间，不默默拖延或只展示好结果。

**交付材料**

- 版本化产物、配置与实验/测试日志。
- 周期报告、会议行动项及更新后的任务状态。
- 阶段演示或复查记录、适用时的变更单。

**验收标准**

- 报告中的进展与实际文件、提交和运行记录一致。
- 阻塞已分派处理，反馈有落实证据。
- 阶段产物可运行或复核，课程、健康等实际冲突得到合理调整。

未达要求：未达成里程碑时列出差距和原因，缩减下一轮任务并约定复查；长期无法投入则明确暂停或交接。

下一步：核心任务达到约定条件后，进入独立复查和成果表达。

配套模板：周报与下一阶段计划（weekly.md）、会议、讨论与决策记录（meeting.md）、实验、复现与运行证据（experiment.md）、课题、计划与资源变更（change-request.md）

### 06 结果复核与成果表达

参考时机：结项、投稿、参赛或公开前

目标：让结论、代码和说明互相对应，形成别人能够理解和检查的成果。

**进入条件**

- 核心产物已经形成，原始记录可追溯。
- 已明确拟交付的是报告、软件、演示、论文还是其他成果。

**操作步骤**

- 从干净环境或由另一位成员按说明复查，核对数据处理、指标计算、失败样例和限制。
- 围绕问题、方法、证据和局限写报告；图表标明来源、单位与对应版本，引用回到原始资料。
- 列出个人贡献、复用内容、合作支持和 AI 辅助用途，确认署名与许可，不把他人工作写成自己的。
- 按拟投稿或参赛渠道核对格式、知识产权、公开范围和提交条件，经确认后再提交。

**交付材料**

- 技术报告或成果稿件、复查记录与复现说明。
- 贡献与引用清单、授权和公开检查结果。
- 适用时的正式提交回执与成果状态记录。

**验收标准**

- 主要结论有直接证据，局限与负面结果被如实说明。
- 第三方能定位产物并理解复查方式。
- 投稿、录用、发表、授权和获奖分别记录，不混用状态。

未达要求：复查失败则定位差异、补证据并同步修改结论；授权不清的材料暂不公开，先取得许可或更换。

下一步：成果通过复查后，办理结项、资料归档和后续交接。

配套模板：学位论文写作与版本检查（thesis.md）、成果要求核对与成果台账（outcomes.md）、学术规范、查非与查重（integrity.md）、AI 辅助使用与披露记录（ai-use.md）

### 07 结项、归档与后续发展

参考时机：项目结束、转入毕设或退出前

目标：留下完整过程和可接续的成果，明确已经完成与仍需承担的责任。

**进入条件**

- 成果和遗留问题已整理；正式项目的结项要求已核实。
- 有确定的接收人或材料保管位置。

**操作步骤**

- 按清单整理任务、报告、代码、数据来源、环境、运行记录与授权信息，建立版本索引和备份。
- 让接收人检查关键文件并实际恢复或运行；记录缺项、修复结果及访问权限。
- 办理项目结项、设备归还和未结经费事项；通过平台正规流程移交组织资源所有权与访问权限，不移交个人账号密码。
- 总结能力进步与不足，商定后续学习或毕设衔接；作品集只选经授权、能说明本人贡献的内容。

**交付材料**

- 归档索引、最终版本和备份校验记录。
- 交接清单、遗留事项与责任人。
- 能力总结及适用时的结项确认。

**验收标准**

- 接收人可以定位、打开并复查核心材料。
- 设备、经费、账号与未完任务均有处理记录。
- 个人隐私和未公开成果未随公开展示泄露。

未达要求：发现缺档或无法恢复时先补齐并重新交接；不能补回的内容注明原因和影响，不把不完整包标成验收完成。

下一步：完成结项后再进入新项目；转为毕设须重新核对任务和学位环节要求。

配套模板：数据、代码与毕业材料归档（archive.md）、阶段移交与离组交接（handover.md）、成果要求核对与成果台账（outcomes.md）

## 本科毕业设计

连起题目、实现、论文与答辩，明确每阶段的交付物。

开展毕业设计或论文的本科生，按工程、实验或理论题目选择证据。；从学院发布当年度安排开始倒排，正式日期、格式和资格以适用专业通知为准。

毕业设计须体现本人综合训练。复用科研、竞赛或实习材料前，核对题目、个人贡献、授权及学校要求，仍须完成毕业设计环节。

### 01 核对要求、选题与任务书

参考时机：学院选题与任务下达窗口内

目标：拿到正式认可、范围适当且资源可获得的题目。

**进入条件**

- 已获取本专业当年毕业设计通知、模板和系统入口。
- 已了解学分、选题资格和指导安排的适用要求。

**操作步骤**

- 建立日期清单，登记选题、开题、中期、论文检查、答辩和归档窗口及通知来源。
- 比较候选题目的问题、已有基础、个人贡献、技术风险和工作量，先验证关键资源是否可用。
- 与导师确认必须完成、可选扩展和明确不做的内容，为每项核心目标写验收证据。
- 按学校流程确定题目与任务书，核对题名、导师、学生信息和成果要求，留存提交确认。

**交付材料**

- 校本要求核对表与时间计划。
- 选题比较、确定的题目及任务书。
- 核心范围、验收条件与资源风险清单。

**验收标准**

- 题目与专业培养要求相符，学生能说明本人承担的工作。
- 任务书与正式系统信息一致。
- 范围可在实际期限内完成，关键依赖有解决方案。

未达要求：题目过大则删去非核心功能；资源不落实则换方案；题目需变更时先办理规定手续，避免论文和系统登记不一致。

下一步：选题与任务书确认后，开展针对性调研并准备开题。

配套模板：入组与阶段计划（onboarding.md）、选题论证与范围界定（topic.md）、本科毕设任务书底稿（bachelor-task.md）、课题、计划与资源变更（change-request.md）

### 02 文献调研与开题

参考时机：正式开题前，留出修改时间

目标：讲清楚为什么做、已有工作做到哪里、自己准备怎样完成和验证。

**进入条件**

- 题目、任务书与范围已确认。
- 已取得适用开题模板和评审安排。

**操作步骤**

- 围绕题目检索文献与现有系统，记录检索词、来源和筛选依据，比较方法与不足。
- 把背景动机转换为需求或研究问题，区分已有技术、计划复用内容和本人拟完成部分。
- 说明技术路线、数据来源、评价或测试方法、计划安排与风险预案，先做关键技术小验证。
- 准备开题报告与汇报，按意见逐条修改；正式提交后保存版本、意见和通过或整改记录。

**交付材料**

- 文献比较表、引用清单和关键技术验证记录。
- 开题报告、汇报材料及阶段计划。
- 开题意见与修改对应表、正式处理结果。

**验收标准**

- 文献结论来自实际阅读，不是仅堆引用数量。
- 问题、方案与验证方法能够对应。
- 正式开题结果可核实，整改事项已安排负责人和期限。

未达要求：开题未通过则按意见重定问题或路线，并遵循学校重审安排；不可仅更换表述而保留不可行方案。

下一步：正式开题及必要整改完成后，细化需求和设计。

配套模板：文献综述与证据矩阵（literature.md）、论文阅读与复现判断（reading.md）、开题方案与评审准备（proposal.md）、送审准备与意见逐条回复（review-response.md）

### 03 需求分析与详细设计

参考时机：大规模实现之前

目标：把方案细化到可实现、可测试、可说明的结构。

**进入条件**

- 开题方案已确认，遗留问题有处理结论。
- 实现环境、数据和主要约束已明确。

**操作步骤**

- 工程题列出用户场景、功能、异常与质量要求；研究题明确假设、变量、基线、指标与实验条件。
- 绘制模块、数据流或研究流程，定义接口、输入输出、数据字典和关键算法。
- 为核心需求建立测试或验证对应表，覆盖正常、边界、错误和资源受限情况。
- 评估隐私、数据许可、安全和可维护性；用小原型验证高风险部分，再确认设计版本。

**交付材料**

- 需求或研究问题说明、范围与验收表。
- 总体及详细设计、接口或实验设计文档。
- 高风险原型结果和测试/验证计划。

**验收标准**

- 核心需求可测量，设计能解释如何满足需求。
- 数据来源、异常处理与关键依赖明确。
- 导师能据设计判断工作量及主要风险。

未达要求：设计无法支撑验收条件时回到需求澄清；关键技术验证失败则更换方案并记录影响，必要时办理变更。

下一步：设计基线确认后，分模块实现并准备中期证据。

配套模板：需求、详细设计与测试报告（engineering-report.md）、实验、复现与运行证据（experiment.md）、课题、计划与资源变更（change-request.md）

### 04 实现推进与中期检查

参考时机：设计确认后至学院中期窗口

目标：形成可演示的核心进展，并据真实差距调整后半程计划。

**进入条件**

- 设计与本轮任务清单明确，版本管理可用。
- 中期检查的材料、时间和提交方式已核实。

**操作步骤**

- 按模块实现并及时测试，保留提交、环境和运行记录；定期演示核心路径，减少末期集成风险。
- 持续写需求、设计和方法章节草稿，记录与原设计不同的决定及理由。
- 对照任务书列出已完成、进行中、尚未开始的事项，用代码、测试或分析结果支撑进度。
- 准备中期报告和演示，说明主要问题、剩余工作和调整计划；把检查意见转成行动项。

**交付材料**

- 阶段版本、运行说明和核心演示。
- 中期报告、进度证据与论文提纲/草稿。
- 检查意见、整改表和后续里程碑。

**验收标准**

- 关键流程确实运行，截图与展示对应当前版本。
- 中期材料如实区分完成和计划，未完成项有可行安排。
- 正式检查结果及后续要求已记录。

未达要求：核心路径未完成时优先补齐最小闭环，暂停非必要扩展；中期需整改或重查的，按正式要求提交复查证据。

下一步：中期问题处理后，完成系统或研究成果并进行全面验证。

配套模板：周报与下一阶段计划（weekly.md）、会议、讨论与决策记录（meeting.md）、中期检查与差距整改（midterm.md）、课题、计划与资源变更（change-request.md）

### 05 测试、实验与结果分析

参考时机：核心实现完成后、结论定稿前

目标：用充分且可复核的证据回答任务书中的目标是否达到。

**进入条件**

- 待验证版本已标记，环境和数据可定位。
- 测试用例或实验方案已有明确预期。

**操作步骤**

- 按需求对应表执行功能、边界、异常及适用的性能和安全检查，记录实际结果与缺陷。
- 研究题核对数据划分、对照设置、指标实现和重复运行条件，避免测试信息进入方法调试。
- 修复影响核心目标的问题并回归验证；无法解决的限制须说明触发条件与影响范围。
- 从原始记录生成图表，解释结果、失败案例和适用边界，区分自测、他人复核与尚未验证。

**交付材料**

- 测试/实验方案、原始记录与结果汇总。
- 缺陷与修复清单、回归结果。
- 需求—证据对应表及结果分析。

**验收标准**

- 每个核心目标有相应证据，没有只展示成功界面的空白。
- 结果与版本、输入和运行条件能对应。
- 结论没有超出测试范围，复核人可按说明检查。

未达要求：关键测试失败则修复并复测；证据不足时补实验或收窄结论，不能通过删去失败记录宣称完成。

下一步：核心验收条件达成后，完成论文与正式检查准备。

配套模板：需求、详细设计与测试报告（engineering-report.md）、实验、复现与运行证据（experiment.md）、学术规范、查非与查重（integrity.md）

### 06 论文撰写与规范检查

参考时机：写作贯穿全过程，检查前形成完整稿

目标：让论文准确呈现本人工作，满足适用的格式与学术规范要求。

**进入条件**

- 主要实现或研究结果已完成，论证所需证据齐备。
- 已取得学院最新论文模板与检查通知。

**操作步骤**

- 按问题、相关工作、设计方法、实现验证和结论组织全文，明确个人工作与复用部分。
- 逐条核对文字、图表、公式、引用和附件；任何数值都能追溯到实际记录，AI 辅助内容由本人审核。
- 按要求完成导师审阅、格式检查、相似性检测及其他适用检查，记录送检版本和正式报告。
- 逐项处理意见并复核修改，确认论文题名、系统登记、提交文件和演示版本一致。

**交付材料**

- 完整论文稿、引用资料与图表来源记录。
- 规范自查表、适用的检测报告与 AI 使用说明。
- 修改对应表、拟提交版本与确认记录。

**验收标准**

- 学生能够解释全文方法和结果，论文对应本人实际工作。
- 格式和学术规范检查按学校口径完成，不自设通过阈值。
- 查重结果、AI 检测与学术诚信判断不混为同一结论。

未达要求：发现无来源表述或错误引用则回到原始材料修正；未达到正式检查要求时按规定整改、复检或调整答辩安排。

下一步：规定的审阅与检查完成、答辩资格获确认后，准备正式答辩。

配套模板：学位论文写作与版本检查（thesis.md）、学术规范、查非与查重（integrity.md）、AI 辅助使用与披露记录（ai-use.md）、送审准备与意见逐条回复（review-response.md）

### 07 答辩准备、演示与回应

参考时机：资格确认后，按答辩通知执行

目标：在规定时间内说明问题、个人工作、结果与不足，并准确回应提问。

**进入条件**

- 答辩资格、场次、时间和提交材料已正式确认。
- 论文、演示程序与汇报内容使用一致版本。

**操作步骤**

- 按规定时长制作汇报，突出本人完成的关键工作、验证结果和限制，避免把背景占满篇幅。
- 准备可重复的演示流程、输入样例及离线备选；备选视频或截图明确标为预录材料。
- 进行计时演练，核对设备、字体和网络依赖，练习对来源、设计取舍与失败案例的解释。
- 答辩时如实回答，不确定的问题记录待核；完整记录评委意见及官方结论。

**交付材料**

- 答辩稿、演示包和演练检查记录。
- 评委问题与回应、正式答辩结果。
- 答辩后修改清单和完成期限。

**验收标准**

- 汇报、论文与系统表现一致，个人贡献清楚。
- 材料与现场安排满足正式通知。
- 学生已理解通过、修改后通过或其他处理结论的后续要求。

未达要求：演示失败时如实说明并使用已标识的备选材料；正式答辩未通过则按学校规定整改和申请后续安排。

下一步：按答辩结论完成修改与确认，再提交最终材料。

配套模板：答辩准备与修改验收（defense.md）、送审准备与意见逐条回复（review-response.md）

参考时机：答辩后至学院归档截止日期

**进入条件**

- 已收到答辩结论与修改要求。
- 归档清单、提交平台、命名及签字要求已核实。

**操作步骤**

- 逐条完成修改并请相应人员确认，生成最终论文与修改说明，避免只改演示稿。

**交付材料**

**验收标准**

未达要求：发现提交版本错误立即联系指定负责人员按流程更正；缺项或无法运行的归档包补齐后重新确认接收。

下一步：归档接收后跟进正式学籍与学位手续，保留后续联系渠道。

### 01 选赛、资格与规则核验

参考时机：报名和购买设备之前

目标：确认这项赛事值得参加、能够报名，且投入与培养目标相符。

**进入条件**

- 已取得主办方当届正式通知与规则。
- 已了解学校报名、认定或推荐流程的适用要求。

**操作步骤**

- 核实主办方、赛道、年级/学籍资格、队伍人数、跨校限制、指导教师要求和赛程。
- 逐项提取作品形态、评分依据、原创性、重复参赛、公开数据与 AI 工具限制。
- 评估比赛收益、课程冲突、费用、设备和算力投入，比较是否有更适合的任务或赛事。
- 把含糊条款向官方渠道核实并保存答复；涉及校内推荐、盖章或报名审批的，先办理对应手续。

**交付材料**

- 资格自查、赛程计划和初步预算。
- 参赛决定及适用的校内审批记录。

**验收标准**

- 资格逐项符合，未把往届规则当作当届依据。
- 核心评分要求与限制已转换为任务条件。
- 费用和时间可承受，正式报名渠道明确。

未达要求：资格不符则换赛道或停止报名；规则尚不明确的高风险事项在官方答复前不作不可逆投入。

下一步：规则与参赛决定确认后，组队并明确责任。

**交付材料**

- 作品任务书、评分对应表和里程碑。
- 资源来源、权属与授权清单。

**验收标准**

### 04 作品实现、复现与内部验收

参考时机：正式提交前，预留修复窗口

目标：让作品在规定环境中稳定运行，并能说明每项成绩或性能的来源。

**进入条件**

- 作品需求与评分对应表已冻结为本轮基线。
- 团队有可用的版本管理和测试环境。

**操作步骤**

- 按评分项实现并维护任务状态，记录成员贡献、版本和变更，定期集成而非临近截止才合并。
- 在规定设备或运行条件下测试正常、边界和故障场景，核对禁止联网、外部服务或数据使用等限制。
- 由未负责该模块的成员按说明复现，检查依赖、许可证、数据路径、运行时间和演示可靠性。
- 完成说明书、海报、视频或答辩稿，标明原型功能与计划功能，逐项验收后冻结提交候选版。

**交付材料**

- 可运行作品、依赖与操作说明。
- 测试/复现记录、缺陷清单与贡献记录。
- 提交候选材料及内部验收表。

**验收标准**

- 评分项与证据可对应，没有未实现却宣称完成的功能。
- 作品可在约定环境复现，失败和限制已说明。
- 代码、数据、视频与说明书版本一致，AI 使用符合当届要求。

未达要求：关键缺陷未修复则删减不可靠功能并同步修改说明；不能满足赛规的组件替换后重测，禁止隐瞒依赖。

下一步：内部验收通过并取得提交确认后，正式上传和参赛。

配套模板：实验、复现与运行证据（experiment.md）、学术规范、查非与查重（integrity.md）、AI 辅助使用与披露记录（ai-use.md）、竞赛立项、备赛与复盘（competition.md）

### 05 正式提交、现场比赛与结果确认

参考时机：按官方截止时间、时区与场次执行

目标：提交正确版本、保留有效凭证，并按规则完成展示和申诉。

**进入条件**

- 提交候选版已验收，所有必要成员或指导者已确认。
- 已核实文件大小、命名、格式、上传次数和最终截止时间。

**操作步骤**

- 检查包内文件、敏感信息、授权声明和成员信息，记录最终版本与校验值，预留上传失败的处理时间。
- 完成上传后重新下载或预览核对内容，保存提交编号、时间、回执及平台显示状态。
- 现场按要求完成展示，记录版本和评审问题；突发故障如实说明，不以剪辑材料冒充实时运行。
- 以官方通知确认晋级、奖项和证书信息；结果疑义按规定期限、渠道和证据要求提出复核。

**交付材料**

- 最终提交包、版本记录与提交回执。
- 现场材料、问题记录及适用的补正记录。
- 官方成绩或证书、适用的复核结论。

**验收标准**

- 提交状态可核实，材料未误传旧版或空文件。
- 展示符合规则，团队知道后续通知和补正窗口。
- 获奖名称、级别、成员与官方记录一致，不根据预测或截图猜测认定。

未达要求：上传失败立即按官方应急渠道处理并保留证据；争议按正式流程申请，不擅改成绩、证书或对外宣传。

下一步：官方结果或本轮赛程结束后，进行复盘、结算与归档。

配套模板：竞赛立项、备赛与复盘（competition.md）、答辩准备与修改验收（defense.md）、成果要求核对与成果台账（outcomes.md）、送审准备与意见逐条回复（review-response.md）

### 06 复盘、经费结算与成果归档

参考时机：赛事结束或决定退出后

目标：将参赛经验转化为可继续学习和使用的资产，完成团队责任。

**进入条件**

- 本轮提交、成绩和费用记录已收集。
- 学校成果认定与报销的适用程序已核实。

**操作步骤**

- 对照目标、评分和实际结果分析做得好与失误之处，区分技术、组织、展示和规则理解问题。
- 核对票据、费用分担、设备与借用资源，按要求报销结算，不能用估算替代真实凭证。
- 归档作品、报告、规则版本、提交回执、成绩证据与个人贡献，安排维护或停止运行。
- 确认后续开源、专利、论文或毕设复用的规则与授权；对外展示使用官方状态和获准材料。

**交付材料**

- 复盘报告、后续行动与个人贡献说明。
- 归档索引、最终作品与正式成绩证据。
- 费用结算、设备归还和项目交接记录。

**验收标准**

- 团队能复用经验，关键问题已有具体改进措施。
- 经费、设备、账号和未完事项均有去向。
- 成果认定按学校正式结果登记，公开范围与知识产权已确认。

未达要求：缺票据、缺授权或成绩待确认时标记待办并落实负责人；不为结项补造证明，不把参赛自动写成获奖。

下一步：完成交接后再确定延续方向；转论文或毕设需要重新立项和核对要求。

配套模板：竞赛立项、备赛与复盘（competition.md）、数据、代码与毕业材料归档（archive.md）、阶段移交与离组交接（handover.md）、成果要求核对与成果台账（outcomes.md）

## 硕士培养与学位全流程

从选题到学位手续，逐项落实研究、审查与交接。

学硕、专硕及不同学制、学习方式的研究生，均应使用本人适用的培养方案。；按个人培养方案和年度通知倒排；研究与写作可并行，正式环节遵守学校先后条件。

学硕着重学术研究能力，专硕还须对应专业实践与应用要求，具体成果形式和标准以所属学科或专业学位类别规定为准。本页不替学校设定成果数量、级别、检测比例或截止日期。

### 01 入学、培养计划与日常管理约定

参考时机：入学后按培养方案要求完成；每学期复核

目标：明确培养类型、必修环节、沟通责任与资料管理方式，建立可持续的研究节奏。

**进入条件**

- 已确认学位类别、专业方向、学制及导师安排。
- 已取得本人适用的培养方案和学院通知入口。

**操作步骤**

- 列出课程学分、实践、学术活动、年度考核、开题与学位环节，登记适用文件、版本和待核实条款。
- 制定个人培养计划；专硕核对实践基地、实践周期、校内外指导及考核要求，学硕核对学科训练要求。
- 约定周报、组会、邮件与任务系统的用途、反馈频率和求助方式；请假、出差、考勤按已生效制度处理。
- 建立个人研究目录、版本管理、备份和权限，完成诚信、伦理与安全学习；遇到健康或重大困难及时说明并商定调整。

**交付材料**

- 个人培养计划与校本要求核对表。
- 学期计划、能力补足清单与沟通约定。
- 资料目录、备份方案和适用的培训记录。

**验收标准**

- 正式计划已按要求确认，必修环节和负责人清楚。
- 学生主导任务推进，导师的指导与反馈责任明确。
- 缺少打卡或报告先核实，可补充更正；自动汇总不能直接作为违纪结论。

未达要求：发现学分、实践或时间冲突时及时咨询教务并修订计划；未确认的条款标为待核，不自行套用他人的培养条件。

下一步：培养计划和工作方式明确后，围绕方向提出候选问题。

配套模板：入组与阶段计划（onboarding.md）、专业实践计划与总结（professional-practice.md）、周报与下一阶段计划（weekly.md）、会议、讨论与决策记录（meeting.md）、校本要求核对与年度培养记录（annual-check.md）

### 02 方向探索与研究选题

参考时机：开题前，完成必要试验后确定

目标：选择有真实依据、个人贡献清楚、能在资源和期限内完成的问题。

**进入条件**

- 已了解方向基础、现有项目和可用资源。
- 能获取代表性文献及合法的初步验证材料。

**操作步骤**

- 从实际问题、已有研究限制或专业实践需求提出候选选题，说明问题出现的场景和证据。
- 比较研究价值、新颖性、相关方法、可验证性、资源和风险；区分真实观察与为说明问题构造的示例。
- 完成小规模基线复现或可行性试验，明确成功、失败和停止条件，避免只凭设想认定可行。
- 与导师讨论主问题、子问题和贡献边界；专硕同时核对实践对象、应用产物及合作单位使用授权。

**交付材料**

- 候选选题比较与选题说明。
- 初步复现/试验记录和资源风险表。
- 问题边界、预期贡献与继续或调整决定。

**验收标准**

- 问题确实存在或具有可检验假设，价值有来源支持。
- 个人工作与团队已有成果可区分。
- 数据、设备、经费和周期可支持最低可行研究。

未达要求：没有真实证据或关键资源不可得时缩题、换方法或换题；保留否定结果，重新讨论后再投入大规模实验。

下一步：候选问题具备可行依据后，通过系统综述完善定位。

配套模板：选题论证与范围界定（topic.md）、科研训练任务卡（research-task.md）、实验、复现与运行证据（experiment.md）

### 03 文献综述与研究定位

参考时机：开题前形成初稿，研究期间持续更新

目标：从可追溯的检索与比较中识别已有结论、争议和本研究切入点。

**进入条件**

- 已有候选问题和检索范围。
- 可访问相关数据库、论文及必要的原始资料。

**操作步骤**

- 设定关键词、同义词、时间范围、数据库和纳入排除标准，保存检索日期与筛选记录。
- 精读核心工作，按问题、假设、方法、数据、评价、结果和局限建立比较矩阵，回溯关键原始文献。
- 核对论文与代码、数据或后续修订的关系；未运行过的工作明确写为文献报告，不混写成本地复现。
- 按问题和方法脉络撰写综述，说明证据冲突、未覆盖条件及本研究如何补充，而非逐篇摘要拼接。

**交付材料**

- 检索记录、文献库与筛选说明。
- 核心阅读记录、比较矩阵和问题地图。
- 综述稿、研究定位及待补证据清单。

**验收标准**

- 代表性方法与相反证据均被考虑，引用能找到原文。
- “尚未研究”等判断有检索边界，不作无依据的绝对表述。
- 研究定位能解释与最接近工作的区别及验证方式。

未达要求：核心相关工作遗漏时补检索并重写定位；发现已有工作已解决主问题时调整问题，不能仅换术语制造创新。

下一步：问题、相关工作和可行性形成一致依据后，准备正式开题。

配套模板：文献综述与证据矩阵（literature.md）、论文阅读与复现判断（reading.md）、选题论证与范围界定（topic.md）

### 04 研究方案与正式开题

参考时机：学校规定的开题窗口内

目标：形成可执行研究方案，并获得正式开题环节的处理结论。

**进入条件**

- 选题、综述和初步可行性材料已形成。
- 已核对开题资格、时间、评审形式及提交模板。

**操作步骤**

- 把主问题拆成可检验子问题，为每项安排方法、基线、数据、指标和预期证据。
- 编制计划、算力与经费预算、伦理与数据许可安排，以及失败、延期和改题的备选方案。
- 按学位类型说明研究或实践产物与能力目标，准备报告、汇报及必要的前期成果证明。
- 按指定流程提交并参加开题，记录评审意见、结论和修改期限，完成逐项回应及必要复审。

**交付材料**

- 开题报告、研究方案与汇报材料。
- 阶段计划、预算、风险及适用审批记录。
- 开题结论、修改对应表和通过或待整改状态。

**验收标准**

- 研究问题、方法和评价相互对应，计划可在剩余培养时间内完成。
- 正式流程、意见处理与版本均可追溯。
- 需要审批的研究活动在实施前已取得相应许可。

未达要求：开题未通过时按意见修改并遵循重审规定；重大改题或方法变化需核对是否重新开题，不能用导师口头认可替代正式手续。

下一步：开题及必要整改、审批完成后，按确认方案实施研究。

配套模板：开题方案与评审准备（proposal.md）、实验、复现与运行证据（experiment.md）、送审准备与意见逐条回复（review-response.md）、课题、计划与资源变更（change-request.md）

### 05 研究实施、专业实践与持续记录

参考时机：开题后持续推进，按约定周期复盘

目标：积累足以支撑论文的可靠证据，同时完成适用的实践与过程要求。

**进入条件**

- 研究方案、授权与资源已落实。
- 实验、实践或分析任务有明确的版本和责任人。

**操作步骤**

- 按问题组织实验或实践，保存数据来源、处理步骤、参数、环境、随机设置和原始日志；失败运行也记录。
- 建立基线、对照、消融或案例验证，防止数据泄漏、评价口径变化和只选择有利结果。
- 周报列证据和阻塞，组会落实行动项；每学期复核课程与年度要求，专硕同步保存实践计划、过程和考核证据。
- 定期备份并试恢复；涉及新数据、新用途、合作变动或预算超支时，先核对授权与变更手续再继续。

**交付材料**

- 版本化代码/分析产物、数据说明、环境与原始记录。
- 实验结果、失败分析、周报和会议行动项。
- 适用的实践报告、年度材料及变更记录。

**验收标准**

- 结论能追溯到真实运行或实践记录，不能把预检、离线重算当作完整实验。
- 关键结果可重复检查，风险和负面证据未被隐藏。
- 课程、实践及年度事项与研究进度一并跟进。

未达要求：结果不稳定先排查数据、配置与统计口径；连续无法支持假设则缩小结论或调整研究方案，并记录导师反馈和必要审批。

下一步：按学校时间准备中期材料，不等全部研究完成才检查进度。

配套模板：专业实践计划与总结（professional-practice.md）、实验、复现与运行证据（experiment.md）、周报与下一阶段计划（weekly.md）、校本要求核对与年度培养记录（annual-check.md）、课题、计划与资源变更（change-request.md）

### 06 中期检查与年度考核

参考时机：按适用制度分别执行，不默认二者互相替代

目标：审视培养条件、研究进度和完成可能性，及时形成可落实的调整方案。

**进入条件**

- 已获得本年度中期及年度考核通知。
- 研究、课程、实践和成果状态有真实记录。

**操作步骤**

- 对照开题计划整理已完成、延期和变更项，提供核心结果、原型演示或实践产物。
- 核对课程学分、学术活动、专业实践、伦理与研究计划等适用事项，提前处理缺项。
- 评估剩余问题、论文结构、资源和毕业窗口，提交现实的后续安排，避免把未做工作全部排到最后。
- 参加正式检查，区分导师建议与考核结论；把每条整改意见转成任务、责任人、期限和复查证据。

**交付材料**

- 中期报告、汇报材料及证据索引。
- 适用的年度考核和实践材料。
- 正式结论、整改计划及更新后的时间表。

**验收标准**

- 进度由已有材料支撑，关键差距和风险已明确。
- 课程与实践等培养环节没有遗漏。
- 整改条件、复查时间和可能影响已得到正式确认。

未达要求：未通过或需整改时按学校规定补材料、调整方案或申请延期，完成复查后再声明通过；不隐瞒影响后续资格的问题。

下一步：中期整改落实后推进剩余研究，逐步形成完整学位论文。

配套模板：中期检查与差距整改（midterm.md）、校本要求核对与年度培养记录（annual-check.md）、专业实践计划与总结（professional-practice.md）、送审准备与意见逐条回复（review-response.md）、课题、计划与资源变更（change-request.md）

### 07 学位论文结构、初稿与反复修订

参考时机：写作贯穿研究，送审前完成实质性审阅

目标：以完整论证呈现本人研究，做到论文、数据、代码和结论一致。

**进入条件**

- 论文主问题与主要证据已明确。
- 已取得学位类型对应的论文规范、模板和保密要求。

**操作步骤**

- 建立章节与研究问题对应表，说明每章的目的、主张和证据；专硕按适用规范呈现专业实践与应用贡献。
- 先完成方法和结果等核心章节，再统一绪论、相关工作与结论；明确已发表合作成果和本人贡献的关系。
- 逐图逐表核对原始数据、单位、统计方法和运行版本，检查论证跳跃、反例与局限。
- 给导师提交可审阅的完整版本与问题清单，保留反馈和逐项修改说明；最终检查摘要、引用、附录及格式一致性。

**交付材料**

- 论文提纲、章节证据表和完整初稿。
- 图表来源、参考文献与贡献说明。
- 审阅意见、修改对应表和候选定稿。

**验收标准**

- 正文形成完整论证，未用计划或占位文字替代结果。
- 学生能解释所有核心内容，引用和复用清楚。
- 导师审阅、格式要求和后续送审时间有可落实安排。

未达要求：核心证据不足则补验证或收窄论点；结构性问题优先修订，不靠润色掩盖缺陷。时间不足按正式程序评估延期。

下一步：写作同时核验培养成果要求；两项均达适用条件后准备正式送审检查。

配套模板：学位论文写作与版本检查（thesis.md）、论文阅读与复现判断（reading.md）、送审准备与意见逐条回复（review-response.md）、AI 辅助使用与披露记录（ai-use.md）

### 08 培养成果与学位申请条件核验

参考时机：入学即了解，学位申请前逐项确认

目标：用正式依据和证明材料确认本人是否满足适用条件，避免临近申请才发现缺口。

**进入条件**

- 已明确本人年级、学位类型、学科或专业类别。
- 已取得相应成果和学位申请规定的有效版本。

**操作步骤**

- 逐条核对课程、实践、考核、成果及其他申请条件，记录文件来源、生效范围和咨询结果。
- 如有论文或其他成果要求，核对类型、作者及单位、时间口径和认定程序；不得自行把专硕或他人标准套用。
- 分别登记投稿、录用、在线发表、正式出版、专利申请/授权、软件登记、获奖或实践验收等实际状态。
- 收集正式证明并请指定部门核验，记录缺项、补救方案和预计完成时间；成果不足时按规定办理后续安排。

**交付材料**

- 适用条件核对表与政策来源。
- 成果台账、贡献说明及正式证据。
- 认定或资格核验结果、缺项处理计划。

**验收标准**

- 每项条件都有适用依据和状态，未核实处明确标注。
- 成果证据可查，状态没有夸大，合作署名与单位符合要求。
- 是否满足申请条件由学校规定的审核环节确认。

未达要求：证据不足则补正式材料或咨询认定部门；未满足条件时如实报告并按规定调整申请时间，不承诺录用、授权或特殊豁免。

下一步：确认适用条件与证明材料后，完成送审前的规范及资格检查。

配套模板：成果要求核对与成果台账（outcomes.md）、校本要求核对与年度培养记录（annual-check.md）、课题、计划与资源变更（change-request.md）

### 09 格式、查重、查非与 AI 使用说明

参考时机：按学校规定的送检和送审窗口执行

目标：完成相互独立的规范检查，确保报告对应实际拟提交论文版本。

**进入条件**

- 论文候选定稿、引用、贡献和成果证明已齐备。
- 已核实学校对各类检查的名称、对象、平台、阈值及复检规则。
- 已核对预答辩是否必需及办理顺序；如为送审前置，提交前必须完成预答辩和规定修改。

**操作步骤**

- 先核对学术诚信、引用、数据真实性、署名与保密，再检查格式、附件和论文信息。
- 按正式通知进行相似性检测，逐项核对重复来源和引用，不以改写、拆字等方式规避检查。
- 部分高校把错别字、格式、图表、编号、参考文献著录和排版等非学术性问题检查称为“查非”。逐项检查并记录位置、修正和复核；本校是否设置正式环节、具体范围与标准以适用文件为准。
- 按学校和成果渠道要求说明 AI 工具、用途、范围及人工核验；如有 AI 检测结果，应与使用说明、相似性报告分开保存。

**交付材料**

- 规范自查表、正式送检版本与文件校验记录。
- 相似性报告及适用的查非/其他核查材料。
- AI 使用说明、整改记录与复检结果。

**验收标准**

- 每份报告对应明确文件版本、检测时间与正式平台。
- 各类检查分别满足本校要求，不能以一项通过代替全部通过。
- 检测分数只是线索或流程依据，不能单独证明不存在学术不端，也不直接代替人工审查。

未达要求：未达要求时核实原因并按规定修改、复检或申请复核；检查后实质修改须核对是否重新送检，不能沿用不对应的报告。

下一步：资格及规定检查完成、送审版本确认后，按学校流程送审。

配套模板：学术规范、查非与查重（integrity.md）、AI 辅助使用与披露记录（ai-use.md）、成果要求核对与成果台账（outcomes.md）

### 10 匿名送审、评阅意见与异议处理

参考时机：学校指定送审窗口内

目标：提交符合匿名要求的正确版本，并按正式评阅结果完成回应和后续手续。

**进入条件**

- 送审资格和前置检查已获确认。
- 已取得匿名规则、提交清单、评阅及异议处理规定。

**操作步骤**

- 从同一论文基线生成完整保存版与匿名送审版，按规则处理姓名、单位、致谢、成果信息、文件属性和可识别链接。
- 检查匿名后的引用、附件和必要研究信息仍完整；未经规则允许，不擅自删改影响评阅的实质内容。
- 通过学校指定系统提交，核对文件预览、版本、信息和回执；保持评审独立，不私自寻找或联系评阅人。
- 收到意见后逐条回应、修订并保留证据；存在事实错误或异议时，在规定期限内通过正式渠道申请复核或申诉。

**交付材料**

- 同源的完整保存版与匿名送审版、匿名检查表。
- 正式送审回执、评阅意见与处理结论。
- 逐条回复、修改论文及适用的复审/异议材料。

**验收标准**

- 匿名要求与论文信息准确性同时满足，提交版本可追溯。
- 所有意见有明确处理，未采纳意见有依据和说明。
- 是否重审、复审或取得答辩资格以学校正式处理结果为准。

未达要求：评阅未达到答辩条件时按规定整改、复审或延期；异议未获结论前不自行认定通过，也不通过非正式接触影响评审。

下一步：正式评阅和修改要求满足、答辩资格确认后，进入答辩。

配套模板：学术规范、查非与查重（integrity.md）、送审准备与意见逐条回复（review-response.md）、学位论文写作与版本检查（thesis.md）

### 11 答辩申请与正式答辩

参考时机：满足正式答辩资格后，按学院通知办理

目标：在规范程序中说明研究贡献、证据和限制，并接受正式学术评价。

**进入条件**

- 已获得明确的评阅处理结果与答辩资格。
- 答辩申请、委员会安排、公开或保密要求由规定程序确认。

**操作步骤**

- 按学院清单完成答辩申请与材料提交，核对论文、评阅回复和资格材料版本；如校规将预答辩安排在评阅后，按通知先完成并落实修改。
- 制作问题—方法—证据—贡献的汇报，明确本人工作和局限，计时演练并准备可复查演示。
- 对照评阅意见准备回答，核对场地、设备、线上安排和保密要求；不自行对外发布受限论文或会议链接。
- 正式答辩如实回应并完整记录问题、修改意见和决议，确认后续期限和负责人员。

**交付材料**

- 答辩申请与资格材料、汇报及演练记录。
- 适用的预答辩意见和修改结果。
- 正式答辩记录、决议与后续修改清单。

**验收标准**

- 所有前置条件和答辩程序按学校要求完成。
- 汇报、论文、成果证明和实际研究一致。
- 答辩结论使用正式表述；答辩通过不等于学位已经授予。

未达要求：答辩未通过或需重大修改时，遵循学校对修改、再次申请及时间间隔的规定；不得自行承诺再次答辩结果。

下一步：按照答辩决议完成修改、审核和学位申请后续手续。

配套模板：答辩准备与修改验收（defense.md）、送审准备与意见逐条回复（review-response.md）、成果要求核对与成果台账（outcomes.md）

### 12 答辩后修改、定稿与学位手续

参考时机：答辩后至当批次材料截止日期

目标：把答辩意见落实到终稿，完成学校规定的审核和提交。

**进入条件**

- 正式答辩决议、修改意见及提交期限已获得。
- 已明确修改审核人和学位材料接收渠道。

**操作步骤**

- 逐条处理答辩意见并说明修改位置，未采纳处写出依据，按要求由导师或指定人员审核。
- 核对终稿的题名、作者、摘要、图表、附录和引用；实质修改是否需要补检或补审按规定确认。
- 完成学位申请、图书馆提交、纸质归档及必要签字，核对各渠道版本一致并保存回执。
- 查询毕业和学位的正式审核状态，分别记录答辩通过、材料接收、毕业审核和学位授予结果。

**交付材料**

- 论文终稿、逐条修改说明和审核确认。
- 学位申请及适用的归档提交材料、回执。
- 正式办理状态表和待补事项。

**验收标准**

- 修改要求全部有处理结论，终稿与审核文件一致。
- 签字、上传和接收记录齐全，待办有负责人和期限。
- 学位状态以学校正式决定为准，不根据答辩或系统草稿自行宣布。

未达要求：终稿或手续被退回时按具体意见补正并重新确认接收；错过窗口应及时联系负责部门按正式程序处理。

下一步：完成终稿与正式材料提交后，继续完成研究资产归档和离组交接。

配套模板：学位论文写作与版本检查（thesis.md）、送审准备与意见逐条回复（review-response.md）、数据、代码与毕业材料归档（archive.md）、成果要求核对与成果台账（outcomes.md）

### 13 研究资料归档、交接与离组

参考时机：贯穿研究，离组前集中验收

目标：让研究在人员离开后仍可核查、恢复和接续，并明确保管与访问责任。

**进入条件**

- 终稿、研究产物和官方材料已整理。
- 导师、项目负责人或指定接收人已明确归档范围与权限。

**操作步骤**

- 建立索引，覆盖论文版本、原始数据、处理脚本、代码、环境、配置、日志、图表来源、许可和正式记录，区分原件与派生文件。
- 冻结最终版本并生成校验记录，按已确认规则备份和试恢复；数据不能随包转移时登记存放位置、访问申请和保管责任。
- 由接收人抽查关键结果和运行说明，记录未完成实验、已知缺陷、合作事项、成果修订及后续负责人。
- 完成设备、经费、账号和权限交接；核对保存期限、保密与公开条件，个人作品集和离组后使用材料均遵循授权。

**交付材料**

- 归档目录、最终快照、校验与恢复记录。
- 数据/代码说明、结果索引和授权台账。
- 交接签收、遗留事项及权限处理记录。

**验收标准**

- 接收人可以找到并打开核心材料，关键证据能够复查。
- 密码不写入普通文档，敏感资料保存在授权位置，公开版本已脱敏。
- 责任、保存期限与离组后的联系和使用边界明确。

未达要求：缺失材料或复查失败时先补齐并重验；无法恢复的内容写明原因和影响，不用空目录或目录截图代替实际交接。

下一步：归档与交接获接收后结束本轮培养任务，后续成果修订按既定责任继续跟进。

配套模板：数据、代码与毕业材料归档（archive.md）、阶段移交与离组交接（handover.md）、成果要求核对与成果台账（outcomes.md）

## 日常管理与协作

日常管理的目的，是让任务有人推进、问题能够及时发现、指导意见落实到下一步。先与导师约定沟通周期、材料位置和反馈方式，再按实际课程与研究安排执行。本页给出工作方法；出勤、请假、实践、经费和考核，执行学校与学院已生效的规定。

[角色与沟通](https://csma-graduation-projects.github.io/management.html#roles-and-channels) [工作节奏](https://csma-graduation-projects.github.io/management.html#working-rhythm) [任务状态](https://csma-graduation-projects.github.io/management.html#task-status) [周报与组会](https://csma-graduation-projects.github.io/management.html#weekly-and-meeting) [请假与实践](https://csma-graduation-projects.github.io/management.html#leave-and-practice) [支持与纠正](https://csma-graduation-projects.github.io/management.html#support-and-correction)

### 先约定责任与沟通方式

学生负责理解要求、提出计划、完成工作、保留真实记录并主动报告困难；导师负责方向、方法、资源和质量上的指导，说明反馈安排，帮助判断范围与优先级。正式培养审核、成果认定、学位申请等由学校指定人员和组织办理。组内检查通过，只说明具备进入下一步的准备，不能代替正式审批。

入组时共同完成一份指导约定：本学期目标、固定交流时间、会前材料、常用渠道、预期反馈时间、紧急事项联系人和请假方式。周期可根据任务调整，不在网页上统一规定每日工作时长，也不把论文数量、在线时长或消息回复速度当作未经确认的考核标准。

不同沟通渠道承担什么工作

| 渠道 | 适合办理 | 留下的记录 |
| --- | --- | --- |
| 学校系统与正式邮件 | 培养审批、请假或外出申请、重要计划变更、需要明确答复的事项；学校要求系统办理时优先使用系统。 | 申请内容、时间范围、明确答复和系统回执。邮件不能替代必须办理的系统手续。 |
| 受控 GitHub 仓库或学校任务平台 | 任务拆分、代码与文档版本、实验记录、问题跟踪、阶段交付。 | 任务负责人、完成条件、提交版本和处理结果。先确认访问权限，再放入材料。 |
| 微信等即时沟通 | 临时协调、紧急提醒、会议变动和简短确认。 | 涉及正式决定时，再补到邮件、任务记录或指定系统，避免决定只留在聊天中。 |

### 让每天的工作连接到学期目标

每天开始前选出当前最重要的一项可交付任务，确认需要的输入与资源；结束前记录完成内容、文件版本、实验状态和下一步。一次失败的运行也有价值：写清预期、实际现象、已排查原因和下一次验证，不以重复尝试次数代替进展。

每周对照计划形成简短周报，附上能打开的证据；根据反馈更新任务状态。每月回看研究问题是否仍成立、工作是否偏离主线、资源预算是否足够，并对完成的里程碑做一次可运行或可核查的展示。每学期依据培养方案核对课程、学术活动、专业实践和正式考核，提前登记下一阶段的官方截止时间。

这些频率是建议起点。课程密集、实习、集中实验或答辩准备期间，可以与导师重新约定；调整后要有明确的下一次检查日期。不要同时承诺多个互相争抢时间的任务，先确定关键任务，再安排辅助阅读和工具学习。

### 用完成条件管理任务

一条任务应写清「要解决什么、交付什么、怎样验收、谁负责、何时检查」。例如，将“继续做实验”改为“运行已确认的数据划分与基线，提交命令、配置、完整日志和结果差异说明”。交付时间是计划；完成状态要由材料和检查结果支持。

建议使用的任务状态与转换条件

| 状态 | 进入条件与下一步 |
| --- | --- |
| 待开始 | 目标与输入已明确，确定优先级和检查日期后开始。 |
| 进行中 | 记录当前版本与最近一次结果；工作过大时拆成可验收的小项。 |
| 受阻 | 说明阻塞原因、已尝试方法、所需帮助、影响和备选方案；及时发出求助。 |
| 待检查 | 交付材料齐全并完成自查，注明希望对方检查的问题。 |
| 已完成 / 待修改 | 记录检查结论；待修改项补充问题位置、责任人和复查日期。正式考核另记官方状态。 |

题目、数据、方法或截止时间发生重要变化时，保留原计划，说明原因、已完成工作如何使用、影响和新计划，再由对应负责人确认。无法按期完成时，尽早报告并缩小范围，不能等截止后补造进度。

### 周报和组会要形成下一步

周报围绕五件事：本周原计划、实际完成及证据、得到的认识、尚未解决的问题、下周可交付任务。把事实与解释分开，例如“本次三次运行中两次失败”是事实，“可能由资源不足引起”是待验证解释。阅读进展说明理解了什么、与当前问题有什么关系；实现进展说明哪些功能已经验证、哪些仍未完成。

会前按约定时间发送材料，并列出需要讨论的具体问题。会上优先讨论结论依据、关键困难和方案取舍；会后整理决策、行动项、负责人、检查日期与需要补充的证据。未达成一致的事项写成待确认，不将猜测记录为导师决定。下一次交流先回看行动项，再讨论新问题。

向导师提交稿件时说明版本、本次主要改动、期望反馈范围和计划提交日期，预留合理审阅时间。反馈超出约定时间，可简短提醒并指出受影响的节点；涉及正式截止日期时同步联系学院负责人员，寻求可执行安排。

### 区分请假、实习与专业实践

请假是特定时间内调整学习或出勤安排；实习是校内外的岗位或项目经历；专业实践是培养方案规定的教学环节。参加实习不自动等于完成专业实践，获得单位证明也不自动替代学校考核。出发前核对申请对象、审批顺序、保险或安全要求、保密与成果归属，以及是否影响课程和研究节点。

申请写明起止日期、安排、任务影响、衔接办法和必要的联系渠道，通过指定受控渠道提交。敏感健康信息只提供给有权限的人员。实践开始前确定学习目标、指导人员、任务与考核材料；过程中保留真实记录，结束后提交总结与所需评价，完成学校认定后才记为相应培养环节完成。

### 先估算资源，再安排实验

申请服务器、模型接口、数据或会议经费前，说明用途、预计时长或调用量、费用上限、数据许可和完成后释放资源的方式。先做小规模验证，再扩大运行；实验记录资源占用与费用，发现预算偏离时及时停止扩张并沟通。共享设备按约定预约，长任务留下用途与结束条件，避免占用后无人知道如何处理。

经费使用和报销按单位流程办理，保留合规凭证。合作项目开始前确认数据可用范围、署名与知识产权；不能因为是实习或竞赛，就默认可以带出单位数据、代码或未公开成果。

### 反馈、健康与记录纠正

持续受阻、负担过重或身心状态影响学习时，尽早与导师、辅导员或学校支持部门沟通，商定任务调整与复查时间。对指导安排、考核或权益有疑问，可通过学院和学校公布的渠道咨询、反馈或申诉；具体程序以适用制度为准。评价应针对工作和证据，保护个人隐私。

AI 可以辅助汇总会议和周报，使用前确认材料允许进入所选工具。汇总后由本人核对事实、姓名、日期和决定，删除错误推断；涉及他人的决定应请相关人员确认。AI 生成的出勤或进度结论不能直接作为考核依据。发现记录错误时保留更正说明、时间和确认人，让后续使用者知道哪个版本有效。

## 学术规范与提交检查

学术规范要落实在选题、阅读、实现、实验和写作的每一步。提交前集中检查很必要，但不能替代平时的真实记录。本页将引用与查重、规范检查（查非）、AI 工具披露分开说明，帮助你逐项自查并形成可复核的修改记录。

[真实证据](https://csma-graduation-projects.github.io/integrity.html#integrity-evidence) [引用与查重](https://csma-graduation-projects.github.io/integrity.html#citation-check) [查非](https://csma-graduation-projects.github.io/integrity.html#format-check) [AI 使用](https://csma-graduation-projects.github.io/integrity.html#ai-disclosure) [匿名送审](https://csma-graduation-projects.github.io/integrity.html#anonymous-review) [整改与复核](https://csma-graduation-projects.github.io/integrity.html#integrity-remediation)

### 先确认材料真实、来源可查

论文中的每个关键结论，应能回到所依据的文献、数据、运行记录或分析过程。区分原作者报告的结果、自己实际复现的结果和仍待验证的推测；借用公开结果作比较时明确来源与条件。演示成功、一次运行完成和充分支持研究结论，是不同层次的证据。

实验记录至少包含代码版本、环境、数据版本与划分、配置、执行命令、时间、退出状态、日志和原始输出。保留失败、超时与异常结果，按事先说明的规则纳入或排除；不能为提高指标临时挑选有利样本而不报告。图表从保存的数据生成，记录处理脚本，核对单位、样本量、误差和图注是否准确。

使用第三方代码、模型、图片和数据时，核对来源、许可证、使用限制和引用要求；“可下载”不等于“可任意公开”。涉及人的调查、访谈、实验或个人信息数据，在招募或采集前判断是否需要伦理审查、知情同意与授权，按学校流程办理。不得在研究完成后用一份自查表冒充事前批准。

### 引用与查重：逐条理解，逐项处理

写作时就建立引用记录：结论来自哪里、原文位置、如何支持当前论述。直接引用标明引用关系；转述用自己的理解组织，并准确给出来源。参考文献要实际查阅和核实，避免引用不存在的题名、作者、年份或 DOI。不能把别人的观点、图表或代码只改几个词后当作自己的成果。

1. **确认规则与版本。**从当年正式通知确认检测平台、检测对象、提交内容、判定口径、修改与重检流程；没有确认的阈值不自行填写。
2. **完成内容与引用自查。**核对正文引文与文后条目是否对应，图表是否说明来源，合作工作和本人已有成果是否说明贡献与复用关系。
3. **使用指定渠道。**提交导师审阅后的完整稿，记录文件名、版本、日期及校验值。不要把未公开论文上传到来源不明的检测网站。
4. **逐项阅读报告。**定位相似片段，判断引用是否准确、表达是否不当、公共定义是否需要说明；修正问题本身，保留修改理由和位置。
5. **按规定复核。**需要重检或审核时走正式流程，保存报告与回执。相似性检测通过，不代表研究质量、署名或数据使用已经合格。

**不要以规避检测代替修改。**不得通过内容图像化、加入无关文字、故意替换字符或伪造引用来降低检测结果。本页不提供统一重复率，也不将检测数值直接等同于学术不端结论。

### 查非：检查非学术性错误

部分高校将错别字、格式、图表、编号、参考文献著录和排版等非学术性错误检查称为“查非”。它与查重是不同环节。本校是否设立正式查非、检查顺序、抽查办法和判定标准，须在[校本要求表](https://csma-graduation-projects.github.io/policies.html#local-check) 中确认；下面的自查方法适用于写作质量检查。

规范检查应对照最终导出的论文逐项完成

| 检查对象 | 具体操作 |
| --- | --- |
| 基本信息与结构 | 核对题目中英文、学位类型、摘要、关键词、目录、章节、声明和附录；采用学校当前模板。 |
| 文字与术语 | 检查错别字、残留占位符、重复段落、术语前后不一致和缩写首次解释。 |
| 图表与公式 | 检查清晰度、图题表题、单位、符号解释、编号、正文引用和跨页显示；核对图表数值与原始结果。 |
| 引用与编号 | 检查参考文献著录字段、引用顺序、页码、交叉引用和自动编号，清除“引用源未找到”等错误。 |
| 页面与导出 | 核对页眉页脚、页码、分页、空白页、字体、可搜索文字与书签；从头到尾查看导出 PDF。 |

检查记录写明页码或段落、问题类型、修改内容、复核结果与日期。修改后重新导出，检查受影响的目录、编号和分页，避免只修源文件而提交旧 PDF。正式提交前再次打开实际待上传文件，不能仅凭文件名判断版本。

### AI 工具使用：可说明、可核验、本人负责

先核对学校、课程、竞赛和投稿单位的适用规定。记录工具名称与版本、使用日期、用途、涉及的章节或代码范围，以及本人如何核验。语言润色、代码建议、资料整理与内容生成应如实区分；需要披露时使用规定位置和格式。任何辅助工具都不能替代本人完成应由本人完成的研究与论证。

逐条核验 AI 提供的文献、事实、公式、代码与数据解释；代码应阅读、测试并确认许可，不能因为能够运行就视为正确。生成示例不得伪装成真实实验记录或真实用户反馈。未公开论文、个人信息、评阅意见及受限数据，只有在工具与数据使用范围均获许可时才能输入。

如学校安排 AIGC 检测，登记政策版本、结果解释与复核渠道，按要求处理。本页不设置“AI 率”阈值，不提供规避检测方法，也不以单个检测分数自动判断违规。发生疑问时，保留写作版本、笔记、实验和修改过程供有权限的人员复核。

### 匿名送审：正文之外也要检查

先读取具体匿名要求，再从确认的论文版本生成送审稿。通常需要核对封面、致谢、作者与导师信息、在学成果、自引表述、项目说明、页眉页脚、附录、图片内文字、附件和文件名。匿名规则不等于删除必要的科学引用，按学校规定处理身份关联信息并保持学术准确。

检查 PDF 或文档属性中的作者、单位、批注、修订痕迹和隐藏内容；同时核对补充材料、演示视频、代码仓库链接、README、提交记录和访问页面是否暴露身份。若评阅要求提供代码，采用获准的匿名方式；不能为了匿名擅自破坏已有仓库历史或删除原始材料。无法兼顾复核需要和匿名要求时，请学院确认提供方式。

保留完整稿、送审稿及其对应关系，记录文件校验值和系统提交回执。冻结后如发现重要问题，先联系指定人员，依规则退回或更正；不能私自替换文件后仍声称是已审核的同一版本。

### 发现问题后，形成可复核的整改

先定位问题涉及的版本与范围，再区分排版错误、证据不足、引用失当或可能的规范问题。暂停有问题材料的进一步提交，保留原始记录，与导师和相应负责人员沟通。逐条写明原意见、处理方式、修改位置、证据和仍未解决的部分；没有采纳的意见说明理由，不能只回复“已修改”。

组内复核、正式查重查非、评阅和答辩分别记录结果。涉嫌学术不端的认定与处理，依学校制度和正式程序进行；对学术评价有异议，查询学校公布的复核渠道。个人意见、检测报告和评阅材料留在受控范围，不在公开主页展示。

### 先做一份能找到材料的目录

沿用已有项目约定，不为统一外观强制搬动或重命名正在使用的仓库。若材料分布在多个获准系统中，用归档索引说明每部分的存放位置、访问条件、负责人和版本。公开索引不包含受控地址、账号或个人评价；需要权限的索引放在对应受控空间。

新项目可以参考下面的结构，按实际工作合并或删去不适用项。学校要求的正式文件仍保存在指定系统；目录清楚比目录数量多更重要。

```text
project/
├── README.md              # 内容、范围、入口与运行说明
├── requirements/          # 需求、问题边界、计划与变更
├── literature/            # 检索记录、文献索引与阅读笔记
├── proposal/              # 方案及适用的开题材料
├── code/                  # 源码、依赖与运行脚本
├── data/
│   ├── raw/               # 原始数据或获准的获取说明
│   └── derived/           # 清洗与加工后的数据
├── experiments/           # 配置、运行日志与环境记录
├── results/               # 结果表、分析与制图脚本
├── thesis/                # 稿件、图表来源与提交版本
├── reviews/               # 受控的意见与修改记录
└── archive/               # 交付清单、校验与验收记录
```

阶段提交使用明确的日期和版本，避免“最终版2”“最后一次修改”等名称。论文的送审、答辩、修改后终稿分别保留，并标记正式提交状态；代码使用对应提交或发布版本。文件名一致不代表内容一致，重要交付同时保留校验值。

### 原始材料、工作材料与公开成果分开

材料的可见性与使用边界

| 材料层次 | 典型内容 | 处理方法 |
| --- | --- | --- |
| 受控原始材料 | 原始采集数据、授权记录、参与者信息、原始实验输出。 | 保留来源和原貌，限定访问；分析使用副本或派生数据，不覆盖原始记录。 |
| 受控工作材料 | 个人计划、周报、未公开论文、评阅意见、研究过程与内部交接记录。 | 按职责授权访问；明确当前有效版本和负责人，不放入公共网站。 |
| 经确认的公开成果 | 获准公开的论文、代码、示例数据、演示、空白模板和说明。 | 单独生成发布包，检查许可、隐私、署名和保密限制，确认后发布。 |

清洗或匿名化后的数据也要检查重新识别风险、授权条件和许可证，不能因为删掉姓名就默认可以公开。无法共享的数据可提供数据字典、申请流程、处理脚本及合成示例，明确示例只用于演示，不代表真实实验结果。

**页面不可见不等于资料私有。**公开 GitHub 仓库中的文件，即使不链接、被折叠或不进入网页构建，仍可能从仓库和历史访问。填写后的个人材料应保存在获准的受控空间。

### 每份关键材料至少说明这些信息

在交付清单中为材料分配稳定编号，记录名称、用途、格式、版本或日期、负责人、来源、对应任务或论文位置、存放位置、访问级别、许可条件和校验值。对不适用的字段说明原因，不使用空白掩盖未确认状态。

数据另记采集或下载时间、数据版本、字段含义、单位、样本量、清洗和排除规则、划分方法及生成脚本。运行记录另记代码版本、依赖、配置、数据版本、命令、资源、起止时间、退出状态和输出位置。图表注明输入数据与生成脚本，形成“论文结论—图表—结果—运行—代码与数据”的对应关系。

受许可限制不能随包交付的材料，登记限制、获准获取方式和负责联系的岗位，不交付个人账号凭据。资料来自合作单位时，确认研究组保留、后续使用和公开的范围；共同完成的代码和论文记录贡献与署名约定。

### README 要让接收者真正运行起来

1. **说明范围。**列出交付内容、论文或项目版本、已经验证的结果与已知限制，说明哪些功能需要外部账号或受限数据。
2. **说明环境。**给出操作系统、语言和关键依赖版本、硬件要求、安装命令及环境文件。模型或服务依赖注明版本和访问条件。
3. **说明数据。**给出合法获取方式、放置位置、预处理命令和数据校验，不要求接收者猜目录结构。
4. **给出最小运行。**提供一条可验证的起步命令、预期输出、预计时间和资源需求，再给完整实验入口。
5. **说明结果。**指出输出文件、指标计算与制图方法，列出可接受差异和随机性来源；不能重复的结果写明原因与复核方式。

交付前从干净目录按 README 操作。确实不能完整重跑时，保留运行日志、原始输出、分析脚本及限制说明，将“完整重跑”“保存记录复算”“只核查文件”分别标记，不把结构检查写成复现成功。

校验值用于发现文件是否改变。以下示例在归档目录内执行，实际文件列表应与交付清单一致：

```text
# macOS：生成与复核 SHA-256 清单
shasum -a 256 README.md thesis/final.pdf > SHA256SUMS
shasum -a 256 -c SHA256SUMS

# Linux 可使用同类命令
sha256sum README.md thesis/final.pdf > SHA256SUMS
sha256sum -c SHA256SUMS
```

文件修改后重新生成清单；校验通过仅表明与清单对应，不证明内容正确或来源真实。备份完成后抽取关键文件做恢复检查，确认能打开、能读取、权限有效；不要把同步成功当作已经完成恢复验证。

### 交接完成，以接收者验收为准

归档与交接的最少验收项目

| 验收项 | 应留下的凭证 |
| --- | --- |
| 正式材料 | 学校要求的终稿、声明、修改记录等已按规定提交，保留对应回执或状态。 |
| 完整与一致 | 交付清单逐项核对；论文版本、代码版本、数据与结果的对应关系清楚，关键文件校验一致。 |
| 可运行与可复查 | 接收者按说明运行样例或约定流程，记录命令、环境、结果和未完成项，注明验证范围。 |
| 权限与许可 | 接收者已取得所需访问权限，公开与保留范围明确，受限材料未误入公开包。 |
| 剩余事项 | 风险、后续维护责任、费用、到期事项和支持安排已记录，并有接收确认。 |

某项未通过时，登记问题、负责人、修复日期和复查方式；不能以“已压缩上传”直接关闭交接。校方归档与研究组交接的完成情况分别记录，最终由相应接收人员确认。

### 明确保留期限与离组后的访问

保留期限依据学校制度、资助项目、数据许可、伦理要求和合作协议确定，记录依据与到期处理责任人，不自行给所有材料统一设年限。到期不自动删除：先核对是否仍有保留义务、复查需求或其他限制，再按批准流程处理并留下记录。

离组交接通过组织所有权转移、成员权限调整、服务账号管理和密钥轮换完成，不交个人密码。检查代码仓库、存储、服务器、模型服务、域名或其他资源的负责人、账单和恢复方式；确认新负责人能访问后，依约撤销不再需要的权限。保留协作需要时，约定访问范围和期限。

### 每学年与每个毕业批次，先核对适用要求

填写核对表的第一步，是明确学校与学院、专业、入学年级、学位类型、学习形式、计划毕业批次和培养方案版本。每条规则记录名称、发布单位、原文链接或正式系统位置、发布日期、生效日期、适用范围、具体要求、核验日期与核验人。无法确认时标为“待核验”，不能自行用相近专业或上一届标准填补。

校本要求确认表应覆盖的事项

| 事项 | 需要确认的问题 | 完成凭证 |
| --- | --- | --- |
| 课程与学分 | 必修、选修、成绩、补修、学术活动与其他培养环节的要求是什么？ | 适用培养方案与正式系统记录。 |
| 实践与安全 | 专业实践的时长、单位、指导、审批、考核及伦理或安全要求是什么？ | 获准计划、记录、评价与认定。 |
| 选题、开题与中期 | 资格、时间、材料、组织方式、变更和未通过处理如何办理？ | 正式表格、意见与完成状态。 |
| 成果要求 | 是否有适用成果要求？成果类型、作者贡献、署名、时间和录用/发表/授权状态如何认定？ | 有效规则与正式认定结果。 |
| 论文与预答辩 | 采用哪版写作规范？是否要求预答辩或其他前置审查？ | 模板版本、审核意见与确认。 |
| 查重、查非与 AI 使用 | 是否设相应环节？渠道、顺序、口径、披露、修改、复核要求是什么？ | 适用通知、提交版本与报告。 |
| 送审与答辩 | 匿名要求、截止时间、评阅周期、资格、修改与异议程序是什么？ | 送审回执、评阅意见和答辩记录。 |
| 学位申请与终稿 | 答辩后如何修改、复核、申请学位和提交终稿？ | 修改确认、申请与归档回执。 |

### 如何把制度转成可执行计划

从学校最终截止时间向前安排导师审阅、修改、检测、评阅和材料确认，预留返工时间。本站建议周期只是工作安排，不替代学校规定的最短间隔、固定批次或期限。学硕与专硕、不同年级、不同学习形式可能采用不同规则，不可只看文件标题相似就沿用。

新通知出现时，核对是否替代旧文件、是否仅适用于某一批次，并更新受影响的任务。来源之间有冲突时交由发布部门确认；保留旧版本与替代关系。以下高校案例用于理解真实流程，不代表本门户所属学校，也不向本站学生移植他校阈值。
