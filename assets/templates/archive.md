# 研究数据、代码与毕业材料归档清单

用途：用于阶段冻结、投稿、送审、答辩后或离组前，将研究结论与可核验材料一起保存。归档既要保证可定位和可复查，也要遵守数据授权、匿名审稿、隐私与知识产权要求。

填写说明：先列实际材料，再区分公开包和受限保存内容。使用项目内相对路径，账号密钥不得进入包内。不能公开的数据保留授权说明、版本标识和获取条件，不用空文件假装提供完整数据。

## 一、归档身份与权限

| 必填项 | 填写内容 |
| --- | --- |
| 项目、负责人、归档日期与版本 | ［本次冻结的范围和用途］ |
| 对应论文或成果 | ［匿名送审版／答辩版／终稿分别标识］ |
| 保存位置与接管人 | ［相对位置、受控存储标识、维护责任］ |
| 公开范围与授权 | ［公开／组内／限定人员；数据、代码、图片和模型许可］ |
| 保留期限与处置依据 | ［按学校、合同或伦理要求填写；不得自行承诺永久保存］ |

## 三、校验与恢复核对

- 文件完整性：生成相对路径文件清单和 SHA-256 校验清单，记录［工具或命令、日期、文件数量、总大小］。
- 校验范围：明确［校验清单自身及临时文件等排除项］；复制或解压后重新校验并保存结果。
- 可用性：在干净目录按 README 检查入口，记录［实际执行步骤、环境、结果］。只检查文件存在时写“结构检查”，不能写“完整复现”。
- 数据边界：原始数据和处理数据分别标识；需授权的数据验证访问规则，不擅自复制公开。
- 备份恢复：记录［备份版本、负责人、恢复演练抽检材料、校验结果］。

## 四、自检与验收

- [ ] 主张、图表、数据、代码与运行记录能够关联。
- [ ] 匿名版与实名终稿区分，包内没有凭据或未授权资料。
- [ ] 校验清单真实生成并复核，缺项和未执行步骤明确。
- [ ] 接管人能找到入口、理解权限及恢复方法。

验收记录：［交付人、接管人、日期、实际抽检范围、失败项与整改期限］。归档状态：［待补齐／已校验／已接收；据实选择］。
