# 学习与成长：五条培养路径的能力衔接

日期：2026-10-19。状态：本地实现与验证完成；用户已确认先发布当前版本，后续增量完善。本文及 JSON 中的测试数据记录发布前的实际验证范围。

## 需求与适用范围

用户要求各部分内容具体、明确，使不同层级学生能够按照培养体系形成连贯的学习和成长过程。本轮在已有培养步骤之上补齐能力目标、学习实践、可观察证据、反馈纠正与迁移，不把自主学习等同于独自完成所有工作。

当前范围为中英各 5 条培养路径、45 个阶段、25 份可填写模板、11 张培养与科研流程图和 7 类工具场景，已核对构建产物共 58 个 HTML 页面。五条路径分别为本科科研训练 7 阶段、毕业设计 8 阶段、竞赛 6 阶段、硕士 13 阶段、博士 11 阶段。国际学生继续使用对应层级路径，并单独核对培养方案、语言、资源和支持安排。

导航栏目保持“导引 / Mentoring”，页面标题为“学习与研究导引 / Mentoring for Study and Research”。学习成长指南承担跨路径执行方法，导引栏目承载学习、研究与指导交流文章，两者互相补充。

## 详细设计

### 1. 从证据找到学习起点

新增 `learning.html` 与 `en/learning.html`，源文件为 `scripts/training-pages/learning.html` 及其 `en/` 配对文件。两种语言共享六个章节锚点：`start`、`levels`、`cycle`、`feedback`、`review`、`next`，便于切换语言后保留位置。

起点诊断以四类小任务取得证据：能否解释对象与理由、完成最小实践、公平比较并解释差异、把困惑转成可回答的问题。每项记录“独立完成 / 借助提示完成 / 尚未完成 / 本轮不适用”，同时附材料与理由；状态用于选择练习，不为学生贴固定能力标签。

### 2. 明确层级责任和求助时机

| 层级 | 主要能力目标 | 学生承担的工作 | 可观察证据 |
| --- | --- | --- | --- |
| 本科科研入门 | 理解具体问题，完成有指导的小任务 | 阅读、最小实践、记录帮助与困难 | 自己的解释、可重复步骤、条件变化后的调整与局限 |
| 本科毕业设计 | 将明确目标形成完整项目 | 组织需求、设计、实现、测试、论文和演示 | 目标至结论的对应关系、典型与失败场景、反馈后的复查 |
| 硕士 | 界定问题并执行有依据的方法和验证 | 比较替代方法，维护主张与证据，处理矛盾结果 | 问题依据、方法理由、公平比较、可追溯结果与局限 |
| 博士 | 组织关联研究并论证原创贡献 | 识别问题、挑战自身解释、管理依赖与变更 | 贡献定位、反例与替代解释、继续或停止的证据、迁移判断 |

每层同时给出应求助的具体情形和准备材料。使用“测试失败调查”的同一任务设计示例解释层级差异，明确示例没有实际实验结果，不以规模、代码行数或材料数量认定能力。

### 3. 网页内直接显示六步学习循环

采用原生 HTML 有序列表与现有 `international-flow` 样式，页面直接显示，无须下载或安装软件：

1. 诊断当前起点，记录证据、帮助和缺口。
2. 选择培养阶段与能力目标，写清交付、检查和支持。
3. 阅读原始资料并实践，记录选择、错误与尝试。
4. 自检证据，区分观察、解释和未验证判断。
5. 获得反馈并纠正，以实际复查关闭问题。
6. 在变化情境中迁移所学，据证据进入下一步或继续补练。

本轮学习结论可为达到目标、部分达到需补练、调整目标后再检查。正式开题、中期、资格考核、送审或答辩结论仍由有权部门确认。

### 4. 处理困难并跟踪反馈

概念困难通过原始定义、正反例和具体不理解位置求助；实现困难保留最小失败案例、版本、输入和尝试；证据不足时列出主张、候选解释与能区分它们的检查。三类路径都要求取得反馈后实际复核，保留未解决问题。复盘检查成果质量、能力成长和个人贡献，允许合理求助与协作。

### 5. 模板和培养路径连接

新增模板 ID `learning-review`，两种语言的实际 Markdown 文件位于 `assets/templates/learning-review.md` 和 `assets/templates/en/learning-review.md`。模板包含本轮能力、起点证据、学习任务与原始资料、独立解释或执行、成果质量与能力成长、反馈与求助、迁移与下一阶段，以及提交前自查。

模板使用可填写表格，提供明确标注为待执行计划的短示例；执行前不得填入成功结果。复盘周期沿用现有周报、组会或任务检查安排，由任务和支持需要决定。模板进入搜索、预览、复制、单文件下载和整包下载，并纳入两种语言的离线手册。

培养路径继续使用统一数据与生成器。博士从原说明页扩展为 11 个完整阶段，纳入阶段总览、个人清单、工具映射、流程图与手册；保留原页面地址及历史锚点。五条路径均应能到达学习成长指南与复盘模板，并在具体阶段说明输入、行动、交付、检查、未完成处理与下一步。

### 6. 内容修补清单

本轮同步审查现有路径中的具体衔接缺口，按以下七项整合数据与生成页面。各项均需在中英文对应阶段核对，不能只修改说明文档或图中的标签。

| 修补项 | 明确后的行为 | 核对位置 |
| --- | --- | --- |
| 1. 提前核对硕士成果要求 | 入学时确认适用成果类型、署名、时间与认定口径，纳入计划；末期完成最终复核，避免临近申请才首次发现条件 | 硕士入学与成果核对阶段 |
| 2. 综述反馈到选题 | 若问题已有充分解决，或必要数据实际不可得，带文献与资源证据返回选题并调整问题或范围 | 硕士选题、综述及对应流程 |
| 3. 中期后的证据缺口返回研究 | 核心主张缺少支持时返回研究与验证；提纲、方法部分等可并行推进，结论以实际证据为准 | 硕士研究、中期、论文与对应流程 |
| 4. 本科设计需要学生实际讲清 | 由学生演示一条“需求 → 接口或变量 → 验证预期”的对应关系，以自己的解释和具体案例检查设计理解 | 本科毕业设计的设计阶段 |
| 5. 竞赛报名单独倒排 | 按报名窗口安排资格、材料与提交，不等待原型完成才处理报名；原型与开发进度另行组织 | 竞赛选赛、报名与团队计划 |
| 6. 六处增加已有模板直链 | `bachelor.topic → annual-check`；`master.orientation → outcomes`；`master.research → meeting`；`competition.build → engineering-report`；`research.validation → experiment`；`doctor.annual-review → learning-review` | 各阶段模板入口与中英 manifest |
| 7. 本科已有能力通过证据诊断 | 用现场解释或实际重跑判断已有能力；缺项补练，依据表现调整学习内容，不按年级直接跳过基础 | 本科科研训练起点与基础阶段 |

上述表格记录本轮修补要求与整合目标；是否已经正确进入页面、清单、流程与手册，以本轮验证结果为准。

## 证据边界

- 指南、空白模板和示例说明怎样工作；不构成学生已经掌握能力或完成正式环节的证据。
- 页面结构、字段检查与链接验证只能证明实现满足对应检查项；学生实际学习效果仍需真实任务、反馈与后续观察。
- 获得指导与能力成长可以并存；记录帮助来源和本人核对过程，独立能力通过变化任务中的表现判断。
- 学校门槛、时间、语言、成果要求和正式通过条件以适用文件及有权部门的结论为准；本轮不新增统一数量或时限。
- 国际学生使用相同的质量要求与证据方法，同时按个人情况安排语言、资源和学习支持。
- 填写后的个人材料保存在获准的受控空间，公共仓库只保留指南、空白模板和已授权内容。
- 本地构建和演示不能代替 GitHub Pages 部署或线上验证；验收报告中的 Git 状态为发布前快照，实际发布结果另核对提交及 Pages Actions。
