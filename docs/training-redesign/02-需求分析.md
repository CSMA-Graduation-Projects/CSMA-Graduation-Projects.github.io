# 培养门户需求分析

日期：2026-10-18。范围：当前培养门户的本地改版；演示确认后另行提交和推送。

## 现状与问题

现有站点包含本科科研、毕设、硕士、博士及资源栏目，具备基本导航与公开边界。主要不足是阶段名称偏抽象、学校流程与研究训练混排、竞赛路径缺失、模板只是说明、未给出整改闭环。用户需要能实际执行的培养说明，而非更多栏目介绍。

## 使用者与任务

| 使用者 | 需要解决的问题 | 本次交付 |
| --- | --- | --- |
| 本科科研学生 | 从哪里开始、如何完成第一个研究任务 | 入门至复盘的阶段指南、小任务与实验模板 |
| 毕设学生 | 每阶段做什么、交什么、怎样进入下一关 | 选题至终稿归档的阶段门与检查表 |
| 竞赛学生 | 是否能参赛、怎样组队和提交 | 资格、规则、方案、开发、提交、复盘全流程 |
| 硕士生 | 研究推进和学位流程怎样衔接 | 13 阶段说明、成果认定、查非、送审与答辩闭环 |
| 指导与审核人员 | 如何据材料给反馈、怎样处理延期 | 统一进入条件、验收依据、整改动作及责任说明 |
| 维护者 | 怎样更新规定而不把建议误写成制度 | 官方来源、校本核对表、内容数据和自动验证 |

## 功能要求

1. 首页在两次点击以内到达培养阶段或模板；本科科研、毕设、竞赛、硕士分别成路。
2. 每一阶段必须明确目标、参考时机、进入条件、具体行动、交付物、验收标准、未通过处理、下一阶段及对应模板。
3. 硕士覆盖入学与课程/专业实践、选题、综述、开题、研究、中期、写作、成果、查重/查非、送审、答辩、终稿与授位手续、归档。
4. 共用指南包括日常管理、学术规范、数据与资料归档、官方依据与年度核对。
5. 模板提供实际 Markdown 文件、逐份预览和下载、全套 ZIP；支持按名称、用途和类别查找。
6. 阶段工具支持按路径和阶段生成自检清单、浏览器本地保存与导出。勾选仅是本人自检，不表示导师审核或学校批准。
7. 旧页面路径、既有导航、新闻/成果/榜样内容继续可用；主要旧锚点保留。

## 内容边界

正式期限、课程学分、成果资格、检测阈值、评阅结论处理及申诉程序依适用学校/学院/年级的有效文件。本站没有可核验的学校身份，不指定统一阈值。组内建议明确标注，不将任何未生效拟定文件作为现行制度。学硕和专硕依据各自培养方案；实践、竞赛、论文不能自动互相替代。学术成果的计划、投稿、录用、发表分别记录。答辩通过不能直接写成已授予学位。

公共站点只提供通用指南和空白模板，不收集学生姓名、成绩、考勤、未公开论文、评审意见或凭据。填写后的文件放入获准的受控工作空间，不提交到公共模板库。

## 验收条件

| 编号 | 验收内容 | 方法 |
| --- | --- | --- |
| A1 | 修改前完整备份且可恢复 | 文件哈希、权限、源不变、git fsck |
| A2 | 4 条路径与完整阶段字段 | 数据结构及人工内容检查 |
| A3 | 24 份真实模板、链接与 ZIP 完整 | 文件存在、内容检查、ZIP 条目校验 |
| A4 | 首页、路径、阶段工具、模板在手机与桌面可操作 | 实际浏览器检查与截图 |
| A5 | 自检持久化、切换不串阶段、导出有效 | 浏览器交互测试 |
| A6 | Jekyll 构建成功，站内链接与旧锚点有效 | 构建和全站静态验证 |
| A7 | 规则来源与适用边界清楚 | 官方来源核对、内容审阅 |
| A8 | 无个人过程材料和本地审计资料进入发布产物 | 构建扫描、配置及差异审查 |
| A9 | 用户演示前不提交、不推送 | Git 状态、HEAD 与远端动作记录 |

## 不在本次范围

账号系统、学校审批接口、学生档案数据库、邮件发送、考勤采集、自动学位资格认定。这些功能需要明确学校制度与受控部署，不通过公共静态站点模拟。
