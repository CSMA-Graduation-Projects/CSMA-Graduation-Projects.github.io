# 流程图与科研工具指南

设计始于 2026-10-18，验收更新于 2026-10-19。范围：在既有培养门户上增加可阅读、可下载、可编辑的流程图，以及与培养任务相对应的工具使用指南。本次扩展已在本地完成，等待演示确认，尚未提交或推送；此前 `befdced` 基础版本已推送上线，其部署结果不代表本次扩展已经发布。

## 需要解决的问题

学生既需要知道培养阶段的先后关系，也需要知道材料没有达到要求时回到哪里、修改什么、何时重新核查。只有一条向前的时间线会掩盖研究迭代和正式审批的差别。流程图必须与现有 34 个阶段说明相互连接，不能成为另一套相互矛盾的流程。

工具建议应从任务和产物出发。例如，综述需要可追溯的检索记录与文献矩阵，实验需要环境、配置和原始结果，写作需要引用、修订记录和可核对的最终文件。选了软件、安装了插件或者生成了一张截图，都不能替代这些产物。工具组合采用已核实可用于当前工作方式的软件，同时提供可选替代；本机盘点、安装路径、账号、许可证和私有资料不进入公共站点。

## 信息与实现设计

- `assets/data/workflows.json` 保存流程节点、连线、分支条件和关联页面。四条培养图沿用既有阶段 ID；共用流程关联对应指南。
- `scripts/workflow_diagrams.py` 根据同一数据生成网页流程、SVG 与 draw.io 文件。网页提供文字顺序和返工提示；SVG 不使用依赖浏览器 HTML 的 `foreignObject`；draw.io 保留节点和连线供继续编辑。
- `assets/data/research-tools.json` 保存工具、任务场景、官方来源以及 34 个阶段的场景映射。公共内容只包含适合教学的操作建议，不包含本机软件资产盘点。
- `scripts/research_tools.py` 生成场景指南和阶段入口；每个建议与实际产物和检查方法放在一起，避免把软件列表当作训练方案。
- `workflows.html` 是全部流程图的入口，`tools.html` 是工具场景的入口。既有培养页面、资源页、共用指南和离线手册同步关联。
- 原模板 ZIP 保持 24 份模板及完整手册的用途；另提供包含 10 份 SVG、10 份 draw.io 文件、使用说明及哈希清单的流程图 ZIP。

统一更新流程如下；图文件、手册和 ZIP 应从源数据一起重新生成，避免只有页面更新而下载内容仍为旧版。

```sh

jekyll build --safe --trace
```

## 必须保留的适用边界

正式阶段顺序、审批主体、成果条件、查重与其他检查的定义、阈值和期限，应核对本人适用的学校和学院文件。图中的“通过”只表示相应核查满足条件，不自动代表学位资格或学位授予。预答辩及其他校内环节按校本要求安排，通用图不能固定所有学校的办理顺序。

软件安装可用不等于账号、网络、付费功能、云端额度或团队许可已经具备。涉及未公开论文、受限数据、评审意见和个人信息时，应使用获准的存储与处理环境。工具指南中的 AI 建议需要人工核查、引用与使用记录；输出文本本身不能作为文献真实性或实验有效性的证明。

## 验收与演示

自动验收脚本为 `node scripts/validate-workflow-tools.mjs`；Jekyll 构建后再运行 `node scripts/validate-workflow-tools.mjs --build` 检查实际发布产物。脚本以学生能否完成任务为线索，检查以下内容：

1. 四条路径中的 34 个阶段没有遗漏、重复或错误链接；每个阶段都能进入对应工具场景。
2. 每个流程的开始可以到达结束；所有节点可达；决策有通过与未通过路线，整改能返回当前或前面的核查位置。
3. SVG 和 draw.io 均可由标准 XML 解析器读取；图内节点与连线存在，下载链接指向真实文件；不含远程执行脚本。
4. 工具场景提供操作、产物与复核依据，所有工具和官方来源引用可解析，不把安装情况或私人路径写入公开数据。
5. 首页、资源页、培养页、共用指南和两个新页面之间的入口可达；所有新增站内链接与锚点存在。
6. 流程图包内容和哈希与源文件一致；模板包中的手册同步；离线手册包含流程的文字说明和全部工具场景。

浏览器验证使用实际 Jekyll 构建，由本机服务器提供页面：

```sh
python3 -m http.server 8766 --bind 127.0.0.1 --directory _site
```

在另一个终端运行：

```sh
CSMA_QA_BASE_URL=http://127.0.0.1:8766 node scripts/browser-qa.mjs
CSMA_QA_BASE_URL=http://127.0.0.1:8766 node scripts/training-browser-qa.mjs
```

演示按以下顺序进行：

1. 从[本地首页](http://127.0.0.1:8766/)进入[流程图总览](http://127.0.0.1:8766/workflows.html)，查看四条培养路径与六类共同工作。
2. 打开[硕士流程图](http://127.0.0.1:8766/workflows.html#flow-master-path)，查看开题判断、未满足时的整改支路，并通过返回链接回到相应步骤。
3. 沿图进入硕士送审说明，检查阶段材料、失败处理和正式资格边界，再使用阶段工具入口进入[论文写作工具场景](http://127.0.0.1:8766/tools.html#writing)。
4. 查看[实验工具场景](http://127.0.0.1:8766/tools.html#empirical)，核对工具、操作、运行记录、原始结果与复跑验收如何衔接。
5. 下载 SVG、draw.io 源文件和流程整包；在本机 draw.io 打开 `master-path.drawio`，选择判断节点观察可编辑节点与连接，不覆盖生成源文件。
6. 用手机宽度查看流程和工具卡片，再检查离线手册与两种下载包。网页无脚本时仍能阅读流程、工具说明并使用下载入口。

桌面分支效果见[实际浏览器截图](screenshots/workflows-branch-desktop.png)。检查重点为文字大小、箭头去向、判断与整改的区分、键盘焦点和 320 像素宽页面的横向溢出。

XML 可解析、结构一致不等于已经在 draw.io 应用中完成导入；若未实际导入，应如实标注。静态语义检查也不替代人工内容审阅、浏览器视觉核验或学校的正式审核。
