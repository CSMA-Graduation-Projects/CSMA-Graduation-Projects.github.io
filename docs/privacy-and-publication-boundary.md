# 隐私与公开发布边界

## 1. 适用范围

本规则适用于 CSMA GitHub Pages 站点、其公开源仓库、静态构建产物、页面资源、下载文件和未来可能新增的结构化数据。

GitHub Pages 是公开静态托管。前端登录、隐藏元素、未链接文件、混淆文件名或客户端权限判断都不能把公开仓库中的数据变成私有。

## 2. 可以公开的内容

- 培养项目介绍、通用流程、阶段目标与公共检查表；
- 经核验的公开课题方向、申请条件和官方渠道；
- 公共模板、写作/研究方法、开发工具和学术诚信指南；
- 经授权的学生成果、公开论文书目信息、专利状态、竞赛结果、软件和演示链接；
- 经过审查、无法反向识别个人的总体统计；
- 公开新闻、FAQ、研究组介绍和官方联系方式。

## 3. 不得公开保存或展示

- 学号、证件号、手机号、私人邮箱、家庭地址；
- 成绩、排名、处分、心理/健康、学业困难、谈话记录、个性化导师评价；
- 推荐信、未公开评阅/答辩意见和个人考核材料；
- 未公开论文全文、原始实验数据、项目申请书、待申请专利内容、内部会议纪要；
- 私有仓库地址、内部服务器入口、受限数据位置；
- 用户名、密码、token、API key、私钥、恢复码及任何账号凭据。

## 4. 默认存储位置

| 内容 | 默认位置 |
|---|---|
| 成绩、考核、学位与正式评审 | 学校/学院受控系统 |
| 周报、计划、导师反馈、个人困难 | 受控私有系统 |
| 代码、实验、论文草稿、项目材料 | 私有仓库或受控云盘 |
| 账号凭据 | 密码/秘密管理服务 |
| 授权记录与内部状态 | 受控数据库或私有档案 |
| 公开指南与经授权摘要 | GitHub Pages 公共门户 |

## 5. 成果发布流程

1. 事实核验：确认标题、状态、参与者与链接。
2. 权利核验：确认版权、数据许可、合作条款和知识产权。
3. 隐私核验：只保留实现公开目的所必需的信息。
4. 授权核验：学生明确同意具体展示方式。
5. 技术核验：链接无 token，文件元数据无个人信息，构建不含内部目录。
6. 定期复核：处理链接失效、状态变化、撤回与更正。

## 6. 推荐授权字段

在不破坏既有接口的前提下，可为未来数据增加：

```text
public
consentToPublish
displayName
visibility
sourceUrl
verifiedAt
```

默认不可公开。只有 `public=true`、授权明确且其他核验通过时才渲染；缺字段不等于允许公开。

## 7. Secret 响应

发现疑似 secret 时：

1. 不在终端、报告、issue 或聊天中复制值。
2. 停止页面和构建产物继续引用。
3. 记录文件路径、类型和风险等级。
4. 通知负责人立即轮换相关凭据。
5. 检查远端、构建产物、缓存和 Git 历史暴露范围。
6. 不自动操作远程账户，不自行重写 Git 历史。
7. 由负责人批准专门的移除与历史清理方案。

仅删除当前文件不能使已泄露 secret 恢复安全，轮换是必要动作。

## 8. 个人信息与授权问题

发现授权未知的姓名、照片或成果时，不复制到新数据源，不包装成公开案例；停止页面继续展示并登记路径与类型。原始数据的迁移、匿名化、归档或删除必须由负责人和相关主体确认。

仅从页面隐藏仍不能消除公开源仓库或历史中的暴露，应明确告知负责人残余风险。

## 9. 发布前扫描

扫描常见 key/token/private-key、邮箱、手机号、证件号、学号及敏感语义。工具输出应限制为文件路径或计数，不回显秘密。还需人工检查：

- 图片/PDF/DOCX 元数据、批注和修订；
- URL 查询参数、私有仓库与服务器地址；
- 学生姓名与成果是否有授权；
- 小样本统计能否反向识别个人；
- 未发表研究、合作数据与知识产权。

## 10. 更正与撤回

负责人应提供官方联系渠道，接收个人信息更正、成果授权撤回和安全报告。当前仓库尚无正式邮箱或学校页面，站点只链接已核验的 GitHub 组织页；该缺口需要人工补充。
