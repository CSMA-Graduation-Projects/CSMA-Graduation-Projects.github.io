# CSMA 主页隐私与公开边界审计

审计日期：2026-09-04  
范围：当前工作树、4 个 Git 提交、现有线上 Pages 页面；未复制或回显任何秘密值。

## 1. 结论

当前未发现格式化 API key、token、私钥、密码赋值、手机号、正文邮箱、学号、身份证号、家庭地址、成绩、排名、处分、健康信息、导师评价、推荐信、前端登录或第三方跟踪脚本。

主要风险来自内容治理而非应用攻击面：公开页面存在授权未知的身份关联型命名示例，同时多个页面会诱导维护者把账号、联系人、过程记录、未公开论文和实验数据放入学生仓库。公开 GitHub Pages 不能作为敏感培养档案后台。

## 3. 扫描方式与阴性结果

扫描只输出命中文件路径，不输出命中原文。检查范围包括当前工作树与全部 4 个提交：

- 常见 secret/key/token/private-key 模式；
- 手机号、证件号、邮箱、学号等格式；
- 成绩、排名、处分、健康、私人评价、推荐信等语义关键词；
- 私有仓库 URL、SSH URL、URL 内嵌凭据；
- localStorage/sessionStorage/cookie/fetch/XHR、表单和前端假登录；
- 图片常见定位/作者元数据迹象。

阴性结果不代表未来文件可以不经审查直接公开。

## 4. 立即实施的公开边界

### 可以公开

- 培养路径、阶段目标、通用任务和质量清单；
- 公共模板说明、公开政策链接、软件工具指南；
- 已核验的公开课题摘要；
- 经明确授权的成果摘要和真实公开链接；
- 匿名化、非小样本可识别的总体统计。

### 默认私有

- 申请材料、能力评估、周报、个人计划、困难记录；
- 导师反馈、成绩、排名、查重结果、评阅/答辩意见；
- 完整开题/中期/论文材料，除非已明确批准公开；
- 未公开论文、实验数据、合作材料、项目申请和待申请专利内容；
- 私有仓库地址、服务器入口、私人联系方式；
- 用户名、密码、token、API key、私钥、恢复码及任何凭据。

## 5. 身份示例处理说明

本次不删除、不改名、不匿名化原始值，也不把它们复制到新数据文件或报告。实现采用 Jekyll 前置区与 Liquid 构建注释：原值仍保留在原 HTML 源文件中，但已由真实 Jekyll 构建从 `_site` 页面彻底剔除；公开页面改用不含姓名/学号的格式说明。自动验证同时检查生成页面不得含身份关联标签、旧姓名式命名格式、源内保留块或未处理的 Liquid 标记。

限制：源仓库与 Git 历史若公开，原始值仍可能被访问。构建剔除不能消除既有源与历史暴露。后续必须由负责人核验公开授权，并人工决定迁移、仓库可见性或历史处置；本次不执行 Git 历史清理。

## 6. 发布授权建议

未来学生/成果数据建议新增可选字段：

```text
public
consentToPublish
displayName
visibility
sourceUrl
verifiedAt
```

默认规则是 `public=false` 或 `visibility=private`。只有事实、知识产权、授权和链接均核验后，页面才渲染该条目。不得用前端登录、CSS 隐藏或未链接 JSON 保护敏感数据。

## 7. 建议迁移位置

- 学院正式系统：成绩、考核、答辩、学位流程。
- 受控私有仓库：代码、实验、论文草稿和过程记录。
- 学校受控云盘：需要权限管理的大文件和签字材料。
- 密码管理器/秘密管理服务：账号凭据和 token，不得写入普通文档。
- 受控数据库：授权状态、内部项目状态、导师反馈与审计记录。

## 8. 人工后续

1. 核验身份关联型命名示例是否得到当事人明确公开授权。
2. 确认仓库当前及未来是否保持公开；必要时制定历史暴露处置方案。
3. 指定实际私有存储系统及访问审批责任人。
4. 提供正式的成果发布授权与撤回流程。
5. 核验背景图来源和使用许可。
6. 提供隐私/安全问题的官方联系渠道。
